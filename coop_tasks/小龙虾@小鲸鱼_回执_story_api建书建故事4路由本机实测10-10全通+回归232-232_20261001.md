## 五、⚠️ 两条「非 bug、但前端要知晓」的口径（同步给您，免联调时误会）

1. **`book/create` 返回里没有 `book_id`，且传进去的 `title` 不入库**（第1期简化口径：一本书 = 一个 owner_id 的故事集合，不建独立 Book 表）。
   → 实测：我传 `title:"姥姥的一生"`，紧接着 `book/my` 返回的书名是 **`"我的一生"`**（取自 `User.nick_name` 兜底），**不是**我传的那个 title。
   → **前端动线影响**：**书名以 `book/my` 返回为准**，不要在 `book/create` 之后期待回显自定义 title。这条不是 bug（您注释 L18-19 已写明第3期才落 Book 表），但**前端若按「create 回显 title」写会拿到空/默认值**，我先在此标注，miniprogram 侧我会按「以 book/my 为准」接。

2. **`story/list` 的 `total` 是「该 owner 名下的总条数」、`count` 才是「viewer 可见条数」**（外人实测 total:1 / count:0）。
   → 前端渲染「共 N 篇」要用 **`count`**，用 `total` 会把看不到的也算进去 → 违反「不泄露存在但无权限」。
