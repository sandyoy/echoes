## 三、接口契约（前端照这个接）

### 3.1 上传地址 `POST /api/echoes/storage/upload-url`

请求：
```json
{ "actor_id": "<用户id>", "kind": "audio", "file_name": "a.mp3",
  "file_size": 12345, "mime": "audio/mpeg" }
```

返回（**新增 form_field，务必用上**）：
```json
{ "ok": true, "data": {
    "upload_url": "https://<域名>/api/echoes/storage/upload_form?key=clips/...",
    "method": "POST",
    "form_field": "file",          // ★ 新增：wx.uploadFile 的 name 用它
    "key": "clips/u_x/audio/xxx.mp3",
    "backend": "local"
}}
```

前端写法：
```js
wx.uploadFile({
  url: d.upload_url,
  filePath: tempFilePath,
  name: d.form_field || 'file',   // ★ 不要写死 'file'，从后端拿
  success: ...
})
```
> ⚠️ 注意：`method` 是 `POST` 不是 `PUT`。微信小程序 `wx.uploadFile` 只认 POST multipart，
> 10-24 已经改成 POST 表单端点，别再按 PUT 写。

### 3.2 确认入库 `POST /api/echoes/storage/confirm`（★ 核心）

请求：
```json
{ "actor_id": "<用户id>", "owner_id": "<故事主人id>", "key": "<上传返回的 key>",
  "kind": "audio", "story_id": "<故事id>", "file_name": "a.mp3",
  "file_size": 12345, "mime": "audio/mpeg", "visibility": "private",
  "duration": 3.2 }
```

返回（**这四个字段是前端直接能用的，不需要再调别的接口**）：
```json
{ "ok": true, "data": {
    "clip_id": "clip_xxx",
    "speak_text": "我十几岁就下地干活了…",     // 文字，可能为空
    "transcript": "我十几岁就下地干活了…",     // ★ 同 speak_text，直接用这个
    "transcribe_state": "done",                // done | failed | skipped
    "media_url": "https://<域名>/media/clips/....mp3",  // ★ 可直接播放
    "playable": true,                          // ★ true 才画音频条
    "duration": 3.2
}}
```

### 3.3 前端要做的三件事

**① 录音时要有反馈（sandy 说「无秒数、字不跳动，不知道录上没」）**
- 按住说话就开始计时，屏幕上显示秒数递增
- 松手立刻显示「正在听写…」的转圈/点点点，别让老人干等
- 转写通常 1–2 秒，超过 5 秒提示「还在听，稍等」

**② 拿到 `transcript` 就把文字上屏**
- `transcribe_state === 'done'` → 文字正常显示
- `transcribe_state === 'failed'` → **灰/黄小字提示「这句没听清，可以再说一遍」**，
  **不弹红叉、不提示重录、不算失败**（这是铁律，`transcribe_failed` 不是错误）
- 文字为空但 state=done → 也按 failed 的样式温和提示，别报错

**③ 拿到 `media_url` + `playable=true` 就把音频条画出来**
- 用 `wx.createInnerAudioContext()`，`src = media_url`
- 音频条 + 播放/暂停按钮 + 时长
- **一定要能回放**（sandy 原话「不能回放」是硬伤）

### 3.4 采访下一问 `POST /api/echoes/interview/next`

请求：
```json
{ "owner_id": "<老人id>", "viewer_id": "<当前用户id>",
  "last_answer": "<老人刚说的那句原文>",
  "interrupted_question": "<如果被打断，刚才问的是啥>" }
```

返回：
```json
{ "ok": true, "data": {
    "state": "following_answer",   // ★ 新增值：表示"已读懂老人的话并接话"
    "question": { "text": "那个生产队里，您一天能挣几个工分？", "id": "..." }
}}
```

**前端要注意**：`state` 现在有这几种取值，都要当"正常往下问"处理，不要因为不认识新值就卡住：
- `asking` —— 正常出下一问
- `following_answer` —— ★新增，读懂上一句后接话（也是正常往下问）
- `resumed` —— 老人刚才打断，先把原问题接回来
- 其他未知值 → 一律按 `asking` 处理，别抛错
