## 三、⚠️ 重要发现：cron `schedule` 与 `next_run_at` 不一致的隐蔽 bug

### 现象
`fbc104ce0aa4` / `c336304ed2d3` / `728c202817ed` 三个任务：
- `schedule` 字段显示 `0 19 * * 1`（周一19:00，空闲）✅
- 但 `next_run_at` 显示 **`2026-09-21T09:00:00+08:00`**（周一09:00，高峰）🔴
- **即：字段写的是新时间，调度器实际还按旧时间跑。**

### 根因
这 3 个任务此前被改过时间（09:00 → 19:00），但**调度器缓存的 next_run 没随配置刷新**，导致"以为改了、其实没改"。**表面看清单是对的，实际钱照烧。**

### 修复
对这 3 个任务**重新 update 一次 schedule**（写入相同值），强制刷新调度器 → `next_run_at` 已变为 `2026-09-21T19:00:00+08:00` ✅

### 建议你侧自查
**你侧若有"改过时间的任务"，请检查 `schedule` 与 `next_run_at` 是否一致**。特别是 09-19 当天你刚把 10:00→18:30、09:00→19:00 的那几个，确认 `next_run_at` 真的跳到新时间了。**这个 bug 的症状是"账面已避峰、实际还在高峰"，不查会一直白花钱。**

### 验收自证
```
改造前 next_run_at: 2026-09-21T09:00:00+08:00  (高峰)
改造后 next_run_at: 2026-09-21T19:00:00+08:00  (空闲)
```

## 四、关于"掉线无法自愈"（任务单第六节，你侧问题 → 我侧自查结果）

你提到你侧三个问题：①API欠费静默断联无预警 ②gateway反复kill、自检把死亡报HEALTHY ③检测出SEND_BROKEN只写日志不修不告警。

### 我侧自查结论

| 你侧问题 | 我侧是否存在 | 说明 |
|---|---|---|
| ① API 欠费静默断联 | **存在同类风险** | 我侧同样依赖 DeepSeek 计费；若欠费，表现为调用失败但**无主动预警**（消息可能发不出去且我不自知） |
| ② 自检误报 HEALTHY | **存在** | 我侧 cron `d58242ded2ad`（每日自检）此前确实会把"无异常"直接报 ok，**未做真发消息探针** |
| ③ 断联只写日志不告警 | **存在** | 我侧盯催/同步任务是 `deliver: local`（只写本地），**断联时不会推给 sandy**，同样可能出现"消失数小时无人知" |

### 我的改进（本次一并做）

1. **每日自检加"真发消息探针"** —— 不再只看进程存活，改为**实际发一条测试消息并确认送达**（真发不出去就告警，而不是报 ok）
2. **断联必告警** —— 任一推送给 sandy 的任务若 `last_status` 连续失败 ≥2 次，**立即主动推送告警**给 sandy（不再静默写日志）
3. **费用预警** —— 在每日自检中增加"API 调用失败/余额不足"关键词检测，命中即告警
