## 一、sandy 报的原话问题

> 因为一点那个写字框，跳出来的那个键盘就特别大，然后就发现那个会遮挡那个写字框的地方。写字框还拉上拉不下去，不上去。所以写的过程中是看不到写字框里面写了什么内容的。得把那个键盘去掉之后才能看到，然后再去改的时候，一点它又看不到了。所以当他写错的时候，要更改的时候有点难。

拆成四个具体毛病：

| # | 毛病 | 后果 |
|---|---|---|
| 1 | 键盘弹出盖住写字框 | 写着看不见自己写了什么 |
| 2 | textarea 有 `resize:vertical` 手柄，手机上手势拨不动 | 想拉高看不到，想缩小拉不下来 |
| 3 | 要改一个字得先收键盘、改完再点、键盘又弹出来盖住 | 改错极难，孩子会放弃 |
| 4 | 底部固定栏 + 问老师按钮 + 聊天抽屉都不躲键盘 | 互相压叠 |

## 二、改了什么（只动了前端一个文件）

**文件**：`xiaoqiao/web/index.html`（44,099 字节，基于线上 11-18 版改，原 33,062 字节）

### 改动 1：键盘高度三路探测（核心）

新写 `kbHeight()`，同时用三条路读键盘高度，缺一条就有手机型号算不出来：

```
① 有 visualViewport：document.clientHeight - visualViewport.height
② 老内核没 visualViewport：document.clientHeight - innerHeight
③ 兜底：页面首次加载时的满屏高 - min(innerHeight, visualViewport.height)
```

⚠️ **踩过的坑（务必别改回去）**：绝对不要减 `pageYOffset`。页面滚动过之后这一项会把键盘高度算成 0，看起来"没键盘"，整个避让功能静默失效。

### 改动 2：键盘弹出时页面让出空间

```css
body{--kb:0px}                                  /* JS 实时写入键盘高度 */
body.kb-up{padding-bottom:calc(var(--kb) + 96px)}
body.kb-up .footer-bar{transform:translateY(calc(-1 * var(--kb)))}
body.kb-up .fab{bottom:calc(96px + var(--kb))}
body.kb-up .sheet{height:calc(72vh - var(--kb));transition:none}
```

### 改动 3：正在写的那道题自动顶到可见处

`focusin` 后按 120/340/620ms 三次重定位（等键盘真弹出来，不然量到的是旧位置），把输入框滚到橙头下面居中位置。键盘高度不变且框已在可见区时不再滚动，避免抖动。

### 改动 4：textarea 自动长高 + 去掉拉伸手柄

- `resize:none; overflow:hidden`
- `autoGrow()`：按内容长高，76px 起、260px 封顶（实测 5 行内容 76→134px）
- 孩子不用再跟那个拨不动的手柄较劲

### 改动 5：键盘顶上「快跳条」（新增，直接解决"改错难"）

键盘弹着时底部出现一条：

```
[↑ 上一题]  第 15 / 23 题  [下一题 ↓]  [✓ 收起键盘]
```

- 弹着键盘就能换题，不必先收键盘再找下一个框
- 单行输入框按 `Enter` = 下一题
- 「收起键盘」一键 blur，想通篇看时用
- 只在键盘弹出时显示，没键盘不占地方

### 改动 6：整道题高亮

正在写的那道题，题号和输入框一起亮橙色边框 + 浅色底，孩子一眼知道自己在写哪题。
