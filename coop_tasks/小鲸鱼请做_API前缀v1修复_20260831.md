## 🔴 问题性质：前端 API_BASE 前缀错（全量网络功能挂）

非 bug 修复分歧，是**确定的路径错误**。用户 sandys 真机扫码测 v4 码，反馈：
1. 录音说话**不能转成文字**
2. **不能保存**

## 根因（已 curl 实测铁证，非猜测）

前端代码所有接口都写在 **`/api`** 前缀下，但后端 FastAPI 真实暴露的是 **`/v1`** 前缀。

| 功能 | 前端实际调（404） | 后端真实路由（200） |
|------|------|------|
| 🎤 录音转文字 ASR | `https://yuanaikang.cn/api/ai/asr` ❌ | `https://yuanaikang.cn/v1/ai/asr` ✅ |
| 💬 AI访谈 | `.../api/ai/interview` ❌ | `.../v1/ai/interview` ✅ |
| 🔊 语音合成 TTS | `.../api/ai/tts` ❌ | `.../v1/ai/tts` ✅ |
| 👤 微信登录 | `.../api/auth/wechat` ❌ | `.../v1/auth/wechat` ✅ |
| 💾 保存故事 | `.../api/stories`⚠️(重定向200) | `.../v1/stories` ✅ |

**实测命令佐证：**
```
curl -s https://yuanaikang.cn/api/ai/asr        -> 404 (text/html)
curl -s https://yuanaikang.cn/v1/ai/asr         -> 200
curl -s https://yuanaikang.cn/api/ai/interview  -> 404
curl -s https://yuanaikang.cn/v1/ai/interview   -> 200
curl -sL https://yuanaikang.cn/api/stories      -> 200 (重定向，非直接通)
curl -s https://yuanaikang.cn/v1/stories        -> 200
```
`/v1/docs`、`/v1/openapi.json` 均 200（FastAPI 自动文档），证明 `/v1` 是真实 API 前缀。

## 🔧 改法（关键，一处改全端通）

把 API 前缀从 `/api` 统一改成 `/v1`。**前端所有文件里 `API_BASE` 的 `.../api` → `.../v1`。**

具体文件：
- `miniprogram/app.js` 第2行：`const API_BASE = 'https://yuanaikang.cn/api'` → `'.../v1'`
  - 同时第29/59/77行的 `${API_BASE}/auth/wechat`、`/stories`、`/ai/interview` 会随之正确
- `miniprogram/pages/interview/interview.js` 第5行：
  `const API_BASE = app.globalData.apiBase || 'https://yuanaikang.cn/api'`
  → 兜底改成 `'https://yuanaikang.cn/v1'`
  - 第138行 `${API_BASE}/ai/tts`、第311行 `${API_BASE}/ai/asr` 随之正确

⚠️ 若 `app.globalData.apiBase` 也是从 `app.js` 拿到的旧 `/api` 值，一并改。**全项目 grep 一下 `api` 前缀确认没有遗漏**：
```bash
grep -rn "yuanaikang.cn/api" miniprogram/
grep -rn "globalData.apiBase" miniprogram/
```
目标：grep `yuanaikang.cn/api` 应 0 命中，全部是 `.../v1`。
