# 卡点上报口径 v1.0

> 发起：小鲸鱼（云端）｜2026-10-02｜适用：双 Agent（小鲸鱼 + 小龙虾）所有定时任务与日常会话
> 目的：**卡点只能"变化时"报一次，不许复读。** sandy 已明确不想再看到同一批卡点被反复念。

---

## 一、什么叫"卡点"

卡点 = **事情真的推不动了，且我自己无法解决、必须外部（sandy / 对方 Agent / 第三方）才能解开的阻塞**。

满足以下**全部**三条，才算卡点：
1. 这件事**在我职责范围内**本该我推进；
2. 我已用尽**自有渠道**（自己拉仓库、自己查资料、自己改代码/配置）仍然推不动；
3. 需要一个**外部角色**动作才能解开（等对方交件、等 sandy 决策、等外部账号/资质）。

⚠️ **不算卡点的常见误判**（这些一律不报）：
- "我在等另一个 Agent 干活" —— 那是**协作常态**，不是卡点，除非已**超期**。
- "我不确定要不要做" —— 那是**待定项**，按"出稿当轮一次性摆出"，不挂成卡点反复念。
- "运维自检发现某文件没更新" —— 那是**我自己的活**，做掉即可，不甩给 sandy。
- "上次说过的问题还在" —— **状态没变就不要再报**（见第三条）。

---

## 二、上报的**唯一时机**：状态跃迁

**同一卡点，只在下面 4 种"状态跃迁"发生时上报一次：**

| 编号 | 跃迁类型 | 举例 |
|---|---|---|
| ① | **解除销账** | "预览码已出，此前卡点消除。" |
| ② | **责任方改变** | "该事已从等小龙虾转为等医院回复。" |
| ③ | **新卡点出现** | 首次出现、此前从未报过的新阻塞。 |
| ④ | **超过最后期限** | 到了约定 deadline 仍未完成，升级上报。 |
| ⑤ | **挂满 7 天兜底** | 同一卡点首次上报后挂满 **7 天**仍未解除 → 强制再提醒一次（此后每满 7 天可再提醒一次）。 |

**除此之外，一律不报、不写、不念。**

---

## 三、禁止复读（核心条款）

- 上一轮报了「A 未完成、B 未完成、C 未完成」，本轮 A/B/C **仍原样未动** → **本轮不得再列 A/B/C**。
- 判断"变没变"的办法：读账本对应行，看卡点的**责任方 / 状态 / 期限**三项是否至少一项发生改变。三项全不变 = 没变 = 不报。
- **无跃迁时的正确输出**：静默标记（如 `NUDGE_OK` / `[SILENT]`），或"本轮无变化"一句带过。**不逐条复述卡点。**

---

## 四、上报格式（一句话讲清"什么变了"）

有跃迁要报时，一句话四要素：**卡点 + 变化类型 + 当前责任方 + 需要谁做什么**。

- 正例：「预览码卡点**已解除**（小龙虾 10-02 已交 v7 包）。」
- 正例：「D02 动作图**责任方变更**：由等我方返工 → 转等医生审核。」
- 反例（禁止）：「当前卡点：①A 未完成 ②B 未完成 ③C 未完成。」（复读，无变化信息量）

## 五、谁适用

- **小鲸鱼**：其 cron（盯催 83581e5fa264 / 认知同步 77039e713ee6）prompt 已加入"铁律0-E·卡点去重"，与本口径一致。
- **小龙虾**：本文件即为其尺子。它的例行自检若发现"同一卡点连续多轮未变"，**不报**；只在跃迁时报一句。

---

## 六、附：本口径解决的真实问题

- 现象：同一批卡点被连续多轮原样上报，sandy 反复收到相同内容。
- 根因：定时任务被要求"每轮扫描卡点"，但**没有"没变化就不报"的约束** → 每轮如实复读。
- 治本：给任务加"状态跃迁才报"的硬约束（已在 prompt 落地）+ 本口径供对端 Agent 遵守。
