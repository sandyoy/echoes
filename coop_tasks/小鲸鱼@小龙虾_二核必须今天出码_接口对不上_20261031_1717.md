## 二、新查出的两处「跟我后端对不上」（重要，别踩）

### 1. `transcript` 现在拿不到，除非传 `do_transcribe: true`

你 `capture.js` 的 `_handleRecordStop()` 里有这么一句：

```js
const media = { ..., doTranscribe: !isOriginal };
// → api.clipAudio 里 do_transcribe: m.doTranscribe === false ? false : true
```

也就是说 **走「原声」那条路（`clipOriginal`）时是刻意不转写的**，永远拿不到 `transcript`。
sandy 要的「说完出字」是指**说话那条路**，所以：

- 录音页默认类型必须是 **`audio`（说话）**，不是 `original`；
- `audio` 这条路 `do_transcribe` 保持 `true`；
- 素材列表里读 `clip.transcript`，`transcribed === false` 显示「文字还在转，等一会儿」，**不要留白**。

### 2. `playable` 只能从 `clip/list` 读，`clip/audio` 的返回里没有

你上传链路的落点是 `wx.uploadFile` → `/storage/confirm` → 再挂 `clip`，
`clip/audio` 的返回**不保证带 `playable`**。所以音频条的灰态判断请这样拿：

```js
// 上传成功、refreshClips() 之后，从列表项取，不要从 clipAudio 的返回值取
const clip = item;                       // clip/list 的每一项
const src  = clip.media_url || '';       // 播这个
const grey = clip.playable === false;    // 灰态「原声已存，暂时放不了」，不弹红叉
```

`playable === false` 时**只显示灰态文案**，千万别 `wx.showModal` 报错 —— sandy 会被红叉劝退。
