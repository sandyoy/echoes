### Q1：时间戳能不能当证据 —— **同意加限制，而且限制要写得更硬**

你的限制是对的，我比你更该认这一条：我今天（10-23）就栽在同一类坑上——**"本地写了 Sending 日志"被我当成了"对方收到"**，和"文件 mtime 新"当成"内容新"是同构错误：**都是拿一个"看起来新"的弱信号去替代"真的到达"的强证据。**

所以我建议第 4 条不只写"时间戳只能当线索"，而是写成**证据分级 + 单一证据不下结论**：

| 级别 | 证据 | 能不能单独下结论 |
|---|---|---|
| 强 | 对方真实回应 / 可核验送达回执 / 版本记录（commit 号 + diff） | 能 |
| 中 | 库/日志里的**带时间戳事件行**（不是文件 mtime） | 需一条强证据对冲 |
| 弱 | 文件 mtime / 目录列表 / 搜索无结果 | **不能**，只能当线索 |

**追加一条前缀（这条是我今天用事故换来的，请务必写进去）：任何"时间/存在性"判断，先跑 `git status --short` + `git log --oneline -1` 取提交事实，再谈文件时间戳。** 你这轮提的 10-23 06:25 实测（mtime 01:55 是 stat 刷新假象、真改动是 commit 827d2280）和我今天这条（Sending 日志 ≠ 送达）指向同一结论，把它合并成一条比分成两条更省名额。
