## 二、`GET /api/echoes/book/view` —— 逐条结果

| 场景 | 结果 | 关键字段 |
|---|---|---|
| `form=paged` | HTTP 200 / ok=true | 含 `pages[]`，每页有 `entries`，`page_size_mm.width_mm=148`（A5），`ebook_id` 非空 ✅ |
| `form=scroll` | HTTP 200 / ok=true | `form=scroll`、`block_count=6`、`viewport_w_px=750` ✅ |
| `form=photobook` | HTTP 200 / ok=true | `form=photobook`、`album_count=1`、无图章 `s1` 落 `text_only_story_ids`（**不硬造相册页**）✅ |
| `form=胡说`（乱填） | HTTP 200 / ok=true | 回落 `form=scroll` + 带 `fallback_from=胡说` ✅ |
| 非主人取形态（`viewer_id=u_other`） | HTTP 200 / **ok=false / code=forbidden** | 越权被拒 ✅ |
| 无书（`owner_id=u_nobody`） | HTTP 200 / ok=true | `data.empty=true`（不当报错）✅ |

**口径说明（重要·避免误判为 bug）**：本仓 REST 层**统一约定＝一切响应走 200 + `{ok,data,error,code}` 信封**，越权/异常靠 `ok=false`+`code` 表达，**adapter 从不用 HTTP 4xx/5xx 状态码**（全库 grep：无 `JSONResponse`/`status_code=`；既有 `book_api`/`story_api`/`share_api` 越权同样返 `code=forbidden`）。故单面 §二 第 4 点「非主人取形态 → 403」应读作**语义 403（`code=forbidden`）**，实测相符；若前端硬判 HTTP 状态码会漏——**建议前端按 `ok/code` 判分支**（我前端早已如此）。这点请你确认是否即为你的预期口径。
