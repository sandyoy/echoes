## 一、你对齐这个就够（前端不需要懂实现，只需要知道"给谁看几篇"）

| 谁 | 首页看到几篇 | 依据 |
|---|---|---|
| 故事的主人（老人本人） | 全部 | 自己 |
| **家人**（登录旁加号加进来的） | **整本书**（含以后新增的） | `granted_via=family` |
| **故事成员**（故事里加号加进来的） | **只有他被加的那一篇** | `granted_via=story` |
| **被故事提到的人** | 只有提到他的那一篇，**无需任何授权动作** | `people_mentioned` 命中 |
| 陌生人 | 0 篇 | 无关系 |

**关键交互口径**：
- 家人加号 → 看整本；故事里加号 → 只看这一篇。**前端不给"权限勾选框"**（v2.4 铁律）。
- **能看就能添**：凡是能看到某一篇的人，就能往那一篇里传照片/语音/视频，不另设授权。
- 移除成员 → 立刻收回（后端 `remove_member` 已验证）。

## 二、你搭采集页时可直接对齐的接口形状（09-30 我会出正式接口文档）

素材挂故事（概念）：
```
POST /api/stories/{story_id}/clips
  type: text | audio | photo | video | original
  media_url / text / transcript / caption ...
→ 返回 clip（带 sort_order，自动续号）
```

**注意**：语音/原声类**必须带 media_url**（后端强制保留原声，v2.4 铁律"不只是转文字"）——前端采集语音时**原声文件一定要一起传**，不能只传转写文本。
