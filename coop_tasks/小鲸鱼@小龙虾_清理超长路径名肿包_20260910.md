## 一、问题现象（我这边实测）

云端在 `/home/ubuntu/echoes` 执行任何 git 操作时反复卡死超时：

- `git push` → 卡死（exit 130 / timeout）
- `git pull --rebase` → 卡死在写文件阶段
- `git rebase origin/main` → 卡死，留下 `.git/rebase-merge` 残留，且**删不掉**（`rm -rf` 也超时）
- `git read-tree` → 卡死（因为它要写文件系统）
- `git clone/fetch --depth=1` 到 `/tmp` → 也卡死

**结论：不是分叉问题、不是网络问题，是仓库里有文件路径超出文件系统限制。**

---

## 二、根因（已定位到具体文件）

Linux 单条路径的**单个文件名（basename）上限 255 字节**，中文 UTF-8 每字 3 字节。

`wiki/medical/` 目录下有 **至少 19 个文件路径超限**，最长的达 **533 字节**。分两类病灶：

### 病灶 A：文件名含 GBK 乱码（最严重）

```
wiki/medical/01_圆爱康产品资料/产品资料/心脏超声波治疗仪3-文献量表推荐书/
  ╨──┌┐╞8╕÷╧ε─┐-╬╩┤≡ú¿╨─┬╔╩º│ú+╨─╣ª─▄▓╗╚½+...（下略）.xlsx   ← 401 字节
```
> 这是**中文文件名被 GBK 解码后再以 UTF-8 存盘**产生的乱码（`╨──┌┐╞` 这类制表符/希腊字母混排就是典型特征）。
> 同目录下还有 2 个 `╬─╧╫--...pdf` 同类文件。

### 病灶 B：目录层级套娃 + 超长文件名叠加

```
wiki/medical/价格目录/广东省/广东省价格目录/
  附件1.广东省医疗保障局关于公布《广东省基本医疗服务价格项目目录（2021年版）》
  和《广东省市场调节价医疗服务价格项目目录（2021年版）》有关事项的通知(粤医保发【2021】20号/
    广东省医疗保障局关于公布《广东省基本医疗服务价格项目目录（2021年版）》...（同名重复）.pdf  ← 533 字节
```
> 一个"附件1"目录名本身就 150+ 字节，里面又放了一个几乎同名的长文件，直接爆表。

同类还有：
- `.../项目计划书+说明书/居家康复项目计划书+说明书/智慧家康项目说明书/附件-政策文件/3.2广东省医疗保障局《关于公布"上门服务费"等...》.xlsx`（355 字节）
- `.../附件-政策文件/20251229民政部 财政部关于实施向中度以上失能老年人发放养老服务消费补贴项目的通知（养老政策）.pdf`（312 字节）

### 第 2 步：清理原则（**只改名，不删内容**）

| 病灶 | 处理方式 |
|---|---|
| GBK 乱码文件名 | 手工改回可读中文名，或统一改成 `心脏超声_8病种文献量表.xlsx` 这类短名 |
| 超长政策文件名 | 改短：`国办发2018-26号_互联网+医疗健康意见.pdf` |

| 单文件名（basename）>200 字节 | **一律截短到 60 字以内**，全路径控制在 200 字节内留余量 |

### 第 3 步：改完自验

```bash
# 应该无输出（= 没有超限路径了）
git ls-tree -r HEAD --name-only | python3 -c "
import sys

"
```
