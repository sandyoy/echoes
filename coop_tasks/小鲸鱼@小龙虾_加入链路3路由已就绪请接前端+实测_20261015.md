# 补上「我也加进来」这一节 —— 3 条路由已就绪，请接前端 + 本机实测

## 为什么做这件事（这是一条「已确认未落地」的活）

需求书 v3.0 §8之二.5【情况①：有故事，分享故事给你看】写死了一条完整链路：

> 老人/子女选一篇故事 → 点【分享给朋友】→ 微信转发卡片 → 对方点开**直接读（不用登录）**
> → 篇末「这是李桂芳的故事，里面提到了你 **[ 我也加进来 ]**」→ 点按钮 → 微信一键登录 → **默认加入"这一篇"**。

**盘现状（10-15）：头尾都在，中间断了一节。**
- **[头]** `share_api.make_story_share` 造 token + `view_shared_story` 无登录读公开篇，并明确返回 `can_join: True`（"看完后想加进来 → 走登录"）。
- **[断]** **`can_join=True` 之后没人接**：全仓库此前 60 条路由里，没有任何一条把"刚登录的人"挂进"他刚看完的那一篇"。`permissions.add_story_member()` 是个内部函数，**没有任何 API 入口通向它** → 前端拿到 `can_join=True` 却无处可点。
- **[尾]** `can_view_story` 规则3（故事成员→只看这一篇）/ 规则5（被提及者→无需授权）已就绪。

## 新增 3 条路由（第 61~63 条）

| 方法 | 路由 | 作用 | 关键口径 |
|---|---|---|---|
| GET | `/api/echoes/join/target?share_token=&user_id=` | 篇末那一块：给前端拼「这是<owner>的故事，里面提到了你」所需的一切 + 能不能加 | 未登录也返回文案；`can_upgrade_to_family` 恒 False（不擅自替书主人开门） |
| POST | `/api/echoes/join/story` | ★点【我也加进来】→ **默认加入这一篇** | **强制要 user_id**（无 → `login_required`，不许无登录偷偷加人）；**幂等**（再点 `already_joined=True`，Member 不翻倍）；**粒度=单篇**不升全本 |
| GET | `/api/echoes/join/mine?user_id=` | 我加入了哪些书/哪些篇（首页要能看见，否则加完就丢） | 无登录 → `login_required` |

## 三条安全闸门（请前端注意，不是可选）

1. **只加这一篇**：加入后 `granted_via=STORY`、`story_id=那一篇` → `can_view_story` 只放这一篇，**同书别的私有篇照样看不到**。
2. **必须先有可见关系才能加**：加入时先过 `can_view_story`；既不是被提及者、又无既有关系 → 拒（`not_mentioned`）。**不许凭一个 token 就把人塞进别人的私有篇**（v3.0 §1.2 铁律3 / §8之二.7）。
3. **登录态才调**：无 user_id → `login_required`。
