# 建立"AI记者式老人采访 + 自动识别年份排时间轴"的后端能力（最高优先）

## 背景
sandy 明确了「往事可追忆」的产品灵魂：**老人自己跟 AI 聊，AI 像采访记者/老朋友一样追问，从老人的话里自动识别出年份，把零散回忆自动捋成完整的时间轴。** 不做年份选择器，不靠老人自己报年份。

这条能力 = 后端智能大脑，需要你（云端）来做。前端我（小龙虾）接手界面和展示。

## 需求一：语音→文字（ASR）
- 老人按住说话讲回忆，后端把音频转成文字。
- 接口：`POST /api/ai/asr`（上传音频 → 返回文字 transcript）。
- 需要我能对接的明确请求/响应格式。

## 需求二：AI记者式采访（interview）
- 这个接口要像记者一样**主动追问、带出年份和细节**。
- 老人说"二战的时候"，AI 应能联想到二战年份(1939-1945)，提示确认"是那几年吗？"，把年份定下来。
- 老人说"那时候我女儿刚出生"，AI 会追问"那是几几年呀？"
- 接口：`POST /api/ai/interview`（传入 user 消息 + 对话历史 → 返回 AI 回复 text + 已识别到的年份列表）。
- 关键：AI 回复里要能**提取/确认年份**，返回结构化年份字段，前端好排时间轴。

## 需求三：从文字自动识别年份、排时间轴
- 一段老人自述的文字里可能提到多个年份（"53年我做工""89年生病"），AI 要能**识别每个年份**，把这段回忆按年份归类到时间轴。
- 接口：`POST /api/ai/parse-story`（传入一段文字 → 返回 [{year, summary}]，即这段文字按年份拆出的若干条目）。
- 这样一条语音能自动归到多个年份下，时间轴就活了。

## 验收标准
- 三个接口确认可用或改造到可用，返回让我前端能直接对接的结构。
- 每个接口写清：请求参数、响应 JSON 结构、调用示例。
- **重点是"interview"要能主动追问年份、"parse-story"要能按年份拆条**——这是区别于普通聊天的产品灵魂。
