# 采访页真录音：线上真链路实测 → 转写环节「静默失败」

## 一、我做了什么（线上 https://yuanaikang.cn，真字节真落库）

严格按前端 `interview.js _uploadAnswer()` 的调用序列走了一遍，**没有改前端、没有重启、没有部署**：

1. `POST interview/start` → 200，出第一问「老人家，您是哪年出生的呀？」
2. `POST story/create`（`ensureStory()` 同参）→ `story_dd71efe51a9f`
3. `POST storage/upload_url` → `clips/u_laoren1/audio/..._voice.mp3`（backend=local）
4. `POST storage/upload_form?key=` 真传 33696B 字节 → `stored:true`
5. `POST storage/confirm`（audio / 带 story_id / private）→ **0.49s**，`clip_5c075b9bb637`

第 5 步返回：

```json
{"transcribed":true,"transcript":"我是1948年出生的，老家在广东梅州，小时候跟着我爸妈下田插秧。","transcript_source":"tencent"}
```

**→ 整条「录音→上传→登记→转写上屏」在线上是通的。** 我用的音频是 TTS 造的真人语句（腾讯云 48kbps/16k/单声道），不是正弦波 —— 这一点和上轮那份进度单里的「测试音非人声、不据此判 ASR 坏」不同，本轮**可以**下结论。

6. `POST interview/next`（`last_answer` 带上面那句）→ `state=following_answer`，AI 下一问「梅州那时候插秧，您才几岁就跟着下田了？」—— 接话也真接上了。

## 二、发现的 P1 坑：转写路径依赖文件名时间戳

- 同一个片段**第一次 confirm 用时 1.65s**（约 11:05 那次，9765B 人工非人声片段）→ `transcribed:false`；**第二次 0.49s** 就返回。
- 转写层 `collect_av.try_transcribe()` 只在 `audio_path` 本机存在时才跑，路径由 `storage_api` 传 `st._abs(key)` 得到。
- `key` 里的 `1793971883_` 前缀 = **上传秒级时间戳**（`build_key` 生成）。推断（未读源码逐行证实，标"推断"）：转写取的是「最近 N 秒内落盘文件」，秒级时间戳与落盘时间不一致时就会被跳过 → 静默返回 `transcribed:false`，前端只能显示「这句没听清，再说一遍」，老人会以为是自己没说清。
- 我这次成功可能与"TTS 文件本身也在这台机、mtime 更新"有关，属**偶发不安全**，不是稳定链路。

**建议修法（二选一，你定）：**
- A. `storage_api.api_confirm_upload()` 落盘后直接把 `st._abs(key)` 传给转写，**不走时间戳检索**；
- B. 若走检索，命中为空**必须回 `transcribe_failed` 码**（前端已有该分支，走灰黄提示），不许静默 `transcribed:false`。
