## 一、事件事实

| 轮次 | 时间 | 我的判定 | 小鲸鱼实测证伪 |
|---|---|---|---|
| 1~3 | 09-20 夜 ~ 09-21 晨 | 报「后端已停」 | 其账本历轮记：echoes.service active、5 接口全 200 |
| 4 | 09-21 06:26 | 报「后端已停」（lsof 无监听 / curl 000） | 06:40、07:25、07:40 三轮独立复核：`ss -tlnp`=LISTEN *:3000 pid2629104、5 接口全 200、service active 10h+ |

**双方结论冲突 → 查清后确认：我的判定是假警报。**

## 二、根因（已查清，非"服务挂了"）

我的 cron 运行在**本地 Mac**，而 v7 线上后端**跑在另一台云主机（小鲸鱼侧）**。
本地 Mac 上 `localhost:3000` / `lsof -i:3000` 本就不监听 —— **拿本地探针去探云端的服务，必失败**。

- 历史佐证：`docs/daily/内测版盯办_20260908_*` 多篇明确记「server.js 属云端、本无监督 cron 不擅动」「本机 127.0.0.1:3000 为本地 mock 端口」。
- 即：**「对的探针打在错的机器上」**，属探针设计缺陷，不是真实停服。

## 三、危害（为什么要留痕）

1. **误导 sandy**：4 次都建议「重启后端（bash start.sh / node server.js）」——若照做，等于对**健康的线上服务**做一次生产变更，风险自担且毫无必要。
2. **浪费对方**：小鲸鱼被迫连续 4 轮花 token 实测证伪，本可用于正事。
3. **污染账本**：假警报与真进展混在一起，sandy 难以一眼看清。

## 四、防复发规则（立即生效，写进我后续扫描流程）

1. **不在本地探 `localhost:3000`**：本地 Mac 无 v7 后端。凡「后端存活」类判定，**一律不采信本地 lsof/curl 结果**。
2. **后端健康以「小鲸鱼侧实测 + git 证据」为准**：我本侧只核 **git 层面**信号（对方有无代码提交、账本有无记「重启/回退」、接口 mtime 有无变化）；实况判定归后端域（小鲸鱼）。
3. **禁止据本地探针建议重启**：任何「建议重启线上服务」的措辞一律删除。重启 = 生产变更，属对方域 + 铁律 0-C 危险动作，只能由小鲸鱼/交互式会话在实测确证停服后受控执行。
4. **同理适用于其它跨机探针**：凡是"服务在 A 机、探针在 B 机"的判定，先确认"这台机器上它本该在吗"，再下结论。
