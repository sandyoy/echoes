## 一、你的假设 A 命中，根因是 try_files 无限内部循环

你的判断完全对，而且和你昨晚点了的 `/media/` **同源**，就在同一段 `location /` 里。

原配置：

```nginx
root /home/ubuntu/echoes/web/frontend;     # ← 这个目录根本不存在
index echoes.html index.html;
location / { try_files $uri $uri/ /echoes.html; }
```

`/home/ubuntu/echoes/web/` **整个目录在仓库里都不存在**，所以：

请求 `/` → 找不到 → 内部跳到 `/echoes.html` → 还是这个 location → 再跳 `/echoes.html` → 无限循环
→ nginx 报 `rewrite or internal redirection cycle while internally redirecting to "/echoes.html"`
→ 对外 **500**，响应体是 186 字节的 nginx 错误页（跟你的探测完全对上）。

**关键认知：这个项目是「纯 API + 小程序」，本来就没有网页首页。** 配一个指向不存在目录的静态站点 =
永远 500。不是配置写错一个字母，是这一段压根不该按"静态站"来配。

## 二、改法（已生效）

```nginx
location = / {
    default_type application/json;
    return 200 '{"service":"echoes-api","ok":true}';
}
location / {
    try_files $uri $uri/ =404;      # 不再兜到 echoes.html
}
```

## 四、⚠️ 顺手查出一条更致命的坑，已改好前端（请你 review 我的改法）

`miniprogram/app.js` 原来的 `isDevEnv()`：

```js
return !info || !info.miniProgram || info.miniProgram.envVersion !== 'release';
```

**问题：扫码打开的「预览版 / 体验版」`envVersion` 不是 `release`，因此被判成"本地联调" →
`api.login({... forceStub: true})` → 永远拿桩身份。**

也就是说：**只要不是正式发布版，真机扫码永远拿不到真实 openid**，上传的东西全混在一个
`stub_xxx` 口袋里 —— 测试结论不可信，而且和"根 `/` 500"叠加，手机侧表现就是进不去。

改法（commit `fb8319a8`，已推 main）：

```js
isDevEnv() {
  try {
    const info = wx.getAccountInfoSync && wx.getAccountInfoSync();
    if (!info || !info.miniProgram) return true;
    const platform = String(info.miniProgram.platform || '');
    return platform === 'devtools';          // 只有开发者工具算联调
  } catch (e) { return true; }
}
```

判据变化：`envVersion` → `platform`。真机（android/ios，含预览/体验/正式）一律走真 code2session。
