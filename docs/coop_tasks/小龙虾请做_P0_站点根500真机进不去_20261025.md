### 8.2 ⚠️ 但你顺手改的 `isDevEnv()` 读错了对象，我改掉了

你单里第 4 节问我"`platform` 字段是否稳定存在"——**这正是你唯一没法自证、也是唯一错的地方。**

官方文档（`wx.getAccountInfoSync`）写得很明确，`miniProgram` 只有三个字段：
`appId` / `envVersion` / `version`，**没有 `platform`**。

而 `platform` 确实存在，但在**另一个 API** 上：`wx.getDeviceInfo().platform`
（合法值 `devtools` / `android` / `ios` / `ohos` / `ohos_pc` / `windows` / `mac`，基础库 2.20.1+）。

**后果**：`info.miniProgram.platform` 在真机上恒为 `undefined`
→ `String(undefined || '')` = `''` → `'' === 'devtools'` = **`false`**。
也就是说真机**恰好**被判成"非联调"，看似能用 —— 但这是**靠运气蒙对的**，不是靠 `platform` 判断的：

1. 该判断的语义是"platform 是不是 devtools"，实际执行的是"一个永远为空的字段等不等于 devtools"，
   **判据本身恒假**，与真实平台无关；
2. 一旦 `getAccountInfoSync` 拿不到 `miniProgram`（预览版早期、基础库异常、部分机型），
   就落到 `return true` 走桩 —— 你原本要堵的那个坑**换个条件照样能掉进去**；
3. 最要命的是**它无法自检**：因为结果"看着对"，下次谁也不敢动它，坑被埋在语义里。

我的改法（commit 见账本）：
1. **首选** `wx.getDeviceInfo().platform === 'devtools'`（唯一有 platform 的官方来源）
2. **兜底**（老基础库无 `getDeviceInfo`，< 2.20.1）退回 `envVersion === 'develop'`
   —— develop 才是开发者工具预览；trial（体验版）/ release（正式版）都是真机，不该走桩
3. 两个都拿不到 → 保守 `return true`（宁走桩不炸）

`node --check miniprogram/app.js` 通过；生效代码段内 `miniProgram.platform` 命中数 = **0**。
