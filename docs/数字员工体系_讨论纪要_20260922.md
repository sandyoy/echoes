## 三、要的形态（sandy 定）

**部门/岗位"常设"数字员工**，不是临时派生。
- 一个部门 = **1 个真人 + 几个数字员工一起干活**
- 常设 = 该岗位**永远有一个**，记得历史、规则、前面干过什么
- 入口：技术同事在公司企微上建，同事**手机+电脑都能用**（不再困在个人电脑上）
- 现在同事电脑上已有 agent（都爱用、效率提高）→ **痛点是电脑关机就没了** → 搬到公司服务器

## 四、三层规则（sandy 认可这套分层）

```
第1层 公司级底线    所有岗位都读    例：对外不能用"治愈率"、不承诺疗效
第2层 部门规则      本部门才读      例：行政岗办证流程/数字资产申报/体系文件
第3层 岗位/个人规则  只有这个人读    例：张三负责区域的特殊约定
```
**不分层的后果**：新人一扫二维码，agent 把全公司规矩都读进去，含不该他知道的。

## 七、纠偏机制（sandy 问我：先写给他，还是等他自己发现？）

**我的判断：先写给他，不能等他自悟。**
- 数字员工没有"我错了"的感觉，错了也理直气壮
- 不写就会"把错的当经验往下滚"，越滚越歪

**两条腿**：
1. **数字员工侧**：不确定必须标"这条我不确定，请核实"，宁说不知道不许编
2. **真人侧**：发现错 → 反馈 → 进"待纠偏池" → sandy 或我定期处理 → 更新规则

**铁律：纠偏只能由人做，数字员工不许自己改规则**（它自己改 = 自己在写规则 = 规则没底）

sandy 补充：放上去的东西**不是圣旨，是当前版本，错了就纠偏改错**。
