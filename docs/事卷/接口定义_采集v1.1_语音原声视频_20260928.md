## 一、四个新接口（POST，JSON）

| # | 路径 | 干什么 |
|---|---|---|
| 1 | `/api/echoes/clip/audio` | 传**语音**（保留原声 + 尽量转文字） |
| 2 | `/api/echoes/clip/original` | 传**原声**（只留声音，**刻意不转写**——保方言/语气） |
| 3 | `/api/echoes/clip/video` | 传**视频** |
| 4 | `/api/echoes/clip/transcribe` | 给已存在的语音**补转写**（先存原声、文字后补） |

加上 09-26 已有的 `/clip/text`、`/clip/photo`、`/clip/list`、`/upload/url`，
**第1期采集的 6 类素材（文字/语音/照片/视频/原声）接口全齐。**

## 二、统一信封（六个接口完全同形，前端一套解析）

```json
成功： {"ok": true,  "data": {...}, "message": "语音已记下，并转成文字了"}
失败： {"ok": false, "data": {}, "error": "给用户看的中文话", "code": "machine_code"}
```

- `error` 是**直接能显示给老人/家属**的中文，**不要**自己再拼文案。
- `code` 给前端做分支（见下表）。
- `notice`（可选）：**成功但有话要说**时的提示，如「这条有点长，建议分几段说」。

### 前端必须认的 code

| code | 前端该怎么处理 |
|---|---|
| `missing_story_id` | 内部错误，不该发生 |
| `missing_media_url` | 原声没上传成功就调了登记接口 —— 先上传再登记 |
| `invalid_audio` / `invalid_video` | 用 `error` 弹提示，让用户换一个文件 |
| `no_permission` | 「你没有权限往这条故事里补充内容」 |
| `attach_failed` | 罕见（故事被删了），用 `error` |
| `transcribe_failed` | **不算失败** —— 原声已存下，只是没转成字。用 `error` 提示，**不要弹红叉** |
| `upload_not_configured` | 上传通道未接对象存储（见第五节） |

## 三、三个新接口的入参

### 1) 语音 `POST /api/echoes/clip/audio`

```json
{
  "story_id": "st_xxx",          // 必填，挂到哪条故事
  "actor_id": "openid_xxx",      // 必填，谁在传（登录态接入后由后端注入）
  "media_url": "https://...",     // 必填！原声地址 —— 铁律：原声必须留下
  "file_name": "voice_001.mp3",  // 建议填，用于格式校验
  "file_size": 245760,           // 建议填，用于大小校验
  "mime": "audio/mpeg",          // 可选
  "duration": 12.4,              // 建议填（秒），用于时长校验
  "caption": "奶奶讲小时候",       // 可选，小标题
  "audio_path": "",              // ⚠️ 见下
  "do_transcribe": true          // 可选，默认 true
}
```

**返回**
```json
{"ok": true, "data": {
  "clip_id": "clp_xxx", "clip_type": "audio", "sort_order": 5,
  "media_url": "...", "media_duration": 12.4,
  "keep_original_voice": true,     // 恒为 true（v2.4 铁律）
  "transcribed": false,            // 这次是否转成文字了
  "transcript": "", "transcript_source": ""
}, "notice": "原声文件不在本机，转写稍后由后台补"}
```

> ⚠️ **`audio_path` 是本机文件路径，前端不要传**（那是后端/后台转写用的）。
> 前端只管：**① 把音频字节传到 media_url ② 调本接口登记**。
> 转写由后端在拿到字节后处理；失败也不影响你已经存好的原声。

### 2) 原声 `POST /api/echoes/clip/original`

入参与 audio 相同，**去掉 `audio_path` / `do_transcribe`**。
返回同形，**但没有 `transcript` 相关字段** —— 原声按设计不转写。
`notice` 会告诉用户：「这段原声按原样留着，不改一个字」。

**语音 vs 原声，前端怎么选？**
- 用户想说**话**、希望变成文字 → 传 `audio`
- 用户就想**留个声音**（唱一句、说方言、叹口气）→ 传 `original`

### 3) 视频 `POST /api/echoes/clip/video`

```json
{
  "story_id": "st_xxx", "actor_id": "openid_xxx",
  "media_url": "https://...",     // 必填
  "cover_url": "https://...",     // 建议填（wx.chooseMedia 的缩略图）；不填则用视频地址顶
  "file_name": "v_001.mp4", "file_size": 5242880,
  "duration": 45.0, "mime": "video/mp4", "caption": ""
}
```

### 4) 补转写 `POST /api/echoes/clip/transcribe`

```json
{"clip_id": "clp_xxx", "actor_id": "openid_xxx"}
```
- **幂等**：已有文字直接返回（`transcript_source: "cached"`），不重跑。
- 原声素材调它 → `original_not_transcribable`（**这是对的**，别报 bug）。

## 四、校验规则（前端可提前拦，少跑一趟网络）

| 项 | 上限 | 超了怎样 |
|---|---|---|
| 语音大小 | 20 MB | 拒，中文提示 |
| 语音时长 | 15 分钟 | **收下** + notice 提示分段 |
| 语音最短 | 0.5 秒 | 拒（「像是误碰了一下」） |
| 视频大小 | 200 MB | 拒 |
| 视频时长 | 10 分钟 | **收下** + notice 提示分段 |

格式：语音 `mp3/wav/m4a/aac/amr/silk/pcm/ogg/webm`；视频 `mp4/mov/m4v/3gp/webm/avi/mkv`。

## 六、铁律（v2.4，请一起守）

1. **语音保留原声**：`keep_original_voice` 恒为 true，前端不许传 false，传了也被后端强制改回。
2. **转写失败 ≠ 采集失败**：原声先落库，转写是第二步。前端遇到 `transcribe_failed` **不要弹红叉、不要提示重录**。
3. **绝不静默丢素材**：任何拒绝都有中文 `error`，前端照显就行。
