## 一、这块解决什么问题

`book_api.py`（10-11 落地）做到了「把两筐素材装进一个 chapters 数组」，但**没有"书的形态"**：

| 需求 | 之前 | 本件 |
|---|---|---|
| §8.6 形态①翻页 | 无 | `render_paged_book()` |
| §8.6 形态②手机端阅读 | 无 | `render_scroll_book()` |
| §8.6 形态③翻相册式 | 无 | `render_photobook()` |
| §8.6「线上什么样印出来什么样→省排版」 | 无 | `paginate()` 同一结果喂屏幕与印刷 + `computed_page_size_mm()` |
| §8.6【待验证】免排版边界 | 没人评过 | `assess_layout_freedom()` 给可核查结论 |
| §8.4 续添（活文档） | 只能删了重生成 | `api_append_to_ebook()`（保 ebook_id） |

## 二、`GET /api/echoes/book/view` —— 取一种形态

**查询参数**

| 字段 | 说明 |
|---|---|
| `owner_id` | 必填。书的主人 |
| `viewer_id` | 可空，默认=owner_id。**非主人 → 403**（私有形态不外流；对外分享走 `share_api`，只回公开素材） |
| `form` | `paged`（翻页）/ `scroll`（手机端阅读，默认）/ `photobook`（翻相册式）。未知值回落 `scroll` 并带 `fallback_from` |
| `book_spec` | `A5`（默认，148×210mm）/ `A4` |

**返回（信封 `{ok,data,error,code}`）**

```json
{ "ok": true, "data": {
  "empty": false, "ebook_id": "ebook_xxx", "title": "我的一生",
  "story_count": 3, "form": "paged",
  "view": { "form":"paged", "form_label":"书的形式（翻页）",
            "book_spec":{"spec":"A5","width_mm":148,"height_mm":210},
            "page_count":2, "pages":[{"page_no":1,"chapter_title":"结婚那年",
            "time_label":"1968年","entries":[...],"page_size_mm":{...}}] },
  "layout_assessment": { "verdict":"文字部分完全免排版；照片比例需人工选一次；字体需印刷厂兜底",
                         "media_ratio":0.167, "must_manual_decide":["photo_aspect_ratio"] }
}}
```

- **无书 / 空书** → `data.empty=true`，不当报错（前端显示"还没成书"）。

### 三种形态的差别（给前端画页用）

| form | 结构 | 用途 |
|---|---|---|
| `paged` | `pages[]`，每页最多 12 条（按**条目**切，不按字切 → 老人不会看到半句话被切走） | 实体书/翻页阅读，页=印刷 A5/A4 页 |
| `scroll` | `blocks[]`，每条素材一段，带 `viewport_w_px=750` | 手机竖屏连续阅读 |
| `photobook` | `albums[]`，以照片/视频为主、文字做注；**无图的章不硬造相册页**，落 `text_only_story_ids` | 翻相册式浏览 |

**三种形态都保留**：`is_quote` / `quote_label` / `editable`（引用段不可改，§8.2）、`time_label`（时间轴标签）。

## 三、`POST /api/echoes/book/append` —— §8.4 续添（活文档）

| 字段 | 说明 |
|---|---|
| `owner_id` | 必填 |
| `actor_id` | 可空，默认=owner_id；非主人 → 403 |
| `story_ids` | 要续添的故事 id 列表；**空 = 自动补进该书主人尚无的故事** |

**铁律：**
1. **不重建、保 `ebook_id`** —— 只把新 story 追加成章，已有章原样保留（引用段不动）。
2. **幂等** —— 已在该书里的 story_id 不重复加，返回 `changed=false`。
3. **不越权** —— 别人的篇（`Story.owner_id != owner_id`）加不进来；续添只收**自己的**素材（公共素材的收录权在"生成"环节点选，此处不擅自装）。
4. **无书** → `no_ebook`，提示先点【我要成书】。

返回：`{ebook_id, added_story_ids, story_count, changed}`

## 四、§8.6【待验证】免排版可行性 —— 结论（技术侧评估）

| 项 | 结论 | 依据 |
|---|---|---|
| 文字/引用分栏落位 | ✅ **可免排版** | `paginate()` 以**条目**为排版最小单元，同一结果同时喂屏幕（750px）与印刷（A5/A4 mm）→ 线上什么样印出来什么样成立 |
| **照片长宽比** | ⚠️ **不可完全免排版** | 老人手机照片比例不一，固定页框下必须裁切或留白 → **由人工在编书环节选一次**（前端给"裁切/留白"开关）。`must_manual_decide=["photo_aspect_ratio"]` |
| **字体字形** | ⚠️ **外部依赖** | 手写体/特殊符号印刷端可能无字形 → 需印刷厂侧字体兜底（非本端可解）。`external_dependency=["printer_font_fallback"]` |
| 纯文字书 | ✅ **完全免排版可行** | `needs_manual_layout=false`、verdict 明写 |

**一句话**：文字部分免排版；照片比例人工定一次；字体靠印刷厂兜底。—— 这是可核查的边界，不是"基本可行"的空话。
