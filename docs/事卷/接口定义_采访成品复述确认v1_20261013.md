## 一、这块解决什么问题（§7.4 / §7.5 / §7.6）

采访是「一问一答」的碎片，但**成品不能是问答记录**。三步：

| 节 | 要求 | 本件落地 |
|---|---|---|
| **§7.4** | 成品里**只有老人讲的内容**，AI 的问句本身不进作品 | `build_interview_draft()` 剥掉问句 |
| **§7.5** | AI 把碎片**理顺成一段流畅的「自述体」**（成品形态的统一器） | `polish_to_self_narration()` |
| **§7.6** | **复述确认 + 归属确认 = 合成一次**（C 方案）——AI 把理顺后内容**用语音报给老人听**，顺便问归属，**一次问完少折腾老人一次** | `make_recap_script()` + `api_recap_confirm()` |

**铁律**：老人**用耳朵验收**（复述走语音/TTS）比看字靠谱；**任何反应都不算错，含糊/超时→安全默认，绝不卡住老人**。

## 二、接口：`POST /api/echoes/interview/recap_confirm`

### 请求体

| 字段 | 类型 | 说明 |
|---|---|---|
| `owner_id` | str | 必填。讲述人（书的 owner） |
| `viewer_id` | str | 可空，默认=owner_id |
| `story_id` | str | 可空。给了则校验权限（外人 403） |
| `qa_pairs` | list | 一问一答 `[{"q":"AI问句","a":"老人答"}]`；**本层自动剥掉 q（§7.4）** |
| `polished_text` | str | 也可直接给成品文本（会做 §7.5 形态统一） |
| `answer_key` | str | 空=只出复述脚本 / `accept` / `reject` / `timeout` |
| `answer_text` | str | 老人说的话（含糊/不对/没听清） |
| `retry_used` | int | 复述重报已用次数 |
| `apply` | bool | accepted 且 True → 写回 `Story.polished_content` |

### 第 1 次调用（无答案）→ 出复述脚本

```json
{
  "ok": true,
  "data": {
    "phase": "recap",
    "polished_text": "六八年结的婚。摆了两桌，队里人都来了。",
    "raw_answers": ["六八年结的婚。", "摆了两桌，队里人都来了。"],
    "recap_speech": "您刚才说的这件事，是这样：1、六八年结的婚。 2、摆了两桌，队里人都来了。是上面说的这件事吗？",
    "recap_points": ["六八年结的婚。", "摆了两桌，队里人都来了。"],
    "ask_attribution": true,
    "buttons": [
      {"key": "accept", "label": "对，就是这样"},
      {"key": "reject", "label": "不对，我再改改"}
    ],
    "buttons_after_ms": 5000,
    "safe_default": "accept"
  }
}
```
- `recap_speech` = **复述句 + 归属问句**（§7.6 C 方案：一次问完）。前端直接喂 TTS。
- `raw_answers` 只含**老人讲的**（§7.4，无问号句）。

### 第 2 次调用（带答案）→ 判定

| 老人反应 | 入参 | 出参 `decision` | 说明 |
|---|---|---|---|
| 点「对，就是这样」 | `answer_key="accept"` | `accepted` | `apply=True` 则写回 polished_content |
| 点「不对」 | `answer_key="reject"` | `rejected` + `need_revise:true` | 不进成品，让老人重说 |
| 含糊（嗯/对/好…） | `answer_text="嗯"` | `accepted` | 安全侧（铁律 E） |
| 说「不对/不是/错了」 | `answer_text="不对"` | `rejected` + `need_revise` | |
| 说「没听清/再说一遍」 | `answer_text="没听清"` | `phase=recap_repeat` | 重报，最多 2 次 |
| 重报用完仍听不清 | `retry_used>=2` | `accepted` | 安全默认，不纠缠 |
| 5 秒无反应 | `answer_key="timeout"` | `accepted` | 安全默认 |
| 老人又补了内容 | `answer_text="还摆了三天席"` | `accepted` + 并入自述体 | `spoken_extra` |

### 错误

| 场景 | `code` |
|---|---|
| `owner_id` 空 | `bad_request` |
| `story_id` 不存在 | `not_found` |
| 无权看该故事 | `forbidden` |

## 三、两个纯函数（供前端/后端复用）

- `build_interview_draft(qa_pairs)` → `{answers, raw_text, dropped_questions}`（§7.4 剥问句）
- `polish_to_self_narration(text)` → `{polished, changed, note}`（§7.5 理顺，**理顺≠改写，不添加老人没说过的内容**）
- `make_recap_script(db, owner_id, polished_text, points)` → 复述脚本（§7.6）

## 四、留给前端（小龙虾）

1. 采访结束 → 调 `recap_confirm`（带 `qa_pairs`）拿 `recap_speech` → **TTS 播**
2. 播报同时浮两个大字按钮（`buttons`）；`buttons_after_ms` 后仍无反应 → 前端计时到期调 `answer_key="timeout"`
3. 老人点/说 → 带 `answer_key`/`answer_text` 再调一次 → 按 `decision` 决定「进成品 / 重说」
4. **两条真机验收硬项**：复述语音老人听不听得懂；5 秒无反应兜底按钮大小是否够点。
