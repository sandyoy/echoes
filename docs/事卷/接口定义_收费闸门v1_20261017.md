## 〇、为什么有这个文件（真缺口，不是概念）

10-12 已落 `payment_api.py`：开价、下单、回调置 paid、查单，一条龙。但**链路在最后一步断了**：

```
Pricing 表开价 → Order 落 pending → 微信回调 → Order.status = paid → ✅
                                                                      ↓
                                                   然后？**全仓库没有一处读它。**
```

实锤：`grep -rn "Order\b" backend/*.py`，除 `payment_api.py` / `models.py` 外 **0 命中**；
`book_view_api` / `book_api` / `share_api` 一次都没问过"这人付没付"。
**结果＝钱收了、权限不发。** "单本收费""年费会员"两种模式形同虚设。

本文件补这一跳：**Order 表 → 判决（能不能看）**，并把卡点只设在"完整版渲染"这一个出口。

## 一、判决口径（唯一真相源）

| 情况 | paid_required | entitled | reason | 前端表现 |
|---|---|---|---|---|
| Pricing 表无该模式 / active=false / price≤0 | false | **true** | `free` | 照常用，不显示付费 |
| 未登录 | true | false | `no_user` | "登录后可购买" |
| 登录、未买 | true | false | `not_paid` | 预览 1 章 + 「解锁」按钮（带价） |
| 买断（single_book）且 paid | true | true | `paid` | 全通，`valid_until=永久` |
| 年费（yearly）paid 且未过期 | true | true | `paid` | 全通，带到期日 |
| 年费过期 | true | false | `expired` | "已到期，续费可继续看" |
| 判决逻辑异常 | false | **true** | `fail_open` | 放行（带 `warning=fail_open` 进日志） |

**四条铁律：**
1. **零信任前端**——只认库里 `status=paid` 的单，绝不接受请求体说"我买过了"。
2. **fail-open**——任何异常/配置缺失一律放行。宁可少收一单，**绝不让老人打不开自己的书**。
3. **后台开关即全站行为**——§9.3「免费↔收费＝后台开关」的代码真身：`Pricing.active` 一行改动，下一次请求立即生效，**不用发版**。
4. **只卡成品，不卡素材**——锁的是 §8.6 三种形态的完整渲染（含 A5 印刷件）；老人自己录的、写的、照片语音，**一条都不锁**。

## 二、接口

### 2.1 `GET /api/echoes/pay/entitlement?user_id=` （第73条）

> 路由计数口径：改前 `grep -c "^@app\.(get|post|put|delete)"` = 71，本次 +2 → **73**。
> （此前文档里写的"72 条"混算了别的装饰器，以本命令为准。）

我在这个程序里到底买过什么。

```json
{ "ok": true, "data": {
    "paid_required": true,
    "entitled": true,
    "reason": "paid",
    "plan_code": "yearly",
    "valid_until": "2027-10-17 00:00:00",
    "notice": ""
}, "error": "", "code": "" }
```

用途：**我的 → 会员**页（"你是年费会员，2027-10-17 到期"／"你没买，单本 29 元"）。价格一律现读 Pricing 表，前端不写死。

### 2.2 `GET /api/echoes/book/lock_state?owner_id=` （第74条）

"我的书"页进页**先调这个**，别直接请求 view 撞锁。

```json
{ "ok": true, "data": {
    "paid_required": true, "entitled": false, "locked": true,
    "can_preview": true,
    "plan_code": "single_book", "plan_name": "单本电子书", "price": 29.0,
    "notice": "这本书还没解锁，付费后可以看完整版"
} }
```

`can_preview` 恒为 `true`——**不给预览不叫收费，叫要挟**。

### 2.3 `GET /api/echoes/book/view`（改：加闸门，不改形状）

已买的／免费的：**返回与 10-13 完全一致**（向后兼容，前端零改动）。
未买的：返回 **HTTP 200 + `ok=true`**，但 `locked=true`、`view=null`、`code=need_pay`：

```json
{ "ok": true, "data": {
    "empty": false, "locked": true,
    "ebook_id": "...", "title": "...", "story_count": 12,
    "entitlement": { ...同 2.2... },
    "preview": { "chapters_visible": 1, "chapters_total": 12,
                 "notice": "这本书还没解锁，付费后可以看完整版" },
    "view": null
}, "warning": "need_pay", "code": "need_pay" }
```

> 为什么 `ok=true`：**书是存在的、是老人自己的**，只是"完整版没解锁"。若返 `ok=false`，前端会当错误弹窗——那是把生意做成了故障。
> 预览章数由 `book_view_api.PREVIEW_CHAPTERS` 控制（现为 1），后台想放宽改一个常量。

**已有前端影响评估**：`miniprogram/pages/book` 当前是空壳（10 行 js），**无既有调用方**，故本次加锁零回归风险。

## 三、自测实证（17 条，全部为"改了表/改了单，判决跟着变"的活证）

| # | 断言 | 性质 |
|---|---|---|
| ① | Pricing 空 → 全站 free | 未开价不误伤 |
| ② | 开价未买 → not_paid，且带上要买的 plan/价格/人话 | 前端可直接渲染 |
| ③ | 买断 paid → 永久授权 | 核心正向 |
| ④ | 年费 `paid_at=-366天` → expired；`-10天` → paid | 到期边界 |
| ⑤ | 后台 active=false → 连没买的人也 free | §9.3 开关 |
| ⑥ | 表价 29.9→59.0 → 判决里金额即时变 | §9.1 零写死 |
| ⑦ | pending 单不算；别人的 paid 单不授权 | 零信任 |
| ⑧ | 注入异常 → fail_open 放行 | 铁律4 |
| ⑨ | 未买 → `locked=true`、`view=null`、仍给预览+报价 | 收钱不关死 |
| ⑩ | 买断同一本 → `locked=false` 且 view 有内容 | 解锁生效 |
| ⑪ | 素材表照常可读写 | 只卡成品 |
| ⑫ | `require_entitled` 未过 → `ok=false + code=need_pay + entitlement` | 信封形状 |
