### 🧨 10-24 修的两个后端硬伤（★重要，防复发）

**硬伤 A：`storage/confirm` 10 天来一直 500（裸奔 bug）**
- 症状：登记接口 POST `/api/echoes/storage/confirm` 一律 500 `Internal Server Error`
- 根因：`api_adapter_fastapi.py` 调 `storage_api.api_confirm_upload(db, ...)` 用**位置参数**传 db，
  而该函数签名是 `def api_confirm_upload(*, db, ...)`（**全 keyword-only**）→
  `TypeError: takes 0 positional arguments but 1 positional argument ... were given`
- 修法：`db,` → `db=db,`（一行）。修后返回明确中文码（如 `missing_story_id`），不再 500。

**硬伤 B：真机 `wx.uploadFile` 打不到后端（10-14 起就埋着）**
- 症状：真机上点拍照/录音上传会"卡住/失败"，域名填得再对也没用
- 根因：微信小程序 `wx.uploadFile` **只支持 POST + multipart/form-data，不支持自定义 PUT**（官方硬限制）；
  而 `LocalStorage.upload_url()` 返回的是 `/storage/put`（**PUT + 原始字节**）→ 协议对不上
- 修法（已落）：
  1. `api_adapter_fastapi.py` 新增 `POST /api/echoes/storage/upload_form`（字段名 `file`，key 在 query）
  2. `storage_api.py` 的 `LocalStorage.upload_url()` 改返回该表单端点（**前端无需改代码**）
  3. 补依赖 `python-multipart`（本机 pip 被锁 → 装到 `~/.local/lib/python3.12/site-packages`）
- ⚠️ 切 COS 后此端点闲置（前端直传签名地址），**别删**

### ⚠️ 进程托管真相（10-24 查清，别再瞎猜）

- **后端由 systemd `echoes-api.service` 托管**（`/etc/systemd/system/echoes-api.service`，`Restart=always`，`RestartSec=3`）
- 日志落 `/tmp/echoes-api.log`
- **重启正确姿势**：`kill` 掉 8971 上的进程 → systemd 3 秒内自动带新代码拉起（`systemctl restart` 对 ubuntu 用户无权限，会卡住）
- 事卷此前写的"无 systemd 托管、裸进程"是**错的**，已在此更正

### 🧨 10-15 踩坑记录（★重要，防复发）

**症状**：小程序后台域名配好了，但外网 `/api/...` 全 404/500。
**根因**：nginx `upstream echoes_backend { server 127.0.0.1:**3000**; }` 指向**僵尸 Node 服务**（`/home/ubuntu/echoes/backend/server.js` **已不存在**，进程从 9-20 挂到现在），而**真后端是 Python/uvicorn，跑在 `8971`**（10-01 起手动启动，裸进程无 systemd 托管）。
**修法**（已在服务器执行）：
```bash
sudo sed -i 's|server 127.0.0.1:3000;|server 127.0.0.1:8971;|' /etc/nginx/sites-enabled/echoes && sudo nginx -t && sudo systemctl reload nginx
```
**遗留隐患（第二步再做，别忘）**：
- ⚠️ Python 后端（8971）**无 systemd 托管**，服务器重启即丢 → 应补一个 `echoes-api.service` 指向 `python3.12 -m uvicorn api_adapter_fastapi:app --host 127.0.0.1 --port 8971`
- 旧 `echoes.service` 建议 `sudo systemctl disable --now echoes.service`（可选，不影响接口）
- ⚠️ 安全层：云端 Hermes 对 `/etc/nginx/` 下操作**一刀切拦截** → 这类改动必须 sandy 手动敲（本次即如此）
