## 一、这条线解决什么（人话）

写故事的人（张三）要把老李写进故事，**老李可能还没账号**。
→ 先按「手机号 / 名字」把老李**登记**成一条「待认领」
→ 老李**哪天注册都行**，用同一手机号自动认领
→ 认领后首页出现「**有 N 篇故事提到了你**」
→ 手机号对不上时，走**按名字搜索认领**（须张三那边点确认）

**铁律**：被提到的人看「提到自己的那篇」**永远不需要授权**；授权只出现在他想要**全本**时。

## 二、接口清单

路径前缀统一 `/api/echoes/claim/`。所有接口返回统一信封：

```json
{"ok": true,  "data": {...}}
{"ok": false, "error": "中文人话原因", "code": "bad_request|unauthorized|forbidden|not_found"}
```

**小前端只需认 `ok` 一个字段。** 任何失败都带中文 `error`，可直接弹给老人看。

| # | 方法 | 路径 | 用途 | 谁调 |
|---|---|---|---|---|
| 1 | POST | `/api/echoes/claim/register` | 写故事时把人登记成待认领 | 写故事方 |
| 2 | POST | `/api/echoes/claim/login` | **登录后调这一个**：自动认领 + 拿首页数字 | 所有登录的人 |
| 3 | GET | `/api/echoes/claim/mentioned` | 「有 N 篇故事提到了你」+ 列表 | 首页 |
| 4 | GET | `/api/echoes/claim/search` | 按名字搜索候选（须登记人确认） | 手机号对不上的人 |
| 5 | POST | `/api/echoes/claim/confirm` | 登记人确认「这就是他」 | 写故事方 |
| 6 | POST | `/api/echoes/claim/reject` | 登记人否认 | 写故事方 |
| 7 | GET | `/api/echoes/claim/pending` | 我还有哪些人没被认领 | 后台/提醒 |

## 三、逐个接口

### 1. 登记待认领 `POST /api/echoes/claim/register`

请求：
```json
{"owner_id": "u_zhangsan", "phone": "13800138000", "display_name": "李叔", "story_id": "story_xxx"}
```
- `phone` 与 `display_name` **至少给一个**，都给最好（手机号认领快，名字是备选路）
- `story_id` 可选：指名道姓提到谁时传（老李点开就能看到这篇）

响应：
```json
{"ok": true, "data": {"claim_id": "claim_xxx", "status": "pending",
                      "match_type": "phone", "display_name": "李叔",
                      "phone_masked": "138****8000"}}
```

**注意**：手机号**回显一律脱敏**（`138****8000`），前端不要拿它做匹配。

### 2. 登录总入口 `POST /api/echoes/claim/login` ⭐ 前端最常用

请求：`{"user_id": "u_laoli", "phone": "13800138000"}`

响应：
```json
{"ok": true, "data": {"owners": ["u_zhangsan", "u_lisi"],
                      "claimed_claims": ["claim_a"],
                      "claimed_members": ["mem_b"],
                      "mentioned_count": 3}}
```
- `owners` = 这个人**全部**归属的书主人（**不只本次新认领的**，含以前认领过的）
- `mentioned_count` = 「有 N 篇故事提到了你」的 N → **N>0 时首页显示红点提示**
- **幂等**：重复登录不重复认领、数字不翻倍

### 3. 提到了我 `GET /api/echoes/claim/mentioned?user_id=u_laoli`

```json
{"ok": true, "data": {"count": 3, "stories": [
  {"story_id": "story_xxx", "title": "和李叔一起下矿", "summary": "",
   "time_label": "1970年代（老人说的）", "owner_id": "u_zhangsan"}]}}
```

### 4. 按名字搜索 `GET /api/echoes/claim/search?display_name=李叔`

```json
{"ok": true, "data": {"count": 1, "hint": "须写故事的人确认后才会生效",
  "candidates": [{"claim_id": "claim_xxx", "display_name": "李叔",
                  "owner_id": "u_zhangsan", "story_id": "story_xxx",
                  "story_title": "和李叔一起下矿", "need_owner_confirm": true}]}}
```
**候选 ≠ 生效**。前端必须把请求发给写故事方点确认。

### 5. 登记人确认 `POST /api/echoes/claim/confirm`

请求：`{"claim_id": "claim_xxx", "owner_id": "u_zhangsan", "user_id": "u_laoli"}`

- **只有 `owner_id`（登记人本人）能确认**，别人调返回 `code=forbidden`
- 这就是「手机号对不上」时的兜底路，防重名冒领

### 6. 登记人否认 `POST /api/echoes/claim/reject`
请求：`{"claim_id": "claim_xxx", "owner_id": "u_zhangsan"}` → 状态转 `rejected`，不再出现在候选里。

### 7. 未认领名单 `GET /api/echoes/claim/pending?owner_id=u_zhangsan`
```json
{"ok": true, "data": {"count": 1, "claims": [
  {"claim_id": "claim_xxx", "display_name": "钱叔", "phone_masked": "136****6000",
   "match_type": "phone", "story_id": null}]}}
```

## 四、前端要接的三个点（建议）

1. **登录成功后**：`POST /claim/login` 一次，把 `mentioned_count` 存下 → 首页红点
2. **写故事加人时**：先 `POST /claim/register`（手机号优先），对方没账号也照样写进去
3. **对方说"我不是这个手机号"时**：`GET /claim/search?display_name=` → 拿候选 → 提示"等写故事的人确认"

- N 计数：只算提到他的，没提到的人 N=0
- 跨书认领：`owners` 含多家；重复登录幂等、数字不翻倍
