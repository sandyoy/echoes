## 一、一句话讲清楚这个产品（v3 版）

> **一个把老人一生的话、字、照片、视频、原声收集起来，自动按时间轴排好，让每个"我"都能从中长出一本自己的书。**

**关键词：每个"我"。** 旧说法"一键变成一本书"错在只有一个"我"。

## 二、地基：视角容器模型（sandy 已确认）

### 2.1 不做"真相的裁决者"，只做"视角的容器"
- 一件事八个人看有八面，**八面都对，不需要拼成完整真相**。
- 系统不负责对齐/拼合/裁决；只负责让每个"我"看的那一面被留下。
- **反例（禁止）**：把"我"变成侦探，非要八个人说法对齐成一条线索链。

### 2.2 素材是公共的，"看"是私人的
- **素材** = 池子；**"我"** = 藏在"谁在看"里，不写在主角身上。
  - 甲写"邻居家那场火" → 书的主角是邻居，书里的"我"是甲。
- **"为谁写"不重要**——写完之后的事，不定义"这书是谁的"。
  - **sandy 原话**："作者只要在写，就都是为自己写——哪怕写的是别人的故事，那也是自己想说的话。"

### 2.3 一棵树
| 层级 | 对应 | 说明 |
|---|---|---|
| 主干 | 公共素材池 | 共同经历，不带"我" |
| 枝 | 各人成书 | 各人按自己视角"摘"出来的一本 |

### 2.4  死结解法：不是"复制素材"，是"引用素材 + 各写各的胶水"
- **甲的原话在邻居书里 = 引用，不是复制**（标"这段来自张大叔的讲述"）。
- 引用段：**改不了**，但**可在旁边加自己的话**；**不算进引用者的署名**。
- → 素材算谁的 / 能不能改 / 署谁的名，三死结自然消失。

### 2.5 唯一系统必须管的
- **"我"不会自动换人**。系统不需"转换"人称，只需保证：**每人只写自己的"我"、只引用别人的话**。
- **系统唯一要兜的**：别让另一个人的字冒充成我的字（引用段标出处、不可改）。

### 2.6  新增：公开 / 私有闸门（sandy 2026-10-09 新增，本页最重要一条）

**素材不是"写进来就归公共"——公开是提供人主动做的一个动作。**

| | **公开素材** | **私有素材** |
|---|---|---|
| 进哪 | 进公共池（故事的角色池） | 只进**提供人自己的私有库** |
| 别人能看吗 | 能 | **不能** |
| 别人能引用吗 | 能 | **不能** |
| 别人能写吗 | 能 | **不能** |
| 被提及的人能看到吗 | **能**（v2.4 铁律在此成立） | **不能**（sandy 新拍：私有库提到人也不给看） |
| 能分享吗 | 能 | **不能**（"分享出去=已公开"，天然排除） |

**三条定论：**
1. **默认私有**（写进来先是自己的）；**公开要主动点一下**。（同"朋友圈默认保守、放开是主动"）
2. **公开范围 = "这个故事的所有角色"**（v2.4 说的"故事里的人"），不是公开给全世界。
3. **v2.4 铁律要改**：旧"看提到自己的那篇永不需要授权" → **改为"只在公开的篇里成立"**；私有库里提到谁，**不给谁看**。

**这条的价值（写下来，防将来被简化掉）**：
> 保护"**还没想好要不要说**"的阶段。老人写一段私下的回忆（家丑、不愿人知的往事），可能**正在犹豫**。私有给了他一个安全区：**先写下来、锁着，想清楚了再公开。**
> 一句话：**公开 = 允许它进入"大家的记忆"；私有 = 这只是我自己的记忆，还没准备好让它变成大家的。**

**由"公开"定义自动长出的规则（不需另定）：**
- 分享机制**只作用于公开素材**——"我分享出去，证明它已不是私有"（sandy 原话）。
- "待认领"提醒**只认公开篇**里提到的人；私有库里提到的人**不提醒**（否则=泄密）。

### 2.7 成书时的两筐素材（sandy 定）
1. **自己的素材** → **自动**按时间顺序装进书里（不用选）。
2. **公共素材** → **点选要不要装**（不一定全装）。

### 2.8 明确不管的
| 问题 | 态度 |
|---|---|
| 两本书对不上 | **不管**，是本来的样子，是卖点 |
| 谁是"主编"/"供稿人" | **不管**，不设这套 |
| "送礼物"算不算主线 | **不管**，写信后顺手动作，边角料 |
| 主角能不能换人 | **不管**，谁出书谁是主角，一份素材可被多本用 |

## 三、【留口】想到但没想透的（雷区地图，不装没有）

1. **【留口·接口】素材条目从第1期起就带"来路"字段**
   - 必须能记：**谁放的 / 公开还是私有 / 原创还是引用 / 引用自谁 / 出处名字（可能是称呼非账号）**。
   - 第1期可不用，**字段必须在** → 第3期成书直接用，**不回头撬第1期接口**。

2. **【留口·权限】"能看 / 能写 / 能引用 / 能公开"可能是四件事**
   - v2.4 定"能看就能补"；今天多了"引用""公开"两层 → 是否分开？待定。
   - **红线（改后版）**：看"**公开篇**里提到自己的那篇"永不需授权；**私有库提到的人不给看**。

3. **【留口·成书】第3期"各摘各枝"的操作入口**
   - 老人不懂"fork"，要不出现技术词的做法（如"用这段""这是我的版本"）。待第3期设计。

4. **【留口·人名】"认领"靠转发、不靠系统识别被提到的人**（v2.4 已定）
   - 因记忆用称呼/笔名，非微信名。**引用出处的名字也走这条**（可能是称呼）。

5. **【留口·边界】多视角怎么呈现给读者**
   - 已定"**不收**"（读者要的是多个视角的入口，不是一个结论）。怎么摆是第3期的事。

6. **【留口·新】私有的边界——"部分公开"要不要**
   - 现在只有"公开/私有"两态。将来要不要"只给指定的人看"（如只给大儿子）？**待定，先不做。**

7. **【已取消·2026-10-09】"子女代放"** —— sandy 拍板：**素材只由"本人"入库，系统不做"替人代放"**；别人手里的照片走**微信原路转给他本人**，由他本人入库、本人定公开/私有。（详见需求书 v3.0 §6.2.1）
