## 一、通用约定

### 1. 统一返回信封（所有接口长一样）

```json
// 成功
{ "ok": true,  "data": { ... }, "message": "文字已记下" }

// 失败
{ "ok": false, "error": "给老人看的中文原因", "code": "机器判定的错误码", "data": {} }
```

**前端铁律**：只看 `ok`。`ok=false` 时把 `error` 原样显示给用户（都是给老人/子女看的中文），
`code` 只用于你这边分支判断，**不要把 code 显示给用户**。

### 2. 两个 ID 的区别（最容易搞混，务必分清）

| 参数 | 是什么 | 例子 |
|---|---|---|
| `owner_id` | **这本书的主人**（讲述人，老人） | `u_grandpa` |
| `actor_id` | **谁在操作**（老人自己 / 子女 / 故事里的人） | `u_daughter` |

> 权限判定的根是 `owner_id`，不是你当前登录的人。
> v1 阶段：登录态没接，`api_adapter_fastapi.py` 里 `owner_id` 暂取 `actor_id`，
> 并标了 `# TODO 登录态注入`。**你前端不用管**，按正常传两个 id 就行，后端替换时你不用改。

### 3. 错误码总表

| code | 含义 | 前端怎么处理 |
|---|---|---|
| `missing_story_id` | 没传 story_id | 你代码 bug，别显示给用户 |
| `empty_text` | 文字是空的 | 提示"说点什么再存" |
| `text_too_long` | 超 20000 字 | 提示太长 |
| `missing_media_url` | 图片没地址 | 上传步骤没走完，重试上传 |
| `invalid_image` | 不是图片 / 太大 / 0字节 | 直接显示 `error`（带具体原因） |
| `no_permission` | 没权限往这条故事补充 | 提示"你没有权限…"。**注意：取不到时也返回这个码，不区分"不存在"与"没权限"（防探测）** |
| `upload_not_configured` | 上传通道未接对象存储 | 见第四节 |
| `attach_failed` | 落库失败 | 显示 `error`，可重试 |

## 二、接口 1：挂文字素材

`POST /api/echoes/clip/text`

**请求体**
```json
{
  "story_id": "s_abc123",      // 挂到哪条故事（必填）
  "actor_id": "u_daughter",    // 谁在传（必填）
  "text": "1968年我第一次坐火车去北京，车厢里全是人。",  // 必填，非空
  "caption": ""                // 可选，小标题
}
```

**返回**
```json
{
  "ok": true,
  "data": {
    "clip_id": "clip_93b568b22565",
    "story_id": "s_abc123",
    "clip_type": "text",
    "sort_order": 3,               // 在筐里的位置（自动续号）
    "created_at": "2026-09-26T10:31:00.455171"
  },
  "message": "文字已记下"
}
```

**后端已验证的行为**（自测 A1–A9）：
- 正文**两头空格自动去掉**
- 空文字 → 拒（`empty_text`）
- 故事不存在 → 拒（`attach_failed` + "故事不存在"）
- 陌生人 → 拒（`no_permission`）
- **家人**（看整本）→ 能补充 ✅
- **故事成员**（只绑了 s1）→ 能补充 s1 ✅，**补充不了 s2** ✅
- 被拒的素材**一件都没落库**（自测 G1 验证过）

## 三、接口 2：挂图片素材

`POST /api/echoes/clip/photo`

> ⚠️ 注意分工：**这个接口只管"登记"**，不管字节上传。
> 字节先走上传通道拿到 `media_url`，再调这个接口登记（见第四节）。

**请求体**
```json
{
  "story_id": "s_abc123",
  "actor_id": "u_daughter",
  "media_url": "https://cdn.example.com/a.jpg",  // 必填
  "file_name": "火车.jpg",       // 建议传（后端靠扩展名认格式）
  "file_size": 3500000,          // 字节，必填
  "mime": "image/jpeg",          // 建议传（无扩展名时靠它认）
  "cover_url": "",               // 可选缩略图；不传则后端用原图顶
  "caption": "站台"              // 可选配文
}
```

**返回**：结构同接口 1，多返回 `media_url` / `cover_url`，`clip_type` 为 `"photo"`。

**图片规则**（已实测 B1–B7、C1–C5）

| 规则 | 值 |
|---|---|
| 支持格式 | jpg / jpeg / png / webp / **heic（苹果手机原图）** / gif / bmp |
| 单张上限 | **20 MB** |
| 0 字节 | 拒（"图片是空的"） |
| 无扩展名 | 必须带合法 `mime`，否则拒（"认不出这是图片"） |
| 非图片（如 .pdf） | 拒 |

**前端特别注意**：苹果手机**默认传 HEIC**，我们已支持，你**不用**在前端转 jpg。
但如果你们的 picker 会把文件名抹掉（只剩 `blob`），**必须把 mime 带上**，否则会被后端拒。

## 四、接口 3：取上传地址

`POST /api/echoes/upload/url`

```json
// 请求
{ "file_name": "a.jpg", "file_size": 1000, "mime": "image/jpeg" }

// 当前返回（对象存储还没定，故意明确报未接，不假装成功）
{ "ok": false, "code": "upload_not_configured",
  "error": "上传通道未接对象存储（待 sandy 定 COS/自建）——当前先用 media_url 直传登记" }
```

**约定好的三步流程（接口形状已冻结，前端可以照写）**：
1. 调本接口拿 `upload_url`
2. `PUT` 字节上去，拿到 `file_url`
3. 用 `file_url` 当 `media_url` 调**接口 2** 登记

> 等 sandy 定了对象存储（腾讯云 COS / 自建），后端把本函数换成真实签名 URL，
> **第 1 步的请求/返回形状不变 → 前端一行不改**。

## 五、接口 4：取一条故事的素材筐

`GET /api/echoes/clip/list?story_id=xxx&viewer_id=xxx`

**返回**
```json
{
  "ok": true,
  "data": {
    "story_id": "s_abc123",
    "count": 5,
    "count_by_type": { "text": 3, "photo": 1, "audio": 1 },
    "clips": [
      {
        "clip_id": "clip_93b568b22565",
        "clip_type": "text",
        "text": "1968年我第一次坐火车…",
        "media_url": "",
        "cover_url": "",
        "caption": "",
        "keep_original_voice": true,
        "created_by": "u_daughter",
        "sort_order": 0,
        "created_at": "2026-09-26T10:31:00"
      }
    ]
  }
}
```

**顺序**：`clips` 已按 `sort_order` 升序排好，**前端直接渲染即可，不用再排**
（自测 D3/D4 验证过：升序、从 0 起、无空洞）。

**权限**：看不到这条故事 → 返回 `ok=false` + `no_permission`，**不告诉"存在但你没权限"**（防探测）。
前端遇到这个就直接当"没有"处理。

**`created_by` 用得上**：显示"这件是女儿补的"——v2.4 里一家人往同一个筐里添，要能看出谁添的。
（自测 F2 验证过，筐里能区分出主人/家人/故事成员三个人。）
