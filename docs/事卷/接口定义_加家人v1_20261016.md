## 〇、这份接口补的是什么（一句话）

需求书 v3.0 §2.2 把权限模型钉死在**两个加号**上。到 10-15 为止，**故事里的加号**已通（`join_api.py`），
**登录旁的加号**仍是断头——`permissions.add_family_member()` 是内部函数，全仓库没有一条 API 通向它。
本件把它补上，让 §2.2 两个加号在 API 层**对称闭合**。

| 加号 | 接口文件 | granted_via | 可见范围 | 状态 |
|---|---|---|---|---|
| **登录旁的加号** | `family_api.py`（本件） | `FAMILY` | **看整本书** | ✅ 2026-10-16 |
| 故事里的加号 | `join_api.py` | `STORY` | 只看这一篇 | ✅ 2026-10-15 |

**铁律（§2.2）**：权限由**从哪个入口加进来**决定，**不设权限勾选框**。
→ 因此 `family_api.add` **没有 scope 参数**：从这里进来**永远**是 FAMILY（看整本）。

## 一、四个接口

### 1. `GET /api/echoes/family/search` — 按名字搜人（§2.3「选名字加入」）

| 参数 | 必填 | 说明 |
|---|---|---|
| owner_id | 是 | 书主人（登录态） |
| name | 是 | 名字（昵称/真名） |

**返回**
```json
{ "ok": true, "data": { "candidates": [
    {"user_id":"u_x","display_name":"小芳","already_family":false,"relation":""}
  ], "count": 1 }, "error":"", "code":"" }
```
- 精确匹配**优先**；精确为零时给前缀命中（前端让用户再点一下确认）。
- **不把自己列进候选**；**不返手机号**（最少信息）。
- 无登录 → `code=login_required`。

### 2. `POST /api/echoes/family/add` — ★加家人（§2.2 登录旁的加号）

| 参数 | 必填 | 说明 |
|---|---|---|
| owner_id | 是 | 书主人（登录态） |
| user_id | 二选一 | 对方已在小程序 → 直接建成已认领 |
| phone | 二选一 | 对方还没上过 → 建成**待认领**，等对方登录自动认领 |
| display_name | 否 | 名单显示名（未给 user_id 名时自动补对方昵称） |
| relation | 否 | 女儿/儿子/朋友 |

**★ 没有 scope 参数**——从这里进来永远是 `FAMILY`（看整本）。

**返回**
```json
{ "ok": true, "data": {
    "member_id":"mem_x","granted_via":"family","granted_scope":"book",
    "claimed":true,"book_story_count":2,"display_name":"小芳","phone_masked":"138****8888"
}, "error":"", "code":"" }
```

**错误码**：`login_required`（无登录）｜`is_self`（不许把自己加成自己家人）｜
`no_target`（手机号/名字/user_id 一个都没给）｜`already_family`（幂等，回原记录）。

**幂等**：同一人加两次 → `already_family=true`、`member_id` 不变、Member 不翻倍。
手机号归一（空格/横线）后仍认得出是同一人。

### 3. `GET /api/echoes/family/list` — 我的家庭通讯录

**返回**：`family`（已认领）/ `pending`（待认领）两栏 + 计数。
手机号一律脱敏（`138****8888`）。`scope` 恒为 `"book"`。

### 4. `POST /api/echoes/family/remove` — 移出家人

| 参数 | 说明 |
|---|---|
| owner_id | 书主人 |
| member_id | 要移出的家人记录 |

**错误码**：`not_found`｜`forbidden`（不是自己名单里的）｜`not_family`（单篇成员不在家人名单，请到那一篇移除）。
移除后 → 该人**不再能看整本**（`can_view_story` 由真转假），**不动**他作为单篇成员的关系。

## 二、与既有接口的关系（不许串）

| 既有 | 关系 |
|---|---|
| `claim_api.api_register_claim` | 家人（未注册）走 phone → PENDING；对方登录时由 `api_claim_on_login` 用同一手机号自动认领（**复用既有机制，未新造第二套**） |
| `join_api.api_my_memberships` | 已含 `families` 段——家人加完后，**在对方那侧**通过这条看见「我加入了哪些书」 |
| `api_mentioned`（§8之二.7） | 「别人写我」——与「我主动加进去的」互补，本件不改 |
| `can_view_story` 规则2 | `granted_via=FAMILY` → 能看整本（含后续新增），本件依赖它、未改它 |

## 三、留给前端（小龙虾）

1. **「登录旁的加号」** → 打开一个面板：①按名字搜（调 `family/search`）选人 ②或直接填手机号
   → 点【加为家人】→ 调 `family/add`。
2. **家庭通讯录页** → 调 `family/list`，已认领/待认领分两栏显示（待认领标「还没上过，等他登录」）。
3. **移出** → 调 `family/remove`。
4. **口径提醒**：界面词**不叫「权限」**（§2.2 老人不需要理解权限）；叫「加上她，让她看整本书」。
