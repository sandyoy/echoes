## 二、全链路动线（联调就照这个顺序点）

```
[首页]  ① 登录         POST /api/echoes/login                → user_id（此后所有请求都要它）
                        切界面  POST /api/echoes/login/ui_mode  → standard / large
[采集页]② 建书（第1期无接口，前端本地建 / 后端建书接口待补）
        ③ 5 类素材挂同一件事：
             文字  POST /api/echoes/clip/text
             照片  POST /api/echoes/clip/photo
             语音  POST /api/echoes/clip/audio
             原声  POST /api/echoes/clip/original
             视频  POST /api/echoes/clip/video
[采集页]④ 取筐         GET  /api/echoes/clip/list?story_id=&viewer_id=
[首页]  ⑤ 我的书       GET  /api/echoes/login/profile?user_id=
[首页]  ⑥ 有N篇提到我  GET  /api/echoes/claim/mentioned?user_id=
[待认领]⑦ 登记/认领    POST /api/echoes/claim/register · /claim/login
```

## 三、接口逐条（联调核对表）

| # | 方法 | 路径 | 关键入参 | 返回要点 |
|---|---|---|---|---|
| 1 | POST | `/api/echoes/login` | `code`（wx.login 给的临时码）· `force_stub`（联调=true，正式不传）· `nick_name` | `data.user_id` / `is_new_user` / `profile.ui_mode` / `owners[]` / `count_stories` |
| 2 | GET | `/api/echoes/login/profile` | `user_id` | `ui_mode` / `has_phone` / `phone_masked` |
| 3 | POST | `/api/echoes/login/ui_mode` | `user_id` · `ui_mode`（`standard`/`large`，兼容「大字版」「senior」） | `ok`，profile 持久 |
| 4 | POST | `/api/echoes/clip/text` | `story_id` · `actor_id` · `text` · `caption?` | `data.clip_id` / `sort_order` |
| 5 | POST | `/api/echoes/clip/photo` | `story_id` · `actor_id` · `media_url` · `file_name` · `file_size` · `mime` | 同上 |
| 6 | POST | `/api/echoes/clip/audio` | 同上 + `duration` · `audio_path?` · `do_transcribe?` | 同上；**转写失败不阻断**（原声照存） |
| 7 | POST | `/api/echoes/clip/original` | 同 photo 口径 | 原声，不转写 |
| 8 | POST | `/api/echoes/clip/video` | 同上 + `cover_url?` | 同上 |
| 9 | GET | `/api/echoes/clip/list` | `story_id` · `viewer_id` | `data.clips[]`（按 `sort_order` 升序） |
| 10 | POST | `/api/echoes/claim/register` | `owner_id` · `phone?` · `display_name?` · `story_id?` | 登记一条待认领（幂等） |
| 11 | POST | `/api/echoes/claim/login` | `user_id` · `phone` | `data.owners[]` / `count_stories`（认领后归属） |
| 12 | GET | `/api/echoes/claim/mentioned` | `user_id` | `data.count` / `data.stories[]` |

**信封统一口径**：`{"ok": true, "data": {...}, "message": "..."}` / 失败 `{"ok": false, "code": "...", "message": "中文话"}`。
`code` 是给程序判断的，`message` 是可直接显示给老人的中文。

## 四、⚠️ 09-30 抓出并修掉的真 bug（联调前必须知道）

**现象**：亲属用手机号被登记 → 登录 → `claim/login` 返回**认领成功、owners 非空** → 但**取筐一件素材都看不到**。

**根因**：`register_claim()` 只写了 `Claim` 表，**没有同步建 `Member` 表**。
登录时 `auto_claim_on_login()` 把 Claim 标成 CLAIMED，但 `can_view_story()`
查的是 `Member` 表 → 查不到 → 判定「无权限」。

**影响面**：整个「手机号登记 → 亲属登录自动认领 → 看故事」这条链路**断的**。
这是第1期四条任务线里 **A 线（数据底座）+ 待认领** 的缝合处，
**按模块测测不出来**（claim 44/44、perm 20/20 各自都过）。

**修法**（`backend/claim.py` `auto_claim_on_login` 第 3 步）：
认领 Claim 时，若该 owner + 该手机号下没有 Member，就**补建一条**
（`story_id` 取自 Claim：有则 `granted_via=STORY` 只看那一篇；无则 `granted_via=FAMILY` 记整本）。

**验证**：`selftest_e2e.py` ⑥4 由 ❌ 转 ✅；五套旧自测回归全绿；**六套合计 206/206**。
