**出件：2026-10-12 ｜ 出件人：小鲸鱼（云端）｜ 依据：《需求书 v3.0》§八之二 + §1.2 公开/私有闸门**

> 08 页原型图「拿给别人看」的前端要真落地，必须先有这层接口。今日补齐。

---

## 一、一句话口径

**分享只管公开素材。** sandy 原话：「我分享出去，证明它已经不是私有了」。
一条素材能不能被分享，**不另定规则**——它从 §1.2「公开」定义里自动长出来：
**visibility == PUBLIC 才能进分享通道。** 私有素材、全私有的篇，一律 `not_shareable`。

## 二、接口清单（3 条）

| # | 方法 | 路径 | 登录 | 作用 |
|---|---|---|---|---|
| S1 | POST | `/api/echoes/share/make` | **要** | 造一条分享（故事/整本/小程序本身） |
| S2 | GET | `/api/echoes/share/view` | **不要** | 读一条被分享的内容（先看不登录） |
| S3 | GET | `/api/echoes/share/card` | 要 | 出「好看的卡片图」所需数据 |

> 后端实现：`backend/share_api.py`（v1.0）｜自测：`backend/selftest_share_api.py`（**29/29 全绿**）

## 三、S1 造分享 `POST /api/echoes/share/make`

请求体：
```json
{ "actor_id": "u_laoli", "kind": "story", "target_id": "story_xxx" }
```

| kind | target_id 传什么 | 说明 |
|---|---|---|
| `story` | 故事 id | §8之二.5 情况①「有故事，分享故事给你看」 |
| `book` | 老板（owner）user_id | §8之二.3.1 分享整本书 |
| `app` | 忽略 | §8之二.6 情况②「没故事，觉得好玩」——分的是产品本身 |

成功返回（story 例）：
```json
{ "ok": true, "data": {
    "story_id": "story_xxx",
    "share_token": "s_3f9c1a...",          // 无登录读这条的钥匙
    "path": "pages/shared/story?t=s_3f9c1a...",  // 小程序落地路径（前端拼转发卡片）
    "kind": "story",
    "public_clip_count": 1
} }
```

失败：
```json
{ "ok": false, "error": "这篇还没有公开的内容，先公开一段再分享", "code": "not_shareable" }
```

**铁律落地**：`can_share_story(story_id)` 判据 = **该篇至少有一条 visibility==PUBLIC 的素材**。
全私有的篇 → 不造 token、不给分享。`app` 类型无此判据（分的是产品，不是内容）。

## 四、S2 读分享 `GET /api/echoes/share/view?t=<share_token>`（★ 无登录）

成功（story 例）：
```json
{ "ok": true, "data": {
    "story_id": "story_xxx",
    "title": "1979年那场大水",
    "time_raw": "1979年",
    "clip_count": 1,
    "clips": [{
        "clip_id": "clip_xxx",
        "type": "text",
        "text": "水退了以后大家互相帮衬",
        "transcript": "",
        "media_url": "",
        "provider_id": "u_laoli",
        "source_type": "origin",
        "ref_author_name": ""
    }],
    "owner_display_name": "李桂芳",
    "can_join": true
} }
```

**★ 最硬的一条**：`clips` **只回公开素材**。私有素材连被提及者都不给看（§1.2 铁律3），
这里**无登录**更不可能给。若这篇分享后被作者改成全私有 → 返回 `share_gone`，**一个字都不泄**。

token 前缀决定读法：
- `s_` → 读一篇故事（`view_shared_story`）
- `b_` → 读整本书（`view_shared_book`，只列**有公开内容的**篇）

「篇末那句」由**前端**按场景拼：`这是<owner_display_name>的故事，里面提到了你 [我也加进来]`
（§8之二.5）。点【我也加进来】→ 微信一键登录 → **默认加入"这一篇"**。

## 五、S3 卡片图数据 `GET /api/echoes/share/card?kind=story&target_id=...`

给前端出「好看的卡片图」用（§8之二.3.1 方式 B）。kind = `story` / `book` / `app`。
返回 headline/eyebrow/excerpt 等文案字段，前端套模板渲图。全私有的目标 → `not_shareable`。

## 六、连带修的一处 v3.0 泄密口（claim.py）

**v3.0 §2.4 改 / §8之二.7 改**：`"待认领"只认公开篇里提到的人`；私有库里提到的人
**不登记、不提醒、不给看**（否则=泄密）。此前 `claim.py` 是 v2.4 语义（不论公私都算），
**今日补上公开闸门**：

| 函数 | 改动 |
|---|---|
| `claim._mentioned_story_ids` | 命中的故事**再过一道公开闸门**：只留「有公开素材」的篇 |
| `claim.register_claim` | 给「只有私有素材的篇」登记被提到的人 → **raise PermissionError** |

> 空篇（还没任何素材）登记**放行**（新建故事先登记人的正常流程），由读取闸门兜底。

**自测**：`selftest_claim.py` 44→**47/47**（+3 条 v3.0 私有闸门断言）；
`selftest_login.py` 37→**38/38**（+1 条）。全量回归 **13 套 417/417 全绿**。

## 七、留给前端（小龙虾）的落地清单

1. 08 页「拿给别人看」：调 **S1** 拿 `path` → 拼微信转发卡片。
2. 落地页 `pages/shared/story`：调 **S2** 渲染（**先看，不用登录**）。
3. 篇末按钮【我也加进来】→ 登录 → `POST /api/echoes/story/...`（加为这一篇的故事成员）。
4. 大字版入口按钮文案＝**「拿给别人看」**（不是"分享"，§8之二.3.1）。
5. 卡片图（方式 B）：调 **S3** 拿文案 → 套模板。
6. 本机 `uvicorn` 实测 3 条新路由（云端无 fastapi，形状已冻结）。
