## 一、统一信封（与其他接口同形，前端一套解析）

```json
{ "ok": true,  "data": { ... } }
{ "ok": false, "error": "你没有权限改这段的时间", "code": "forbidden", "data": {} }
```

**错误码**：`bad_request`（缺参/参数不合法） / `not_found`（故事不存在） / `forbidden`（越权）。

## 二、四个端点

### 2.1 取整本时间轴 — `GET /api/echoes/timeline`

**Query**

| 参数 | 必填 | 说明 |
|---|---|---|
| `owner_id` | ✅ | 书的主人（讲述人）——权限判定的根 |
| `viewer_id` | ⭕ | 谁在看（默认＝owner_id）。家人看整本；故事成员只看命中那篇；外人空轴 |

**Response `data`**

```json
{
  "owner_id": "openid_laoren",
  "nodes": [
    {
      "node_id": "n1968",
      "time_sort_key": 1968,
      "label": "1968年",
      "count": 1,
      "stories": [ { ...story_card... } ]
    },
    {
      "node_id": "n1979",
      "time_sort_key": 1979,
      "label": "1979年",
      "count": 2,
      "stories": [ { ...story_card... }, { ...story_card... } ]
    }
  ],
  "pending": [ { ...story_card... } ],
  "stats": { "total": 4, "placed": 3, "pending": 1, "node_count": 2 }
}
```

- `nodes` **已按时间正序排好**（前端顺序渲染即可，不用再排）。
- `nodes[].count` ＝ 该时间点下的故事数（**同一时间点允许多个故事**，v2.4 §5之二.2）。
- `pending` ＝ 【时间待定】区，**永远排在最后、不参与排序、不猜**（v2.4 §5.4 保命线）。前端把它渲染成底部一个灰点问号节（见你预案 §1.2/§1.3）。
- 外人无权限 → `nodes=[] / pending=[] / stats.total=0`，**不报错**（不泄露「存在但你没权限」）。

**`story_card`（每条故事的时间卡）**

```json
{
  "story_id": "story_xxx",
  "title": "分到第一套房",
  "summary": "一句话摘要",
  "time_raw": "七几年那场大水",
  "time_label": "1970年代（老人说的）",
  "time_precision": "fuzzy",
  "time_sort_key": 1970,
  "time_extract_method": "模糊年代",
  "time_confirmed_by_user": false,
  "is_anchor": false
}
```

| 字段 | 用途 | 前端怎么用 |
|---|---|---|
| `time_label` | **展示文案（唯一该显示的）** | 直接显示。模糊的带「（老人说的）」，**后端保原样，绝不凑整** |
| `time_precision` | `year/season/month/day/fuzzy/unknown` | 决定要不要显示更细的样式（你预案 §1.3 精度分级）；**不参与排序** |
| `time_sort_key` | 排序键（year，int） | **不用前端算**；同节的卡属于同一时间点 |
| `time_confirmed_by_user` | 用户手改过 | 用于节点文案优先取「被确认过」的那条（后端已处理）；前端可加个小标记 |
| `is_anchor` | 是否人生锚点（出生/上学/结婚/生娃/退休） | 显示「锚」角标（v2.4 §5.3） |

**同义端点**：`GET /api/echoes/timeline/grouped`（同体，兼容你旧的 grouped 命名，用哪个都行）。

### 2.2 只取【时间待定】区 — `GET /api/echoes/timeline/pending`

**Query**：`owner_id`（必填）、`viewer_id`（可）。

**Response**：`{ "ok": true, "data": { "owner_id": "...", "pending": [...], "count": 1 } }`

### 2.3 ★「改时间」— `POST /api/echoes/timeline/set_time`

你预案 §2 的「改时间弹层」提交落这里（v2.4 §5.5）。

**Body**

```json
{
  "story_id": "story_xxx",          // 要改的那条
  "actor_id": "openid_erzi",        // 谁改的（须为主人或已认领家人）
  "new_time_text": "1980年5月",     // 用户说的话 / 手输，如「八十年代」「文革那会儿」
  "anchors": { "birth_year": 1950 },// 可选：已知锚点，供「我八岁那年」反推
  "force_raw": ""                   // 可选：只留原话不解析时填（落待定但保留原话）
}
```

**Response**

```json
{
  "ok": true,
  "data": {
    "story_id": "story_xxx",
    "placed": true,                 // ★ 是否成功归位（false＝进了「时间待定」，前端据此提示）
    "time": { ...story_card时间四件套... },
    "node_hint": "1980年5月",        // 可直接播报/显示「挪到 1980年5月 了」
    "evidence": "1980年5月",         // 命中的原文片段（可空）
    "confidence": 0.95
  }
}
```

**行为（照 v2.4 §5.5 逐条）**：
1. 解析 `new_time_text`（**复用后端 timeline.py 的 extract_time，前端不用做解析**）
2. 落库并 **置 `time_confirmed_by_user = True`** → **此后任何自动归位都不得再覆盖**（用户说一不二）
3. 解析不出年份 → `placed=false`，**保留原话、进「时间待定」、不瞎猜**（前端照你说的话回读：「这段先放『时间待定』，等您再想想」）
4. 越权（故事成员想改）→ `forbidden`；故事不存在 → `not_found`；空时间 → `bad_request`

### 2.4 自动归位（保存即触发，可选）— `POST /api/echoes/timeline/auto_place?story_id=xxx`

老人/家人新录一段后调一次，后端自动抽时间归位（v2.4 铁律 5：保存即触发排序调整）。

- **用户手改过的会自动跳过**（`skipped=true`），绝不覆盖。
- 锚点反推：后端会先把**同一本书**里已确认的锚点抽出来，再解析（让「我八岁那年」能落地）。
- 前端可**先不接**这条（第1期采集时后台调即可），不卡你。

## 三、四条铁律（前端必须依赖后端、不要自己绕）

| # | 铁律 | 谁负责 |
|---|---|---|
| 1 | **排序只在后端** | 前端拿 `nodes` 顺序渲染。**别在前端按字符串/字典序重排**（会打乱精度不影响排序的规则） |
| 2 | **时间文案只显示 `time_label`** | 前端**别自己把「1970年代（老人说的）」加工成「1975年3月」**（v2.4 §5.5 第3条） |
| 3 | **【时间待定】必须单列** | 用 `pending` 渲染到底部灰点，**别塞进 nodes 参与排序**（§5.4 保命线） |
| 4 | **改过的不许被覆盖** | 前端只管提交 `set_time`；覆盖判断在后端（`time_confirmed_by_user`），你不用管 |

## 四、联调顺序（你接前端时照这个点）

1. `GET /api/echoes/timeline?owner_id=X` → 看 `nodes` 是否按正序、1979 节是否挂 2 张卡
2. 造一条说「七几年」的故事 → 看它落到 nodes（`time_precision=fuzzy`、label 带「（老人说的）」）、不是 pending
3. 造一条没有任何年份的故事 → 看它进 `pending`
4. `POST set_time` 把某条改成「1980年5月」→ 再取 timeline，看它挪到 1980 节、`time_confirmed_by_user=true`
5. 再对同一条调 `auto_place` → 看 `skipped=true`（**证明手改不会被覆盖**）
