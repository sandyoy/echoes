## 二、三个接口（形状已冻结，请照此接）

### 1. 登录（唯一入口，进小程序第一件事）

```
POST /api/echoes/login
```

请求体：
```json
{
  "code": "wx.login 拿到的临时 code",
  "nick_name": "老李",        // 可选
  "avatar_url": "http://...",  // 可选
  "phone": "13700137000",      // 可选：带手机号 → 登录即自动认领
  "force_stub": false          // 联调时可传 true（见下）
}
```

返回：
```json
{
  "ok": true,
  "data": {
    "user_id": "oX...（openid，后续所有接口都用它）",
    "is_new_user": true,
    "profile": {
      "user_id": "...", "nick_name": "老李", "avatar_url": "...",
      "ui_mode": "standard",      // standard / large —— 决定你渲染标准版还是大字版
      "has_phone": false, "phone_masked": ""
    },
    "owners": ["书主的 openid"],   // 我能看的书（自动认领后）
    "count_stories": 0,            // 「有 N 篇提到了你」（被提到的篇数）
    "mentioned_count": 0,          // 同口径，历史字段，保留
    "session_from": "stub"         // stub = 走的桩；wechat = 真调微信
  }
}
```

> **前端只需要调这一个接口**：我是谁 + 我有哪些书 + 有几篇提到了我，一次拿齐。
> 「确认登录」「首次引导」等页面按 `is_new_user` 决定怎么显示。

### 2. 读资料（切页/冷启动拉状态）

```
GET /api/echoes/login/profile?user_id=<openid>
```
返回 `{ok, data: {user_id, nick_name, avatar_url, ui_mode, has_phone, phone_masked}}`

### 3. 双界面切换（标准版 ⇄ 大字版，v2.4 第9条）

```
POST /api/echoes/login/ui_mode
{ "user_id": "...", "ui_mode": "large" }
```
- 收 `standard` / `large`，**同时兼容** `senior` / `big` / `大字版` 等别名（统一归一化）。
- `ui_mode` 是 **User 级持久设置**：切一次，下次进来 profile 就是 large，前端不用自己存。

## 三、⚠️ 关于 `force_stub`（联调必读）

本机**没有微信 appid/secret**（凭证不入仓库），所以真调微信走不通。
- 生产：不传 `force_stub`。若服务器配了凭证（`~/.config/yuanekang/wechat_mp.json` 或环境变量 `WECHAT_MP_APPID`/`WECHAT_MP_SECRET`），自动走真 `code2session`。
- 联调/自测：传 `"force_stub": true`，用 code 稳定算出一个伪 openid（同 code 同 id，可重复跑）。
- 返回值里 `session_from` 会明确告诉你走的哪条路，**不会静默假装成功**。

> 需要真机跑通登录前，**得有一个微信小程序的 appid/secret**（小程序后台能拿到，不花钱、不用认证企业）；
> 这件事属 sandy 侧的一个小动作，我在汇报里提了，不占用你的时间。

## 五、本日同时修的一个真 bug（与登录态相关，已修）

`claim_everything_for()` 在**没传手机号**时，把 `owners` / `count_stories` 直接置空
→ 未绑手机的微信用户（最常见的情况）首页「有 N 篇提到了你」**静默显示 0**。
已修：无手机号时也按已有成员关系算 owners，并按被提及篇数算 count_stories。
`selftest_login.py` E4 用例专门盯这个（实跑通过）。
