## 0. 为什么补这一节（不是新增功能，是补断头）

`share_api.make_card_data()` 此前只产**数据**（headline / excerpt / 出处 / episode_label），
前端拿到它还得自己画 —— 而**"谁来画"全项目没人负责**：
没有任何一处代码能产出一张图片。§3.3.1 把「做成一张图」写成**明案**（老人直接发出去，
像小年糕那种），§8之二.3.1 也把"分享卡"列为对外形态之一。

今日补上：后端直接出 **PNG 字节**。前端拿到即可 `wx.saveImageToPhotosAlbum` / 转发，
不需要在小程序里再实现一套 canvas 排版。

## 1. 两条路由（分工不同，别混用）

### 1.1 `GET /api/echoes/card/render` → 直接回 PNG 二进制

| 参数 | 必填 | 说明 |
|---|---|---|
| `kind` | ✅ | `story`（一篇）/ `book`（整本书） |
| `target_id` | ✅(story) | `kind=story` 传**故事 id**；`kind=book` 传**书主人 owner_id**（缺省=本人） |
| `actor_id` | ✅ | 当前登录用户 user_id（登录态口径同其余接口） |

**成功**：HTTP 200，`Content-Type: image/png`，`Cache-Control: no-store`，body ＝ PNG 文件字节（宽 750px）。
**失败**：回 JSON 信封（不是图片）：

| code | HTTP 语义 | 何时 |
|---|---|---|
| `not_shareable` | 403 | 该篇**一条公开素材都没有**（全私有）——绝不出一张含私有内容的图 |
| `not_found` | 404 | 故事/书不存在 |
| `bad_kind` | 400 | kind 不是 story/book |
| `render_unavailable` | 503 | 本机找不到中文字体（**明确报错，不静默出豆腐块**） |
| `missing_actor` | 400 | 缺 actor_id |

**前端接法**：`wx.downloadFile` 或 `wx.request({responseType:'arraybuffer'})` → 存临时文件 → 转发。
**判断要点**：先看 `Content-Type`：是 `image/png` 就是图；是 `application/json` 就读 `code`。

### 1.2 `POST /api/echoes/card/preview` → 只量不出图

请求体：
```json
{ "actor_id": "u_xxx", "kind": "story", "target_id": "s_xxx" }
```
返回：
```json
{ "ok": true, "code": "ok", "data": {
    "width": 750, "height": 1004, "bytes": 48325,
    "overflow": false, "bottom_padding": 48,
    "headline": "嫁过来第二年", "episode_label": "1976年",
    "owner_label": "李桂芳", "excerpt": "我嫁过来第二年，村里头通了电……"
}, "message": "" }
```
用途：①前端先排版（决定预览容器比例）②**自测用它做"不信 ok=True、量像素"的自证**
（`overflow=false` 且有 `bottom_padding` 才算真画对，不看眼睛）。

## 3. 明确未做（边界，别问）

1. **不画真二维码** —— 要小程序码，属微信后台/小龙虾域。现在图上只有小程序名，**没有假码假链接**。
2. **不做字体下载/打包** —— 本机有 Noto/文泉驿用本机的；真机上最终以**前端 canvas 出图**为准（手机端字体更好看）。
   故这条路由定位是：**后端可独立验证 + 服务端生成（分享落地页/打印/运营素材）**，不是要替代小程序 canvas。
3. **不做竖排/艺术字/多模板** —— 先保证"一张能拿得出手的图"，模板化等 sandy 看图后再定。
4. **路由云端仍未实测**（本机无 fastapi；形状已冻结、编译通过，已请小龙虾本机 uvicorn 打一遍）。
