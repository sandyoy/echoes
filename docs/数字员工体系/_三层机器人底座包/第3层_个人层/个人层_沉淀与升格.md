# 第3层 · 个人层（怎么沉淀、怎么升格）

> **这一层是什么**：个人怎么用自己的机器人攒经验，以及**经验怎么往上长**。
> **注意**：个人层的"规则"现在**不建、留位**；但**个人层的"积累"现在就建**——
> 同事每天用机器人干活，干了什么自动进 `积累/个人/<userid>/`。
> 版本：v1.0（2026-10-07）

---

## 块 1 · 个人层的形态（定死：共用一个号，按人分记忆）

- **一个"销售助理"机器人号，全销售部共用**，不一人开一个号
- 谁找它，它认谁；**记忆按人分开存**——张三的偏好李四看不见
- 好处：成本低、扩人不用重开号
- **代价（技术必做）**：企业微信必须把**"发送人身份（userid）"透传**，机器人才能"认人"
  - ⚠️ **没有 userid 透传，私聊就退化成"一个人"**，所有人都共用一份记忆 = 数据泄露

---

## 块 2 · 两个入口，各干各的活（两个都要，不是二选一）

| | 私聊（"销售助理"号） | 部门群 |
|---|---|---|
| **定位** | 各人自己干活 | 部门公用 |
| **典型动作** | 跑私活、出自己的文档、查口径 | 对齐口径、共享模板、新人照抄 |
| **对应记忆层** | **个人层**（入口） | **部门层**（入口） |
| **谁看得见** | 只有本人 | 全组 |

**关键逻辑（两个都要的根本原因）**：
> 私聊是**"个人经验往上长"的入口**。只有私聊里的东西攒够了，才有东西可以提成部门层。
> 如果只有群，经验永远停在群消息里，沉不下来，也升不上去。

---

## 块 3 · 经验怎么长（三层 + 升格机制）

```
公司层  共用口径   —— 全公司一致，不许各自猜
   ↑  升格：部门层反复验证的方法，经负责人确认后上提
部门层  销售部套路 —— 本部门通用打法（报价怎么算、话术怎么应对）
   ↑  升格：个人层反复用的套路，机器人主动提议上提
个人层  各人偏好   —— 个人习惯（说话风格、常用模板、关注重点）
   ↑
积累/个人/<userid>/   —— 每天干活自动落盘（可写区）
```

**升格机制（这是"经验沉淀"的落地动作）**：

> 机器人发现某人**反复用同一个套路**（比如张三连续三单都用同一套报价逻辑）→
> 机器人**主动提议**："这套打法要不要提成销售部通用方法？" →
> sandy/部门负责人点头 → 写进部门层，全组受益。

**同事只管正常干活**，"哪些值得沉淀、怎么封装、放哪"**由机器人自己判断和提议**，不靠员工自觉上交。

---

## 块 4 · 为什么个人层的"规则"现在不建

**留位不建。** 理由：
- 部门机器人还没跑起来，**现在不知道这个人需要什么**
- 个人层的规则最容易变成"每个人一套"——**十个人十套，就没法管了**
- 个人特性应该**从积累里长出来**，不是一开始写死。跑两个月后，由本人提出"这个机器人知道我的习惯"，**那时再固化成个人规则**

**但要建的是**：`积累/个人/<userid>/` 现在就开——**人干过的活得先存下来，才有得沉淀。**

---

## 块 5 · 个人层权限（和公司/部门层一致的原则）

| 部分 | 机器人权限 |
|---|---|
| 个人**规则**（暂空，留位） | **只读** |
| 个人**积累**（`积累/个人/<userid>/`） | **可写** |
| **其它人的个人积累** | **完全不可见**（不是只读，是看不见） |

**隔离硬要求**：张三的进程**读不到**李四的 `积累/个人/<李四id>/`。
如果所有人对话存一个库里，"张三问产假怎么算"的答案可能引到李四的上下文 → **这是数据泄露**。

---

## 块 6 · 记忆纪律（三层通用，重复强调）

```
1. 不落盘 = 没干过：任何台账、结论、做过的活必须写进"积累"目录。
2. 重启后先读"积累"：恢复上下文再干活。
3. 半截的活不许当成品交：从上一个完整节点接着干，或本轮作废重来。
```
