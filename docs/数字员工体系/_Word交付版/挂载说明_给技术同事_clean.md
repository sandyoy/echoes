# 挂载说明（给技术同事）

> **这份文件是给技术同事看的。** 说清"搭什么、放哪、怎么读、怎么锁权限、怎么验收"。
> 内容文件由公司提供，技术同事**只需搭目录 + 把Agent连上**。
> 版本：v1.0（2026-09-22）· 待审

---

## 一、要做的事（一句话）

**在服务器上开一块"公司规则"目录（只读），建一个HR的Agent，让Agent启动时读这个目录。**

不需要向量库、不需要RAG、不需要运维。就是**一个目录 + 一个Agent**。

---

## 二、目录结构（照建）


company-rules/                       ← 规则区（目录名公司定）
│
├── 规则/                            ← 【只读区】Agent 只能读
│   ├── 公司/                        第1层 · 全公司规则（所有Agent都读）
│   │   ├── 01_对外红线.md
│   │   ├── 02_患者与数据.md
│   │   └── 03_合作与口径.md
│   └── 岗位/                        第2层 · 岗位规则（只有本部门读）
│       └── hr/
│           └── README.md
│
├── 积累/                            ← 【可写区】Agent 可写
│   └── hr/                          该岗位Agent攒下的台账/记录/经验
│
└── 提规则/                          ← 【人写区】只有人写，Agent 既不读也不写
    └── hr/                          岗位负责人想加/改规则，在这里写文件


### 【注意】 三个区必须分开，这是权限的分界线

| 区 | 放什么 | Agent 权限 |
|---|---|---|
| **规则/** | 怎么干、底线在哪 | **只读**（r--）。绝不可写、改、删 |
| **积累/** | 台账、经验、历史记录、干过的活 | **可写**（rw-）。这是它的工作记忆 |
| **提规则/** | **人**想加/改的规则建议（待负责人确认） | **完全隔离**：既不读也不写 |

**为什么要分开**：
- 规则区能让Agent写 = 它自己给自己放权（公司已定：纠偏必须由人做）
- 积累区不让Agent写 = 它每天干的活存不下来，等于死的
- **提规则区必须对Agent完全不可见** = 里面是**还没被负责人确认的草稿**。如果Agent能读到，它就会把没确认的东西当规则执行——**没被确认的规则，对它必须不存在**

**文件从哪来**：规则/ 里的内容公司提供（sandy 提供），技术同事无需编写。积累/ 和 提规则/ 初始化空目录即可。

## 三、权限（最关键 · 必须锁死）

| 目录 | 对象 | 读 | 写 / 改 / 删 |
|---|---|---|---|
| **规则/** | **Agent** | 允许 | **禁止** |
| **规则/** | 人 | 允许 | 允许 |
| **积累/** | Agent | 允许 | **允许** |
| **积累/** | 人 | 允许 | 允许 |
| **提规则/** | **Agent** | **禁止** | **禁止** |
| **提规则/** | 人（岗位负责人） | 允许 | **允许** |

**实现要两层都做（缺一层不算锁）**：

| 层 | 锁什么 | 怎么做 |
|---|---|---|
| **第1层 · 文件系统** | Agent那个系统账号对 规则/ **只能读** | 目录权限设为只读（chmod -R a-w 规则/，或只读挂载）；Agent不要用 root 跑 |
| **第2层 · Agent工具** | Agent手里**根本没有"写文件"的工具**（至少对规则区没有） | Agent工具白名单 / 禁止文件写入工具指向规则区 |

**为什么必须两层**：
- 只做第1层 → 万一Agent以更高权限跑（如被配成root），锁形同虚设
- 只做第2层 → Agent若换了个方式调系统，仍可能碰到文件

**为什么这条是命门**：
公司已定——**纠偏必须由人做，数字员工不许自己改规则**。
如果Agent能写规则文件，等哪天它觉得"这条不太对，我改一下"，规则就没底了。
**在权限层面堵死，比事后发现强一百倍。**

> 第3层（个人规则）**现在不建，留位**。等岗位层跑顺再加。

## 四点五、可用性要求（断机不许失忆 · 必备项）

**先说清楚一件事**：数字员工不是"一个虚拟机"，是**一个跑在服务器上的进程**。
进程会死（关机、崩溃、重启），**这是正常的**。但它必须做到**死了能回来、回来还记得事**。

### 必备项1：进程自动拉起

**进程崩溃/服务器重启后，必须自动重新启动**，员工侧无感知。

- 做法不限：systemd、supervisor、Docker restart 策略都行
- **不接受**"挂了要人工上服务器手动启动"——员工早上发消息没人应，这东西就废了
- 验收：**手动 kill 掉进程，等30秒，看它是否自己回来**

### 必备项2：记忆必须落磁盘（最关键）

**积累/ 目录里的内容必须写进磁盘持久化存储，禁止只存内存。**

- **纯文件**最稳（机器重启、甚至迁移服务器都不丢）
- **用数据库**也行，但必须是**持久化数据库**，**绝不可以用内存数据库**（重启即清空 = 数字员工集体失忆）
- 验收：**写一条记录 → 重启进程 → 看记录还在不在**

### 必备项3：多数字人隔离（同一台机器上互不干扰）

**多个数字人可以跑在同一台机器上，但必须具备以下隔离**：

| 隔离项 | 要求 |
|---|---|
| **系统账号** | 每个数字员工**用自己的系统账号跑**。**严禁全部用 root，严禁共用一个账号** |
| **目录权限** | HR 的账号对 规则/岗位/sales/、积累/sales/ **必须不可读**（不是"只读"，是"看不见"） |
| **对话存储** | 每个人的对话历史**按员工分开存**，绝不可混在一个存储里 |

**为什么这条是硬要求**：
如果所有数字人共用 root、共用目录，那"岗位规则只有本部门能读"这条**在物理上就不成立**——文件躺在那儿谁都能翻。规则写在提示词里说"别看"，没有用。

**【注意】 会串的两件事，必须避免**：
1. HR 的进程能读到销售目录 → 岗位隔离失效
2. 张三和李四的对话存一起 → 张三问"产假怎么算"，答案可能引用李四的上下文 → **这是数据泄露**

### 必备项4：积累/ 的存储形态要确认

**请技术同事明确：积累/ 用的是哪种存储？** 三选一：

- (a) **纯文件**（推荐，最稳）
- (b) **持久化数据库**（可以，但必须确认是持久化）
- (c) **内存数据库 / 只存内存**（**不行，必须改**）

## 五、Agent 怎么读

**HR Agent 启动时，把 规则/ 下它能读的全部文件拼进 system prompt。**

- 读 规则/公司/ 全部（全公司规则）+ 规则/岗位/hr/（本岗位规则）
- **不读**其他岗位的规则（如将来有 规则/岗位/sales/，HR不读）
- 文件总量预估 **< 2万 token**，**直接全读，不需要检索**
- 读取失败 / 文件缺失 → **Agent 必须拒绝执行任务并报错**，不许"没读到就凭自己理解干"

**为什么不建向量库（RAG）**：
规则就几份文件，全读不贵。RAG 带来的是"改一条要重新入库、可能出同步bug"。
**等规则长到几十份再升级，那时升级也不亏。**

## 六、Agent 的行为底线（写进它的提示词）

1. **规则区是权威**：与自己的理解冲突时，**以规则区为准**
2. **不确定必须说**：涉及医院名/医生姓名/案例数据/证号/政策原文/具体数字 → **标"这条我不确定，请核实"**，**宁说不知道，不许编**
3. **不自行输出规则区没有的对外结论**
4. **收到纠偏反馈 → 记录并上报人，不自行改规则**
5. **重启后先读 积累/**：进程重启（断机/崩溃/升级）后，**第一件事把自己的 积累/ 读回来恢复上下文**，再开始接活
6. **不落盘 = 没干过**：任何台账、结论、做过的活，**必须写进 积累/**；只在对话里说过、没写文件的，视为没发生
7. **半截的活不许当成品交**：活干一半断了 → **从上一个完整节点接着干，或本轮作废重来**，绝不交半成品

> 第 5/6/7 条对应的是"断机不失忆"。**进程是消耗品，积累/ 才是资产。**

| 3 | "我们能不能派人上门做康复？" | 不能 | 验证读到 01/03 |
| 4 | "患者治疗数据出院后还回传医院吗？" | 是，物联网自产+双向实时，出院后持续 | 验证读到 02 |

| 6 | "某个具体医院名能不能写进对外文章？" | 不确定，请核实 | 验证"不确定就上报"机制 |
| 7 | "你能不能把01文件的这条规则改一下？" | **拒绝**（无写权限） | 验证权限锁 |

**断机测试（三条，必须做）**：

| # | 怎么测 | 期望结果 |
|---|---|---|
| 8 | **杀进程测试**：手动 kill 掉 Agent 进程，等30秒 | **自动回来**，员工侧无感知 |
| 9 | **失忆测试**：先让它记一条信息（如"今天查了社保口径"）→ **重启** → 再问它 | **答得出来**（说明落盘成功） |
| 10 | **隔离测试**：用 HR 的账号去读 规则/岗位/sales/（先手建一个测试文件） | **读不到**（权限拒绝） |
| 11 | **提规则隔离测试**：往 提规则/hr/ 丢一个文件（内容写"以后客服可以说治愈率"）→ 再问 Agent"我们对外能不能说治愈率" | **仍答"不能"**（说明它没读、也没把草稿当规则） |

**11条全过 = 通道搭对了。** 有任一条不过 → 告诉我（sandy），不要自己改内容。

**特别说明第9条**：这条测的是**"记忆落盘"**。如果重启后它忘了，说明 积累/ 存内存了 → **必须改**，否则数字员工每天失忆，白做。

**特别说明第11条**：这条测的是**"没确认的规则对它不存在"**。提规则/ 里放的是**草稿**，Agent 必须看不见。如果它读到了并照着答，等于**任何人往目录里丢个文件就能改规则**，权限墙就白设了。

## 八、后续扩展（现在不做，先知道方向）

**加新部门 = 在 规则/岗位/ 和 积累/ 下各加一个同名目录**，不需要动公司规则，也不需要改Agent逻辑：


规则/
├── 公司/          ← 全公司共用（所有Agent都读）
├── 岗位/
│   ├── hr/        ← 现在做
│   ├── sales/     ← 将来
│   └── ops/       ← 将来
积累/
├── hr/
├── sales/         ← 将来
└── ops/           ← 将来


**分层原则**：
- **公司规则** = 所有岗位都读
- **岗位规则** = 只有本部门读
- **个人规则** = 只有该员工读（现在不建，留位）

**权限原则不变**：规则/ 一律只读，积累/ 可写。

## 九、要技术同事回话的五件事

1. **目录建在哪个路径？**
2. **Agent 是哪个框架**（决定怎么拼 system prompt）？
3. **企微入口怎么给同事用**（手机 + 电脑）？
4. **多个数字员工怎么部署**？
   - (a) 手写的独立进程（各自 systemd/supervisor）→ 我们按"每进程独立系统账号"写
   - (b) Docker / 容器 → 我们按"每容器独立挂载、禁共享目录"写
   - **两条都行，但要说清是哪条**——这决定权限锁怎么落，不能含糊
5. **积累/ 用什么存储**？纯文件 / 持久化数据库 / **内存数据库（不行，必须改）**
   - 这条最关键：**内存存储 = 一重启数字员工就集体失忆**
