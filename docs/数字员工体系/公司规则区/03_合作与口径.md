# 公司规则 · 03 合作与口径

> 适用：公司所有岗位，尤其销售、商务、运营、内容岗位。
> 权限：**只读**。数字员工不得修改。
> 版本：v1.0（2026-09-22 起草）· 待审

---

## 一、公司是什么（一句话站位）

**圆爱康不卖设备，做的是居家康复服务模式。**

- 角色：**第三方基础设施方**（家用器械 + 远程系统 + 医疗机构持证医师远程协同）
- 称谓：**"辅助方"**、**"第三方技术与服务提供方"**
- 医疗主体、收费主体：**始终在合作医疗机构**

---

## 二、绝不上门（不可谈判的边界）

**圆爱康绝不上门施治。**
- 上门须医疗持证人员，且=重资产，**公司不碰**
- 对外不得出现"上门"字样的服务描述

**正确描述**：患者在**合作医疗机构执业医师指导下**，于**家中使用医疗级设备**完成治疗性训练。

---

## 三、钱怎么走（收款支付）

### 3.1 铁律
- **患者收款方必须显示医院名**（曾因"第三方收款"被投诉伤信任）
- **主账号绝不用圆爱康**——微信收款名绑主体，一换就露馅是第三方

### 3.2 正解
**圆爱康做微信服务商、医院做特约商户，系统代医院自动原路退款。**

### 3.3 差额退款
要求"原路 + 快 + 24h系统自动"，但主账号（医院商户号）财务难随时退——**用上面的服务商方案解决，不靠人工。**

---

## 四、销售主推路径

**主推 A**：圆爱康收钱，再购医院服务。
**医院拒绝 → fallback B**：分账。

**对外只讲一条主路**（患者自费 + 医院服务 + 圆爱康基础设施）；**对内选项永不封死**。

---

## 五、支付通道优先级

```
1. 患者自费     ← 当前主路
2. 商业保险
3. 财政 / 社保
```

### ⚠️ 长护险 = **冻结状态**（2026-09-22定）

**不接长护险。**
**为什么**：绑社保 = 定点资格 / 服务目录 / 定价被管 / 须持证上门 → 撞"不上门施治"红线。

**但是**：判断可以软、留活口，**对外姿态必须硬**。
（政策在变、项目长相在变、渠道也在变——现在不适用≠以后不适用。）

---

## 六、投标与应标（分工红线）

**Agent只负责客观呈现，决策权永远在人。**

| Agent 该做 | Agent 绝对不做 |
|---|---|
| 用公司能力清单摆出：能覆盖哪些产品线、覆盖到几成、有哪些硬门槛（资质/注册证/垫资/现金流/硬性★条款） | 用"🟢最契合 / 🟡能投但重 / 🔴接不住"替人做"投不投"的决定 |

**基调 = 积极覆盖优先**：跟公司有关系的项目大范围覆盖去投；**只有硬门槛真过不去**才标记出来给人看。

**"门槛高" ≠ "不能投"**。门槛高是提醒人注意成本，不是替人拒绝。

**输出形式** = 每份的覆盖程度清单 → 交给人判断。

---

## 七、对外沟通的两个禁区

### 7.1 不主动提"数据资产"
（详见 02 患者与数据）改成"**数据反哺医院**"。

### 7.2 不提"医生入口医院化"是医生要求
**真相**：医生入口医院化是**管理层/IT要求**，不是医生要求。
**医生只求一件事：省事、好用。** 医生用我们的小程序，是因为它省事。

---

## 八、政府 / 政策相关

- **引用政策必须用原文**，一个字都不能编
- 政策判断三层问：①**能不能做** ②**该不该做** ③**钱从哪来**
- 任何政策都是"**暂时可能**"——现在不适用≠以后不适用，**留活口**

---

## 九、给医院写内容的语气（易错）

**绝不能写成"我院开展新项目/新服务"的通知腔。**

医院要的是【**科室成果 + 患者视角**】：
- 讲"我们做居家康复已经做得很顺、帮多少患者选择了居家、患者少跑腿轻松了"
- **主角 = 患者，不是项目**
- **语气 = 分享总结，不是通知**

---

## 十、内部备案 ≠ 对外材料

**内部可以记录的事，对外一个字都不能出现。**

例：具体医院名（如某市人民医院）的内部案例、暂停中的合作、未公开的商务谈判——**只进内部备案，绝不对外**。

**数字员工判断不了"这条是不是内部"时 → 默认不输出，标"请核实"。**
