## 二、B 版是什么样（先看效果再传）

打开 `preview_cases_B.html` 能看到传上去以后的长相。跟现在的 `cases.html` 比，只多了一块：

现在线上 `cases.html` 长这样（从上到下）：

```
① 合作医院案例（标题）
② 合作医疗机构 —— 18 家医院卡片（3 列）
③ 为什么同一套模式能在不同医院复用 —— 3 张卡
④ 如何开始合作 —— 3 个入口
```

B 版在 **③ 和 ④ 之间**插一块，变成：

```
① 合作医院案例（标题）
② 合作医疗机构 —— 18 家医院卡片（3 列）   ← 不动
③ 为什么同一套模式能在不同医院复用 —— 3 张卡   ← 不动
★ 四家医院，四种条件，四个答案         ← 新增（B 版）
★ 同一个模式，在哪一步不一样           ← 新增（B 版）
④ 如何开始合作 —— 3 个入口   ← 不动
```

新增那块的结构：

1. **四张卡**，一家医院一张，每张卡 4 行：
   - 医院名 + 地区/类型
   - **它要解决什么**（一句话）
   - **它怎么解决**（一句话）
   - **关键设计**（一句话）
2. **一张 4 列对照表**（手机端自动变卡片）：医院 / 动因 / 组织形态 / 关键设计
3. 表下一句免责：「以上内容整理自各医院公众号公开发布信息，不作为现时合作承诺。」

## 三、B 版为什么这么设计（给 sandy 看的判断，技术同事可跳过）

- 客户在官网上要的**不是"读论文"**，是**30 秒内看懂"这套东西在我这种医院能不能用"**。
- 所以不做长文，做 **"四家医院 × 四行"**——扫一眼就知道自己是哪一种。
- 长文（原来的 atlas 稿）不进官网，作为 AI 可读的留档材料另放，不上导航。
