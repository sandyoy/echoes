# 🔴 紧急：远程main被误删除文件，需要小龙虾本地push一次恢复

**触发时间**：2026-08-21 下午（14:48 cron daily-nudge-0821c8）
**原因**：云端主工作区 `git add -A` 把磁盘不存在但被git跟踪的文件（771个）误判为删除并推上去了 → 远程main从1090文件塌缩到319文件。
**根因**：云端是多分支不完整checkout，文件存在但不在磁盘上，`git add -A` 会全部标为删除（已知陷阱，见 tencent-cloud-github-access 技能）。

## 恢复方法（小龙虾本地机执行，一键fast-forward）

```bash
# 在任意有 ~/echoes 对象的机器，或直接在小龙虾本地克隆执行：
git fetch origin main
git push origin 75032cac1c99205236846a3f232a7595a877deee:main
# 备选SHA：95031e64d1f19b9053b351dfcb69a0fcf5c482fc（同内容）
```

**为什么是安全的fast-forward**：恢复提交75032ca 的父提交 = 当前坏提交8fc4396，树 = 健康1090文件树，无冲突，普通push即可让远程回到完整树。数据零丢失（所有blob都在远程对象库，坏提交的父可达）。

## 验证
```bash
git ls-remote origin refs/heads/main   # 应为75032ca
git ls-tree -r origin/main --name-only | wc -l   # 应为1090
```
