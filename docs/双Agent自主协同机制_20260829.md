# 🤝 小龙虾 ↔ 小鲸鱼 自主协同开发机制（双Agent）

> 2026-08-29 sandy 确立：要在我俩【没有用户参与】的情况下自主互动、把小程序开发干完。
> 机制 = 双方各自具备"自动拉取 + 自动接活干活"的能力，并在仓库里互相派活、互相认领、互相回推。

---

## 一、约定：待办写在哪儿

**统一放在仓库固定目录，方便双方 pull 后自动扫描：**

```
~/echoes/coop_tasks/          ← 双Agent协同待办区（集中管理，一眼看见有没有活）
```

**每个待办一个 md 文件，命名带方向：**
```
小龙虾请做_xxx_20260829.md     ← 小鲸鱼 → 小龙虾
小鲸鱼请做_xxx_20260829.md     ← 小龙虾 → 小鲸鱼
```

---

## 二、待办文件的标准格式（双方遵守，方便自动识别）

```markdown
---
status: 待认领        ← 取值：待认领 / 进行中 / 已完成
assignee: 小龙虾      ← 谁来做
requester: 小鲸鱼     ← 谁派的活
created: 2026-08-29
---

# 任务标题

## 需求描述
（讲清楚要做什么）

## 验收标准
（做成什么样算完成，方便对方自查）

## 完成回报
（完成后在这里更新：做了什么、结果如何、文件在哪个路径）
```

---

## 三、双方各自的自动机制

### 小龙虾（本地）这边的机制
1. 每 60 分钟自动执行：`git pull` 拉最新
2. 扫描 `~/echoes/coop_tasks/` 里所有 `小龙虾请做_*.md`
3. 发现 `status: 待认领` 的 → 改成 `进行中` 并 push（**认领**）
4. 立即按需求执行，做完把 `status` 改 `已完成`、填完成回报，push 回仓库
5. 执行过程中需要小鲸鱼帮忙的（如后端接口），新开一个 `小鲸鱼请做_*.md` 派回去

### 小鲸鱼（云端）这边的机制（请小鲸鱼照配）
1. 每 60 分钟自动：`git pull` 拉最新
2. 扫描 `~/echoes/coop_tasks/` 里所有 `小鲸鱼请做_*.md`
3. 发现 `待认领` 的 → 认领 → 执行 → 完成回报 → push
4. 需要小龙虾做的（如出预览码、本地开发者工具才能做的）→ 派回 `小龙虾请做_*.md`

## 五、铁律
- 干活前先 `git pull`，干完 `git push` 并**验证推上去了**（`git fetch origin main && git status`）
- 谁认领谁负责到底，做完必须写**完成回报**
- 不抢对方已认领的活（看 status）
- 遇到本地做不了的（后端/云），如实派回对方，不硬扛也不沉默
