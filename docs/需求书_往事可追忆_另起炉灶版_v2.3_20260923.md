## 〇、一句话讲清楚这东西是什么

**一个把老人一生的话、字、照片、视频、原声收集起来，自动按时间轴排好，一键变成一本书的产品。**

老人只管说。说的东西自己会找到自己的位置。

## 一、为什么另起炉灶

| 旧版 | 新版 |
|---|---|
| 只能记录文字 | 文字 + 照片 + 视频 + 原声 |
| 一条故事 = 一段文字 | 一条故事 = 一个素材筐（挂同一件事） |
| 以"老人"为账号主体 | **以"故事"为数据主体**（v2.1 重大修正） |
| 时间 = 用户手动填 | 时间 = 系统自动归位 + 可手调 |
| 无成书 | 先出电子书 → 可选印实体书 |
| 无收付款 | 后台可配置：免费 / 单本收费 / 年费 |
| 单一界面 | **标准版 / 大字版 双界面** |
| 静态页面 | 活文档，可续添 |

旧代码在数据模型根上就不同，修补等于重写，故整体作废。

## 二、数据主体模型（v2.1 核心修正）

### 2.1 主体 = 故事，不是人

**修正原因**：一个人一生有很多故事，每段故事的参与者都不同。以人为中心会导致权限越做越绕。

故事「1979年那场大水」
   ├─ 👤 讲述人：李桂芳（老人）
   ├─ 👤 记录者：小李（女儿）
   └─ 👤 参与者：老王（被提起的人）

### 2.2 两个"加号"，位置决定权限

| 加号位置 | 作用 | 可见范围 |
|---|---|---|
| **登录旁的加号** | 加**家人**（家庭通讯录） | 看**整本书**（全部故事） |
| **故事里的加号** | 加**这个故事的人** | 只看**这一篇** |

**铁律：权限由"从哪个入口加进来"决定，不设权限勾选框。** 老人不需要理解"权限"这个概念。

**补充规则**：
- 高权限覆盖低权限（家人即全本）
- 家人自动可见**后续新增**的故事
- 支持**移除**（可收回权限）

### 2.3 家人加入方式

- 用**手机号**录入即可
- 若对方已在小程序，可直接**选名字**加入
- 加入后**对方自己的账号**里出现入口

### 2.4 "有你的故事"入口（社交裂变种子）

被加入者登录后，首页出现提示：

> 「**李桂芳的故事里提到了你**」

- 可点进去看（按权限）
- 可**补充自己记得的版本**（*只要能看，就能补充*——看与写是同一个权限，不另设授权）
- 意义：老人把朋友写进书 → 朋友也来做自己的书 → **从"一人做书"变成"一群人在做书"**

【待验证】被加入者的通知方式（微信订阅消息 / 站内）需按体验与政策定。

## 三、双界面：标准版 / 大字版

### 3.1 命名

**用"大字版"，不用"老人版"**——按功能命名，不按人，避免标签感。老花眼的年轻人同样可用。

### 3.2 进入方式

打开小程序 → 默认标准版
   ↓
提供显眼入口【切换大字版】
   ↓
随时可切回（全局切换，不是注册时选一次）

### 3.3 两版差别

| | 标准版 | 大字版 |
|---|---|---|
| 字体 | 正常 | **特大** |
| 首页 | 故事列表 / 成书 / 全部功能 | **就一个大按钮：按住说话** |
| 功能 | 全部 | 只留核心，其余收起 |
| 加人 / 设置 | 正常 | 藏在"更多"里，不露出 |
| 配色 | 正常 | **高对比度** |
| 反馈 | 常规 | 点按**有声音反馈**（老人靠耳朵） |

**核心原则：大字版里凡出现"设置 / 权限 / 分享"字样，即为失败。**

### 3.4 实现方式

**同一套代码，两套样式——不是两套程序。**

- 两套程序 = 改一个功能要改两遍 = 长期必然走偏
- 代价：界面需按"可切换"重构，第1期工作量增加
- 【待验证】微信小程序**全局字号缩放**存在 rpx 限制，能否一键全局放大需实机验证；做不到时可能退化为"核心页面大字版"

## 五、时间轴（灵魂功能）

### 5.1 自动归位
- 用户**不按时间顺序说话**是常态：今天说1980年、下次说1937年
- 系统需从**语音内容**和**文字内容**中提取时间线索，自动归位
- **保存即触发**排序调整

### 5.2 提取算法（三类线索）

| 线索类型 | 例子 | 处理 |
|---|---|---|
| ① 显式年代 | "1937年""六十年代" | 直接识别 |
| ② 历史事件 | "文革""包产到户""闹饥荒" | 映射到年代区间 |
| ③ **人生锚点** | "我八岁那年""嫁过来第二年""老大刚会走" | 用已知年份反推 |

### 5.3 人生锚点表（让时间轴变准的核心）

出生年 → 上学年 → 工作年 → 结婚年 → 生老大 → 生老二 → 退休年

- 一旦采到（哪怕随口提到），后续所有"我八岁那年"类表述可**自动换算**
- **采访中应有意自然询问**（"您是哪年结的婚呀？"）——不是闲聊，是给时间轴打地基

### 5.4 保命线：不猜

**无法判定时标"时间待定"，不瞎猜、不归错位。**

归错比不归更糟——老人看到1949年的事被排到1980年，会觉得"这破东西不懂我"。

### 5.5 手动调整
- 可拖动调整顺序
- 支持**语音修正**："这事发生在1937年1月，那个是1937年8月"
- 系统据此再次调整

【待验证】方言、口语、模糊表述的识别准确率。**须拿真实老人语音样本实测，不得凭常识估算。**

## 五之二、时间与故事的关系（v2.2 核心修正）

### 5之二.1 时间是排序维度，故事是归属维度

**两者独立，互不冲突。**

| | 干什么 | 谁用 |
|---|---|---|
| **时间** | 决定**排在哪**（排序） | 时间轴 |
| **故事** | 决定**跟谁一组**（归属） | 内容 |

1980年1月 ────● 修水库（跟老王）
              ├─● 女儿出生
              │
1980年5月 ────● 分到第一套房
              │
1980年12月────● 买了第一台电视

**时间轴是目录，故事是章节。**

### 5之二.2 铁律

- **同一时间点允许多个故事**；同一年不同月份可以是完全不同的故事
- **一说年份 ≠ 归入某个故事**
- 时间精度分级：**年 / 季 / 月 / 模糊**（早年·年中·年末）
- **精度不同不影响排序**（粗的排粗位）→ 老人永远不用为排序去编具体日期

### 5之二.3 一段话含多个时间点怎么办

- 能明确切分 → 切成多个故事，时间各归各位
- 紧密关联（如"从水库赶回来"）→ **询问老人是否算一件事，不替他决定**
- 拿不准 → 切开，允许事后合并

### 5之二.4 归类原则：宁可分错，不可错并

| 错法 | 后果 | 可修性 |
|---|---|---|
| **分错**（本该一件，分成两件） | 老人说一句"这俩是一件事"→ 合并 | ✅ 小错，可修 |
| **错并**（两件事，并成一件） | 要拆开，老人可能都懒得说 | ❌ 大错，难修 |

**合并损失 > 分离损失。**

### 5之二.5 系统怎么判断"是不是同一件事"

第1步：抽时间（1980年）
第2步：抽主体（跟老王 / 女儿出生）→ 涉及谁
第3步：比对已有故事
       ├─ 拿不准 → 新建一件（宁可多，不可错并）
       └─ 相似度高 → 提供候选，**由人确认**

**后台关联度 = 助手，不是判官**：

| 后台干什么 | 举例 |
|---|---|
| 提供候选 | "这段话跟故事A相似度78%，是否归入？" |
| 找相同的人 | "老王出现在3个故事里，要合并吗？" |
| 找相近时间 | "1980年1月和3月，是同一年的事？" |
| **最终由人确认** | 老人/子女点一下才算数 |

**禁止全自动合并。** 全自动并一定出事——"1980年"这个相似度太容易碰巧撞上。

【待验证】"抽主体判断是否同一件事"涉及语义理解，难度**高于**时间提取，非规则可解。须小鲸鱼评估。

## 六、素材篮子（一条事，多种素材）

**铁律：所有素材挂在"同一件事"上展示。**

| 素材类型 | 来源 | 说明 |
|---|---|---|
| 文字 | 老人自己写 / 语音转文字 | 原声可保留 |
| 语音 | 按住说话 | **保留原生声音**，不只是转文字 |
| 照片/视频 | 老人手机图库 / 子女图库 / 故事里的人图库 | "+"号 → 跳图库 |
| 视频 | 当场录 / 相册传 | 对着手机说话的视频也算 |

### 上传交互（照微信做）
- 一个"**+**"号 → 直接跳手机图库
- 选项样式参照微信发消息：上传照片？视频？拍一个？

### 拍板确认
- **谁传照片/视频**：**老人自己 + 子女 + 故事里的人**——凡有这篇故事权限的人都能往里添
- **视频来源**：当场录 + 相册传（老人/子女/故事里的人均可）

## 七、采访引导（含"可打断"硬要求）

### 7.1 AI 当记者
- **主动引导老人讲**："老人家，您说一下那时候的情况？"
- 不是干等老人自己说，是**被引导着说**

### 7.2 ★ 必须支持"老人打断"（硬要求）

采访不是记者念稿子、老人等着。真实对话就是抢话、打断、跑题再拉回。

| 细节 | 要求 |
|---|---|
| **打断要快** | 老人一出声，AI **1秒内**停止说话 |
| **打断不丢话题** | AI 记住刚才问的，老人说完接着聊 |
| **AI 主动让路** | 每问完一句要留等待，不连珠炮 |
| **允许跑题** | 老人说别的，AI 顺着走，不硬拉 |
| **打断灵敏度** | 提供内部档位，应付嘈杂环境（免提/电视/哭声） |

【待验证】微信小程序录音/播放切换的系统级延迟，**能否压到1秒需实机测量**，不得凭印象承诺。

**此为第2期验收硬项——必须真机真人试，不能只看代码。**

### 7.3 ★ 自述页的归类机制（v2.3 修正）

**问题**：采访页有 AI 记者，可以当场问"这是同一件事吗"。但**自述页没有记者在场**，老人自己闷头说，说完就完了 → 归到哪去？

**关键约束（sandy 指出）**：
- 若用**语音问** → 老人得会说、且知道要说 → **需要一个触发按钮**
- 若用**点选** → 老人得看得懂、点得准 → 大字版都未必够
- **两者都有门槛，不能想当然**

**结论：分两步走，第1期只做"不打扰"，第2期真机试后再定要不要问。**

---

**第1期（先能用）——不问，只留小标**

保存完 → 系统按最可能归位 → **不打扰老人**
但页面留一行大字小标：「这段还在 1980年5月，要挪个位置吗？」
老人/子女什么时候看到，顺手一说或一点即可。

- **子女端**：有"待确认归类"提示区，子女可帮整理
- 好处：完全不打断，老人想说说、想停停；猜错了也有子女兜着

---

**第2期（真机试后评估）——语音问 + 大字按钮兜底**

┌─────────────────────────────┐
│  ✔ 记下了                                │
│  🔊（自动语音）"这年您还讲过修水库、      │
│      女儿出生。这段是新的一件事吗？"      │
│                                        │
│      [ 新的一件事 ]  [ 是上面的某一件 ]   │
└─────────────────────────────┘

- **语音优先**：自动播放问题，老人**只用说**，不用点
  - 说"是新的事/是修水库" → 按他说的归
  - 说"嗯/对/好"（含糊）→ **默认新建**（安全侧）
  - 说"什么？/没听清" → **重问，最多2次**
- **大字按钮兜底**：5秒无反应 → 浮出两个超大按钮
- 始终无反应 → **默认新建，不纠缠**

**铁律**：老人**任何反应都不算错**，永远有安全默认（新建），绝不卡住他。

**频率保护（防烦）**：那年只有1件事则不弹；连续多段攒起来一起问；老人说过"别问了"则不再问。

【待验证】"老人对语音提问的真实反应"**完全无数据**。老人真会不会答"嗯/对"、听不听得懂，**须真机找3个老人试**，试完才敢定。此为第2期验收项。

## 八、成书机制

### 8.1 ★ 成书顺序（铁律，v2.1 修正）

点【我要成书】
   ↓
先出电子书（必有，无需选择）
   ↓
看电子书 → 满意 → 再决定是否印实体书
   ↓
要印 → 选开本/装帧 → 印刷厂 → 邮寄到家

**为什么这样定**：
- 电子书 = 0成本、秒出、能改 → 该是默认结果
- 实体书 = 花钱、印刷、改不了 → 必须是**后置的、慎重的决定**
- **电子书 = 印刷样稿**：先看一遍改好，避免印废书

### 8.2 电子书
- 生成后可**分享**
- 可**继续看**
- 可**往里面再添内容**（照片、视频、文字）
- **成书不是终点，是活文档**

### 8.3 实体书
- 对接印刷厂（sandy 联系，多家比价）
- 印刷厂决定页数、开本、装帧
- 印完邮寄到家
- **现在不用决定**印刷事宜

### 8.4 书的形态（三种都要）

| 形态 | 说明 |
|---|---|
| 书的形式 | 常规电子书翻页 |
| 手上看的电子书 | 手机端阅读 |
| 翻相册式 | 用翻相册的手势去翻 |

**设计追求**：线上看到什么样，印出来就什么样 → 省排版。
【待验证】完全免排版的可行性边界，由技术侧评估。

## 八之二、分享机制（v2.3 新增｜sandy 原话定型）

### 8之二.1 sandy 原话

> **"一种是有故事，我直接分享故事给你看；**
> **一种是没有故事，但是我觉得这个很好玩，分享给朋友看。"** —— sandy

**这一句就是分享的全部定义。两种分享，不是一回事。**

### 8之二.2 两种分享对照

| | **① 有故事 → 分享故事给你看** | **② 没故事 → 觉得好玩，分享给朋友看** |
|---|---|---|
| **出发时手里有什么** | 手里**有一篇故事** | 手里**没有故事**，只有"这东西好玩" |
| **分享的是什么** | **那一篇故事** | **小程序本身** |
| **收到的人看到什么** | 直接看到**这篇故事** | 看到**引导页**（"给你家老人也做一本？"） |
| **他接下来会做什么** | **加进来**，说说他记得的版本 | **自己开一本** |
| **登录时机** | **看完之后**、想加进来时 | **想开始时** |
| **典型场景** | 老人把老伙计写进书里 → 转给他："你看，我把你写进去了" | 子女自己用着觉得好 → 转给同事："你也给你妈做一个" |

**共同点：都是先看，后登录。看不用登录，参与才登录。**

### 8之二.3 分享的技术形式（微信生态的现实）

| 方式 | 门槛 | 说明 |
|---|---|---|
| **转发小程序卡片** | **最低** | 微信里点开直达，**主力方式** |
| **二维码** | 高 | 微信外 / 面对面 / **印在实体书封底** |
| 网页链接 | —— | **小程序没有网页链接**（除非另做 H5 版） |

### 8之二.4 情况①：有故事，分享故事给你看

```
老人/子女选一篇故事 → 点【分享给朋友】
   ↓
微信转发卡片（卡片上带故事标题/首图）
   ↓
对方点开 → 直接读这篇故事（**不用登录**）
   ↓
篇末一句：
   「这是李桂芳的故事，里面提到了你
     [ 我也加进来，说说我记得的 ]」
   ↓
点按钮 → 微信一键登录 → **默认加入"这一篇"**
```

- **被提一句的人，只看这一篇，不看全本**
  - 这里**不需要任何授权动作**：张三写故事时把他加进来，等于张三已经同意他看这一篇
  - 所谓“不越权” = **只给他提到他的那篇**，不是“要他再申请一次”
  - **只有一种情况要授权**：他想看**全本**（张三的全部故事）→ 这才须张三/家人点头
- 意义：老人把朋友写进书 → 朋友也来做书 → **从"一人做书"变"一群人在做书"**

### 8之二.5 情况②：没有故事，觉得好玩，分享给朋友看

```
子女在自己手机上点【分享给朋友】
   ↓
微信转发小程序卡片（卡片上是产品本身，不带他的故事）
   ↓
对方点开 → 引导页「给你家的老人也做一本？」
   ↓
点【开始】→ 微信一键登录 → 开自己的故事
```

- 分享出去的**不是他的内容**，是**产品入口**
- 这是他主动替产品说话的场景——**口碑入口**

### 8之二.6 情况③：没被分享，自己找上来的（v2.3 补充）

**sandy 指出的第三种入口**：这个人没收到任何分享，是从**别的渠道**知道这个小程序的（朋友随口一说、搜到、听人推荐），他自己上来了。

```
张三写故事 → 把老李写进故事（老李此刻还没上过小程序）
   ↓
老李从别的渠道知道小程序 → 自己注册/登录
   ↓
一进去就看到：「有 1 篇故事提到了你」   ← ★ 惊喜点
   ↓
点进去看完（也不用登录动作之外的任何授权）
   ↓
可以补充自己记得的版本
```

**关键：他上来了，系统怎么知道“这篇提到了他”？**

| 环节 | 做法 |
|---|---|
| 张三加老李时 | 老李可能**还没有账号** → 先按**手机号/名字**登记为一条“待认领”的人 |
| 老李后来注册 | 用**同一手机号**登录 → 系统自动**认领**那条待认领记录 |
| 认领成功 | 首页出现「**有 N 篇故事提到了你**」 |
| 若手机号对不上 | 提供**按名字搜索认领**（张三那边可确认） |

**为什么要“待认领”这个设计**：
- 写故事的人**必须能先把人写进去**，不能因为对方没账号就写不成
- 对方**什么时候上来都行**，早来晚来都能认到自己那份
- **不需要事先通知他、不需要他同意**——他是被写进去的，不是来签字的

**铁律：被提到的人看“提到自己的那篇”，永远不需要授权。**
授权只出现在**一件事**上——他想要**全本**。

### 8之二.7 登录点与铁律

| 场景 | 登录时机 | 位置 |
|---|---|---|
| ① 收到故事的人 | 看完后、想加进来时 | 故事页底部按钮 |
| ② 被推荐来玩的人 | 想开始时 | 主页"开始"按钮 |

- **通用原则：看不用登录，参与才登录。** 登录为了"参与"，不为"围观"
- 优先**微信一键登录**；手机号登录作备选
- 分享范围 = "哪本 / 哪篇"，**默认不越权**
- **分享有效期**：暂**不设期限**（老朋友可能隔几个月才点，设失效反把人挡门外）

【待验证】"免登录先看、看完再登录"涉及小程序未登录态的页面权限设计，具体好不好做须实测。

## 九、收付款（后台可配置）

### 9.1 原则
- 程序只提供"**能收**"的能力
- **收不收、收多少、怎么收 = 后台配置，不写死在代码里**
- 具体收费规则由 sandy 后续定，我们再补

### 9.2 收费模式（后台开关 + 规则表）

后台管理页
   ├─ 单本电子书：□收费  ☑免费    → 填：___元
   ├─ 年费会员：  ☑开启          → 填：___元/年
   └─ 实体书：    按册计价（印刷厂报价）

- 第4期**一次性预留三种模式**（免费/单本/年费），后续随意切换
- 好处：改价格、开关收费**不用找开发、不用重发版本**

### 9.3 改动代价说明

| 改动内容 | 是否需重发小程序 |
|---|---|
| 改价格 | ❌ 后台改 |
| 免费↔收费 | ❌ 后台开关 |
| 加"年费"模式 | ⚠️ 后台已预留则不用；未预留则需重发 |
| 加支付宝 / 海外支付 | ✅ 需新版本 + 审核 |

### 9.4 支付渠道
- 第一版：**微信支付**
- 预留：支付宝 / 其他
- 若海外售卖，需加海外支付模块

### 9.5 待调研（调研后回 sandy）
1. **小程序能否直接收款？** 需何种认证？（微信支付商户号资质）
2. **年费挂在哪？** 会员制 / 订阅制 / 单本授权？
3. 【待验证】微信支付后台改价免重发版的政策，**须查官方最新文档**，不凭印象
