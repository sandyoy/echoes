## 六、记忆互拉机制（sandy姐8月5日定，方案A）

**背景**：你（小鲸鱼）之前卡在"本地→云端传记忆"方向，以为是大文件问题。但**记忆其实是文本小文件**，一共才 8KB 左右，根本不是大小问题。真正的问题是：**记忆文件没被共享出来，你不知道它在哪、长什么样。**

**记忆文件位置（在我这台本地机器上）：**
- `~/.hermes/memories/MEMORY.md`（我的记忆，约2500字符 / 5771字节）
- `~/.hermes/memories/USER.md`（sandy姐的用户档案，约885字符 / 2399字节）
- 容量配置在 `~/.hermes/config.yaml` 的 `memory.memory_char_limit`（我这边已调到4000）、`memory.user_char_limit`（已调到2500）

**为什么你拉不到：** MEMORY.md / USER.md 存在本地 `~/.hermes/memories/`，**根本不在 GitHub 仓库里**，所以你在远程当然找不到。不是网络慢，是文件从未被推送过去。

**同步机制（统一用这套）：**
1. **我不推 MEMORY.md 原始文件**（含我本地的内部结构，不干净）。
2. 我在衔接文档里维护这份「记忆地图」——告诉你关键记忆条目存在哪个文件/哪份共享文档里（比如业务铁律在 `docs/投标合作铁律_给小鲸鱼_*.md`、沟通规矩在本文档第五部分）。
3. 你（小鲸鱼）每天 `git pull` 拉这个衔接文档的更新，就能看到我这个方向新增的重要记忆/结论。
4. 你自己也维护一份镜像衔接文档（或在本文档追加你的记忆地图），我这边 pull 也能看到你的。
5. **原则**：重要的"结论/铁律"写成共享 `.md` 放进仓库，细枝末节的临时状态不共享。真正的 knowledge 放文件，memory 只做索引。

**一句话给你**：别怀疑网络和大小，记忆是 8KB 小文本；去找共享文档里的"记忆地图"，不是去 GitHub 翻原始 MEMORY.md。
