# 文件修订管理 · 双 Hermes 共同规则

> ⚠️ 本规则由小鲸鱼创建，**小鲸鱼与小龙虾共同遵守**，可通过 GitHub 同步共享。
> 目的：解决"读文件发现要改点，当时只口头提、没改，下次新版本又放回旧错误"的失控问题。

---

## 一、问题场景（为什么要立这条规则）

- 读文件时发现数据过时/表述不对/逻辑错误
- 但"当时没改"，只在对话里口头说了一句
- 下次出新版本时，靠脑子记，隔几个话题就忘了
- 结果又把**旧的错误数据/表述**放回新版本

> 这不是能力问题，是"没有落地机制"的问题。靠临时记忆不可靠。

---

## 二、规则核心（三件事）

### 1. 发现即登记，不只在嘴上说

读任何文件，凡发现需修订的点，**当场**：
- 写进该文件**顶部**一个 `> ⚠️ 待修订：[日期] 问题描述，需改为...` 块
- 同时登记到 `docs/圆爱康/修订待办清单.md`

> 禁止只在对话里口头提一句就完事。

### 2. 出新版前必查清单

任何一次**重写 / 出新版本 / 改文档**，第一步先查：
- 该文件有没有 `⚠️ 待修订` 块
- `修订待办清单.md` 里有没有本文件的未完成项

> 把该改的都带上，再写新版本。这是硬性前置检查。

### 3. 重要文件带"修订历史"

每份**重要输出文件**，顶部维护一个 `## 修订历史` 块：

```
## 修订历史
- v3 (2026-08-06) 修正产后数据1500万→数百万；新增两类闭环
- v2 (…)          重构/新增XX
- v1 (…)          初版
```

> 改没改、改了什么，白纸黑字可见。防止"倒退"，把旧错带回去。

---

## 三、修订待办清单的用法

- 文件位置：`docs/圆爱康/修订待办清单.md`
- 分两栏：`🔴 未完成修订` / `🟢 已完成`
- 每项：文件路径 + 问题 + 是否已解决
- 谁发现、谁登记；谁解决、谁销项

---

## 四、双 Hermes 协同约定

| 动作 | 谁做 | 怎么共享 |
|------|------|---------|
| 发现修订点 | 任一 Hermes | 登记到清单 + 该文件⚠️块 |
| 解决修订点 | 任一 Hermes | 改文件 + 清单销项 + 更新修订历史 |
| 出新版本前 | 双方 | 先查清单和⚠️块 |
| 同步 | 双方 | 通过 GitHub push/pull 共享清单和文档 |

> 重要：**小龙虾改的任何文件，同样先查清单**；小鲸鱼登记的修订点，小龙虾 pull 后要看见、要执行。这套机制是全公司 Agенты 共用的，不是某一个人的记性。
