# 圆爱康数据知识产权登记 · 技术人员数据提取执行清单

> 用途：给圆爱康技术团队的一份可照做的数据提取清单。
> 目标：从后台系统导出、整理出"数据知识产权登记"所需的核心数据材料。
> 执行人：技术人员（数据库/后端）
> 版本：v1.0 · 2026-08-11

---

## 〇、先讲清楚：这份清单是干嘛的

圆爱康要做"数据知识产权登记"，需要向登记平台证明"圆爱康确实有一批属于自己的、有价值的数据"。这需要从后台数据库把数据**导出来、统计、整理**成登记材料。

**不是"搜索数据"，是"从后台数据库里提取圆爱康自己产生的数据"。** 圆爱康系统里产生的数据（患者做康复、设备回传数据、六师共管App记录）都在后台数据库存着，技术要做的是把这些**结构化、统计、脱敏**地导出来。

---

## 一、先圈定：要提取哪些数据域（在后台哪些模块）

圆爱康的居家康复闭环 + 六师共管，数据主要分布在**三大模块**，这三大块就是最值得申报的数据资产：

### 模块1：居家康复训练数据（★ 最有申报价值）
后台位置：**设备数据/康复训练记录表**
来源：患者在家用圆爱康设备训练，设备通过物联网实时回传。
包含：病种（盆底/心脏等）、训练项目、训练时长、训练频次、训练过程中的生理参数、训练成果。

### 模块2：六师共管服务数据（★ 高价值，圆爱康独有）
后台位置：**服务协同/随访记录表**
来源：六师（科室专科医生/治疗师/专科护师/线下督导/设备工程师/线上专业客服）在App/后台对患者做的评估、开方、随访、指导。
包含：评估记录、康复方案、随访记录、指导记录、效果评估。

### 模块3：患者基础康复档案数据（★ 申报价值中，需谨慎处理）
后台位置：**患者档案表**（脱敏后）
来源：患者入院建档。
包含：年龄区间、病种、健康状况等（**必须去掉个人身份信息**——姓名、身份证、手机号等不可出现）。

---

## 二、逐项提取要求（技术人员照这个做）

### ① 数据名称 / 内容描述（整理成文字）
**这一个不是技术提取，是业务命名**，但技术要配合确认数据实际覆盖范围。
- 建议名称（示例，可按实际调整）：
  - "圆爱康居家盆底康复闭环训练数据集"
  - "圆爱康六师共管心脏康复服务过程数据集"
- 内容描述模板："本数据集包含____（数量）名患者的居家康复全过程记录，涵盖____（病种）康复训练及____（六师）协同服务数据，反映患者从建档、评估、训练到效果随访的完整康复闭环。"

### ② 数据规模 / 量级（技术统计）
在后台对各数据表跑统计，输出：
| 统计项 | 说明 | 输出示例 |
|---|---|---|
| 患者总数 | 去重后患者数 | 1,280 名 |
| 康复训练总记录数 | 训练记录表行数 | 35,000 条 |
| 覆盖病种数 | 涉及几个病种 | 2（盆底、心脏） |
| 服务记录数 | 六师随访/评估记录表行数 | 8,200 条 |
| 时间跨度 | 数据最早~最新 | 2025-03 ~ 2026-07 |

### ③ 数据结构 / 字段说明（技术列出）
技术人员打开数据库，把相关表的字段列成清单，输出格式如下：

**表1：康复训练记录表**
| 字段名 | 含义 | 是否参与申报 |
|---|---|---|
| patient_id（脱敏） | 患者编号（脱敏后） | 是 |
| disease_type | 病种（盆底/心脏） | 是 |
| training_item | 训练项目 | 是 |
| duration_min | 训练时长(分钟) | 是 |
| training_date | 训练日期 | 是 |
| device_sn | 设备编号 | 是 |
| ... | ... | ... |

**表2：六师服务记录表**
| 字段名 | 含义 |
|---|---|
| patient_id（脱敏） | 患者编号 |
| service_teacher_role | 服务角色（医生/治疗师/护师/督导/工程师/客服）|
| service_type | 服务类型（评估/开方/随访/指导）|
| service_date | 服务日期 |
| service_content | 服务内容（可摘要）|

> ⚠️ **删字段红线**：姓名、身份证号、手机号、家庭住址、精确年龄(可保留年龄区间)、可定位信息等**个人身份识别字段一律不参与申报**，申报前必须从导出数据中剔除。

### ④ 数据形成方式（整理成文字，技术确认来源）
技术配合确认数据是怎么进系统的，写清楚"实质投入"。模板：
"患者经合作医院医生评估开方后，在居家场景使用圆爱康生物反馈电刺激设备进行康复训练；设备通过物联网实时将训练数据回传圆爱康平台；同时六师团队通过圆爱康服务App对患者进行远程评估、方案调整与随访，形成训练与服务双闭环数据。数据由圆爱康自有设备、平台与服务体系全流程产生。"

### ⑤ 应用场景（整理成文字）
"用于居家康复方案的个体化优化、康复效果的量化评估、不同病种康复规律的统计分析，以及服务质量的持续改进。"

### ⑥ 脱敏 / 合规声明（技术做脱敏 + 出具声明）
- **技术任务**：从所有导出数据中，**剔除/替换所有可识别个人身份的信息**。
  - 姓名 → 删除
  - 身份证/手机号/地址 → 删除
  - 患者ID → 用不可逆编号重排（如 P001、P002…）
  - 年龄 → 保留区间（如 30-39 岁）
- **输出声明**（登记平台需承诺）："本申报数据集已完成脱敏处理，不含可识别个人身份的信息，数据来源为圆爱康自营服务所产生的合法数据。"

### ⑦ 样例数据（技术导 5-10 条脱敏样例）
从后台导出 5~10 条**脱敏后**的数据，作为样张证明。
示例格式（训练记录，已脱敏）：
| 患者编号 | 病种 | 训练项目 | 时长(分) | 训练日期 | 设备编号 |
|---|---|---|---|---|---|
| P001 | 盆底 | 生物反馈电刺激 | 30 | 2025-08-01 | DEV001 |
| P002 | 心脏 | 心脏康复训练 | 20 | 2025-08-02 | DEV002 |

### ⑧ 申请书 / 登记表（执行人在登记平台在线填写，系统生成）
技术人员负责**提供数据**，执行人负责**在平台填表**。技术把①-⑦整理好交付给执行人即可。

## 三、技术执行步骤汇总（照着做）

1. **登录圆爱康后台数据库**，确认数据表位置（训练表、随访表、患者档案表）。
2. **统计量级**：跑 SQL 统计患者数、各表记录数、病种数、时间跨度（对应②）。
3. **拉字段**：查各表字段定义，列出字段清单（对应③）。
4. **脱敏**：写脚本把导出数据中的个人身份字段剔除/替换（对应⑥）。
5. **导样例**：导出 5-10 条脱敏后样例数据（对应⑦）。
6. **出统计表**：把②的量级统计、③的字段清单整理成表格文档。
7. **核对**：确认所有导出数据**不含任何个人身份识别信息**。
8. **交付**：把 ①②③④⑤⑥⑦ 全部整理打包，交给登记执行人填写⑧。

---

## 四、给技术的小提醒

- **时间**：建议优先导出"居家康复训练数据 + 六师共管服务数据"这两块（最能体现圆爱康独特价值）。
- **合规第一**：任何一条导出数据**都不能出现患者姓名、身份证、手机号**，这是登记的红线。宁可删字段，不可留敏感信息。
- **不编数据**：所有统计数字（多少患者、多少条记录）必须是**后台真实查出来的**，不能虚报——登记审核会抽查，且真实数据本身就体现圆爱康有料。
