## 二、客服岗定位（一句话）

**客服 = 非医疗事务的唯一承接方。**

- 医疗归医疗团队（医生/护士/康复师）；
- 非医疗（设备操作答疑、使用提醒、订单物流、服务期咨询、异常发现与通知、回访）归客服；
- 涉及病情的判断与处置意见，一律由医院执业医师给出——**客服只承担发现、通知、协助联系、流程跟进。**

> 这句话是客服岗的护身符，也是第一课。任何培训/对外表述不得越过它。

## 三、通道纪律：哪些动作才"算数"

### 3.1 白名单（留痕通道内做的服务才算数）

1. 企业微信
2. 小鲸客服 APP
3. 服务群（企微群）
4. 医生端系统内对话

### 3.2 不算数（须拦回白名单）

- 私人微信私聊
- 电话（无录音）
- 当面口头（例外见 3.3）

### 3.3 当面沟通的补录口子

当面口头不计。但允许**事后 24 小时内补录进 APP**，补录成功才算数——否则线下彻底成黑洞。

### 3.4 硬话术（必须进培训，否则规则形同虚设）

患者要加私聊时，客服只说这一句：

> "公司规定服务记录要留痕，您的权益也靠这个保障。我加您企业微信，一样随时找我。"

## 四、服务怎么算"一条"

### 4.1 定案：C 为主、A 为辅

- **主**（考核主指标）：按**有效服务动作**算——标签制。一个标签 = 一条服务动作。一次对话里客服既教了操作又催了回访，打两个标签，算两条。
- **辅**（质量观察）：会话时长 / 响应时长，只做后台观察数据，不直接进考核。

### 4.2 为什么不用 A / B

- **A 按会话算**：客服可磨时长刷条数。
- **B 按患者-日算**：一个患者一天三个独立问题只算一条，客服敷衍。
- C 是唯一能撑住"可追溯"的算法——将来医院问"你们做了哪些服务"，只有 C 答得上。

### 4.3 标签规则（先粗后细，不上 AI）

- 客服在 APP 里处理完一件事，**手动选一个标签**：
  操作指导 / 使用提醒 / 订单物流 / 服务期咨询 / 异常响应 / 回访 / 投诉
- 标签对应合同 10 条服务内容，**共 7 个**，点一下即可。
- **每月抽查 10%**，标签打错扣"记录质量分"（不扣投诉）。
- 第二步（半年后）：只对高频稳定场景（退费、报障）做自动识别；**不追求全自动**——口语化对话 AI 识别做不到让考核服众。

> 给技术团队的一句话：**"不要求系统自动判断对话内容，只要系统能让我手动打个标签、标签能导出来就行。"**

## 五、投诉分责：看记录不看嘴

### 5.1 分责原则（不靠"谁说的"，靠"记录里有没有动作"）

| 情形 | 判定 | 计分处理 |
|---|---|---|
| 客服按口径答了、按流程做了（有记录） | 患者问题（不合理诉求/情绪） | **不计**客服投诉 |
| 客服答错 / 答慢 / 没按口径 / 没闭环 | 客服问题 | **计**投诉 |
| 无对话记录（私聊、口头） | 默认不算投诉 | **不计**投诉，但计入"服务留痕缺失"扣分 |

### 5.2 两个口径分开算

- **投诉率**：只统计"计投诉"的条数 / 服务总条数。
- **留痕缺失**：单独一项扣分，与投诉分开。无记录≠有错，但没留痕要担。

### 5.3 这条规则的作用

逼客服把话都留在留痕通道里：留企微判得清，留私聊自己担。与"全员企微"纪律同方向、互相加固。

## 六、考核维度（维度我出，标准线 sandy 填）

**本表只给"考什么、怎么量"。标准值栏留空——由 sandy 按公司实际填。**

| # | 考核维度 | 怎么量 | 数据来源 | 标准值 |
|---|---|---|---|---|
| 1 | 服务量 | 有效服务动作条数（标签数） | 客服APP标签导出 | ___ 条/月 |
| 2 | 响应时效 | 首次响应时长 | 会话记录 | ___ 分钟内 |
| 3 | 问题闭环率 | 已闭环问题 / 受理问题总数 | APP + 异常台账 | ≥ ___ % |
| 4 | 记录质量 | 标签抽查正确率（月抽10%） | 抽查结果 | ≥ ___ % |
| 5 | 留痕合规 | 留痕缺失条数（私聊/未补录） | 抽查 + 通道比对 | ≤ ___ 条/月 |
| 6 | 投诉率 | 计投诉条数 / 服务总条数 | 投诉台账 | ≤ ___ % |
| 7 | 服务态度/口径 | 违反红线口径次数（如承诺疗效） | 抽查 | 0 次（硬线） |
| 8 | 培训达标 | 入职培训考核分数 | 培训考试 | ≥ ___ 分 |

> 第 7 项是**硬线**：0 容忍，不设浮动值。

## 八、通道归拢方案（技术侧，一期目标）

**一期目标只做到：每条对话都能查到、能导出。** 不做"自动生成患者服务档案"（二期）。

钥匙 = **手机号**（企微外部联系人手机号 + 客服APP患者手机号 + 订单手机号，三边匹配）。
难点 = **打标签**，不是留痕。不要让技术把两层糊在一起。

给技术团队的 5 个确认问题：

1. 企微"会话存档"开了没？（没开先开，不用开发）
2. 会话存档能不能按外部联系人批量导出？什么格式？
3. 小鲸客服APP导出字段里有没有患者ID/订单号/手机号？
4. 患者下单时能不能强制填手机号，并与企微外部联系人手机号匹配？
5. 医生端对话和客服端对话是不是同一个系统？能否用同一个患者ID串起来？

**若技术说"留痕很难"**，让他明确回答：是"第一层（存下来）"难，还是"第三层（归拢到一个患者名下）"难。第一层基本是开功能，第三层才要开发。
