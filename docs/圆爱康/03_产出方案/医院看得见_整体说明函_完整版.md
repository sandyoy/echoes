# 「让医院看得见」居家康复闭环 · 整体说明函

> 面向：院长 / 分管副院长 / 医务科 / 信息科 / 临床科室
> 作用：把【理念 + 技术实现 + 已有能力 + 业务流】完整串起来,一次讲清"医院凭什么敢跟圆爱康合作、数据在哪、名分在哪、闭环断不了"
> 版本：v1.0 · 2026-08-06 小鲸鱼整理

---

## 〇、这份文件讲什么(One Page 看懂)

**一句话：圆爱康不碰医院系统、不动 HIS**，靠【自己已有的三端产品 + 物联网设备】跑通"院内评估 → 居家执行 → 数据反哺回医院"的完整闭环。医院要的三样东西——**名分、数据、主权**——全部通过我们的产品交付,医院方零开发、零对接、零信息科介入。

```
患者出院→居家康复→数据实时回传→（医生端小程序/数据报告/医院入口）= 医院看得见的完整闭环
```

---

## 一、核心理念(先对齐,再谈技术)

### 1.1 我们的核心不是"患者管理",是"治疗闭环"

- 不是单向的"看护/随访",是**双向实时的治疗活水**
- 患者在家治疗 → 设备数据实时上传 → 医生看得见 → 医生反向调方案 → 患者继续治
- 数据是**活的、双向的、闭环的**,不是躺着的一份名单

### 1.2 医院真正要的是什么?—— 三样东西

| 医院要的 | 本质 | 我们怎么给 |
|---------|------|-----------|
| **名分** | 患者感知这是"我们医院的服务",不是外部的 | 入口挂院名院徽,医生端、患者端都以医院名义呈现 |
| **数据** | 数据归医院,能查、能存档、能汇报、能审批 | 患者治疗数据同步医生,周期性报告反哺,结构可导出 |
| **主权** | 医疗主权不旁落,医院说了算 | 医疗服务、开方、复诊转化均由医院医生主导,圆爱康只做"设备/运营/执行" |

### 1.3 三条"绝不能主动挑"的雷

> 这些是谈判中被证明最伤合作的坑,我们不主动碰,等医院开口再说。

1. **数据资产意识** —— 不主动提"数据资产/数据变现",只讲"数据反哺医院"
2. **医生入口归属** —— 不争"入口放哪边",入口天然以医院名义,医院要形象就给形象
3. **技术对接成本** —— 这是我们最大的卖点:**零对接**,不碰 HIS、不找信息科

### 1.4 最锋利、最不可辩驳的那把刀 ——「闭环会断」

- 监测类数据：绑医院系统,医院自己攒 → 出了院就断
- 我们的数据：**物联网设备自产 + 双向实时治疗闭环**,医生能改方案、能续疗程 → **断不了**
- 医院的 HIS 是"数据只进不出";我们的闭环是"数据实时进出"。
  **把双向治疗闭环硬塞进医院系统 = 中断。** 所以闭环必须完整保留在我们这一端,同时通过报告/入口把"可见性"给医院。

### 1.5 我们的核心筹码 —— 数据愿意反哺医院

> 不说"数据资产归谁",说"数据反哺医院"。这是最实用、最不引发主权/安全重谈判的表述。

## 二、我们已经有的能力(不是画饼,是现成的)

| 端 | 现状 | 承担什么 |
|----|------|---------|
| **医生管理端小程序** | ✅ 已有,成熟 | 医生登录即看**自己名下管理的患者**——实时数据、治疗进度、预警。**不需要额外扫码、不需要新增查房页** |
| **患者端** | ✅ 已有 | 患者在家训练、填问卷、看进度,设备数据上传 |
| **运营端** | ✅ 已有 | 客服/工程师/线下督导做随访、设备指导、复诊提醒(六师共管) |

**关键事实：医生端小程序已经有"每个医生看他名下患者"的能力。** 所以"医生看得见自己管的患者"这件事,已经是现实,零新增开发。

## 三、技术实现路径(全部在我们这一端,零对接医院系统)

> 核心结论：**医院方的"看得见",不需要通过对接医院系统实现,而是通过我们已有的产品 + 数据反哺实现。**

| 医院需求 | 技术实现 | 是否要开发 |
|---------|---------|-----------|
| 医生看名下患者实时数据 | **医生管理端小程序(已有)** | ❌ 零开发 |
| 患者感知是医院服务(名分) | 患者端/签约页挂**院名+院徽** | ✅ 极小(改前端文案/主题) |
| 医院管理层能汇报、有数据底(数据权/主权) | 周期性生成《医院居家康复数据报告》,结构可导出、可存档 | ✅ 极小(模板+自动生成) |
| 医院管理层"自己进来看"(可选,视院长要求) | 在**已有医生端**基础上,给管理员加一个"管理驾驶舱"角色页 | ✅ 可控(加角色+汇总页,底层数据现成) |

**三个"不需要"：**
- 不需要对接医院 HIS / 不需要信息科参与
- 不需要医院任何系统开发
- 不需要医院配服务器 / 配接口

## 四、业务流串流(一图到底)

```
【在院】患者住院/门诊治疗
   │ 医生评估 → 适合居家康复
   ▼
【签约】医生/客服推荐服务包,患者签字
   ------ 入口以医院名义,挂院名院徽(名分) ------
   ▼
【居家执行】圆爱康寄设备到家,患者在家治疗
   │ 物联网设备 → 治疗数据实时上传
   ▼
【数据流】数据同步平台与主管医生
   │
   ├──► ① 患者端：自己看进度、训练引导
   │
   ├──► ② 医生管理端小程序(已有)：主管医生看名下患者实时数据
   │
   └──► ③ 全流程客服证据链(24h人工+Agent)：
         客服按疗程主动提醒/督促/指导,患者时刻有人管
   ▼
【评估/复诊】两类闭环（按设备区分）
   ├─ 盆底(设备自带评估)：在家治→线上评估→疗效结论→医院复诊转化续单
   └─ 多数治疗设备：客服提醒患者回院评估→医院据疗效复诊转化
   ▼
【复评/续疗】由医院据疗效转化复购 → 患者继续 → 数据重启 → 闭环不断
```

**两类闭环的"患者回流、医院评估转化"是共同主线** —— 这正是医院最关心的：患者持续回流复诊、科室有后续收入。圆爱康负责把"治疗过程管到顺"，复诊转化归医院。


**闭环的关键动作：医生在管理端看到数据 → 调方案 → 患者继续治疗 → 数据继续回传。**
数据在这个循环里是**活的**,这才是"闭环".

## 五、为什么这套能成立(给每一位决策者的底气)

1. **医院零对接** —— 不碰 HIS、不动信息科、不做接口,消除最大推进阻力
2. **名分在医院** —— 入口挂院名院徽,患者感知是"我们医院的服务"
3. **数据全给医院** —— 周期性报告结构可导出,能存档、能汇报、能对接审批
4. **医生零学习成本** —— 医生端小程序已有,医生本来就在用,不用培训
5. **闭环断不了** —— 治疗数据由我们物联网设备自产实时上传,业务流完整在圆爱康这端跑通,不会因为"系统没对接"而断
6. **主权不动摇** —— 医疗服务由医院医生主导,圆爱康只做设备+运营+执行;医院要的方向说了算

## 六、给院长/信息科的关键表述(拿去就能说)

> "X院长 / 信息科同事,这套居家康复**不用动贵院任何系统、不需要信息科参与。**
>
> 医生管理端小程序我们现成的,每个医生进去就看他名下管理的患者实时数据;
> 患者的服务入口挂的是贵院的名字和院徽,患者看到的就是'我们医院的居家康复',不是外部的;
> 我们每周期还自动给贵院生成一份《居家康复数据报告》,患者做了几次、依从性、进度、预警全都有,您可以直接存档、汇报、走审批。
>
> 数据全在贵院的掌控里,医疗服务是贵院医生主导的,我们只做设备、执行和运营。
> 患者出院以后这条治疗线不断,数据不断——这就是我们要给贵院的东西。"

## 七、给医院的下一步(可选升级,不在本项目硬性范围)

> 如果院长/信息科提出"我们院长层自己也要有个看板",以下为可选项,不影响主线推进:

| 选项 | 说明 | 周期 | 是否阻塞 |
|-----|------|------|---------|
| A. 数据报告反哺(主线) | 周期性报告送上门,零开发，立即可上 | 即日 | 否 |
| B. 管理驾驶舱(可选升级) | 在已有医生端加管理员角色页,院长看全院汇总 | 追加排期 | 否，可后做 |

> **建议：主线走 A,先把"看得见"做起来；B 视院长反馈再追加。不因 B 的排期拖慢整体签约。**
