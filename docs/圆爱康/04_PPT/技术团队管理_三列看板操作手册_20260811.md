# 圆爱康技术团队管理 · 三列看板操作手册

> 编制：云端小鲸鱼 · 2026-08-11
> 用途：给圆爱康（sandy）用于管理技术团队的落地工具——从"三列看板"起步，配合周会三问和版本轨道。
> 定位：技术小白也能用。**不要求你懂技术，只要求"目标清、时间清、结果清、风险清"。**

---

## 一、为什么先做"三列看板"

技术小白管技术团队，最容易踩的坑是：
- ❌ 想看技术细节（累死自己，团队还烦）
- ❌ 天天盯着问（团队烦、你也累）
- ❌ 只问不做笔记（说了就忘，没记录）

**三列看板是最轻、最快见效的第一步**——一张表，把"谁在做什么、做到哪、什么时候好"全部摆清楚，你每周看一次就能掌握全局。

---

## 二、三列看板长什么样

核心就是三个状态列，所有任务都进看板：

```
┌─────────┬─────────┬─────────┐
│  待做    │  在做    │  完成    │
│ (To Do) │(Doing)  │ (Done)  │
└─────────┴─────────┴─────────┘
```

每张"任务卡"写清楚 3 样东西就够了：
1. **要什么**（目标/验收标准——用大白话写，不写技术术语）
   - ❌ 错误："优化数据库索引"
   - ✅ 正确："让医生能在小程序里看到患者康复进度"
2. **谁来做**（负责人，一个人）
3. **什么时候好**（预计完成时间）

**用哪个工具**：飞书多维表格 / 腾讯文档 / Excel / 甚至微信群+共享表格，都行。工具不重要，先跑起来。

---

## 三、三列看板怎么用（你的用法）

### 你每周看一次看板，只看三件事：
1. **有没有任务卡在【在做】太久没动？** → 说明卡住了，要去问"卡在哪，要不要我出面帮解决"
2. **有没有【待做】越堆越多？** → 说明排期失控，要砍需求或加人
3. **有没有说"做完了"但【完成】没更新？** → 说明有人嘴上说完成，实际没落地

### 三列看板的立规矩（团队照做）：
- 所有任务必须进看板，标负责人+时间
- 任务动一步，看板更新一步（【在做】↔【完成】）
- 每周一统一过一遍看板

---

## 四、配套：每周一30分钟周会（三问）

看板是"记录"，周会是"对齐"。每周一留30分钟，周会上你只盯这几句：

### 周会四步：
1. **上周完成了什么**（对照看板【完成】）
2. **这周要做什么**（从【在做】【待做】里挑重点）
3. **有没有卡住/风险**（最关键！让他们主动说"遇到什么阻碍"）
4. **下个版本定什么**（版本轨道是否推进）

### 你作为老板，周会上只说三句：
1. **"这个功能的目标是啥？什么时候好？"** → 对齐目标和时间
2. **"有没有风险/卡点需要我出面解决的？"** → 你帮他们清障碍，不是催
3. **"做完了给我看效果，别只跟我说做完了。"** → 盯结果，不盯过程

---

## 五、版本更迭怎么管（配套）

版本管理的关键是"**别让技术想发就发**"，要有发版节奏。分三个轨道：

| 版本轨道 | 用途 | 节奏 |
|---|---|---|
| **大版本**（1.0 → 2.0）| 新增重要功能 | 几个月一次，里程碑 |
| **小版本**（1.1、1.2）| 加小块功能/优化 | 几周一月一次 |
| **补丁**（1.1.1）| 修bug、紧急问题 | 随时，小改动 |

### 每次发版前，你问技术三句话（医疗产品命门）：
1. **这次发版解决什么？**（目标）
2. **会不会影响已在用的患者/医院？**（风险——**医疗产品人命关天**）
3. **老功能有没有被破坏？**（回归测试——必须问）

### ⚠️ 医疗产品专属红线：
- 涉及**治疗方案、设备控制**的改动，必须走内部评审，不能随便发
- **涉及患者安全问题，你必须有最终拍板权**——哪怕技术说"先上线"，涉及患者安全你必须踩刹车
- 任何发版，都要做**回归测试**（确认没搞坏老功能）

---

## 六、重要认知（看板背后的心法）

**你管的是"目标、节奏、结果"，不是"技术怎么写代码"。**

- ✅ 你要做的：目标清楚、时间清楚、结果清楚、风险清楚
- ❌ 你不做的：怎么实现、用什么技术、代码怎么写（这些交给技术负责人）

**医疗产品再加一条**：安全与合规问题，你必须有最终拍板权，永远站在"患者安全"这边。
