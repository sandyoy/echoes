# 影视/内容物料交付打包规范 v1.0

> 制定：2026-09-19　｜　依据：心脏康复门诊科普片交付实战（sandy 确认"这套结构好用、已转制作方"）
> 适用范围：**所有**由小鲸鱼产出、需转给外部制作方（剪辑/配音/拍摄）的物料——科普片、宣传片、视频号拆条、动画等。
> 状态：**现行标准**。小鲸鱼打包时按本规范执行，不再逐次询问格式。

## 一、为什么要有这个规范

sandy 大部分时间不在电脑前，用手机看文件。**markdown / txt 在他手机上打不开**，等于没交付。
所以他看到的、以及转给制作方的，必须是 **Word（.docx）**。

历史教训（2026-09-19）：曾交付 .md + .txt 版，sandy 明确纠正"你给我打包的东西必须是 word 版本，否则我看不见"。
→ **本规范第 0 条：对外/给 sandy 的物料，一律 .docx。.md 只允许存在于仓库内（版本管理用）。**

## 二、包结构（三段式）

一个 zip，里面固定三段：

```
<项目名>_交付包_<日期>/
├── 00_交付说明.docx          ← 必放，见第四节
├── 01_文字稿/                ← 旁白文字稿 / 解说词
│      <项目名>_<版本>_文字稿_<版本号>.docx
├── 02_录音稿/                ← 供配音员录制的稿件
│      <项目名>_<版本>_录音稿_<版本号>.docx
└── 03_分镜脚本/              ← 画面分镜（镜号/画面/时长/旁白/备注）
       <项目名>_<版本>_分镜脚本_<版本号>.docx
```

**分三段的理由（sandy 原话："按照文字稿、录音稿和脚本分三个"）**：
制作方是**按工种分头干活**的——文案看文字稿、配音看录音稿、剪辑/拍摄看分镜脚本。
三段分开 = 拿到包的人不用在长文档里翻找自己那部分。

**例外处理**：若旁白文字稿本身即可直接用于配音（本项目的实际情况），
可将 `02_录音稿/` 合并进 `01_文字稿/`，并在 `00_交付说明.docx` 中写明"旁白稿即录音稿"。
**但目录名仍保留 `02_录音稿` 的位置说明，不得静默省略**——制作方找不到会回头问。

---

## 三、命名规则

- 包名：`<项目名>_交付包_<YYYYMMDD>.zip`
- 子夹：`01_文字稿` / `02_录音稿` / `03_分镜脚本`（**中文 + 两位序号**，序号保证排序稳定）
- 文件名：`<项目名>_<支号/版本>_<文件类型>_<版本号>.docx`
  - 例：`心脏康复科普片_第一支症状版_分镜脚本_v1.0.docx`
- **版本号必须写进文件名**（v1.0 / v1.1 / v2.0）——制作方改完回传时能一眼对上，不出错版。
- 不用空格，用下划线连接。

---

## 四、`00_交付说明.docx` 必含四块

1. **包内结构清单** —— 哪几个夹、每个夹放什么、各多少镜/多少段
2. **形态说明** —— 实拍/动画/混剪？有无真人出镜？一套素材几种用途？
3. **给制作方的硬约束** —— 合规红线，逐条编号，语气明确"不得改写"
4. **反馈路径** —— 制作方遇到问题找谁、反馈到哪，明确"不要自行改写旁白"

**为什么必须放这块**：制作方拿到包不等于知道边界。约束写在包最外层的说明里，才不会被漏读。
本项目实战约束（可作模板）：
- 不出现品牌名 / 厂商名 / 价格
- 不写"我院已开展"（通用版，任何科室可播）
- 「院内打主力、居家补频率」，不写"居家替代院内"
- 所有数字只能是"治疗安排"（次数/时长/频率），**不得**写成"疗效结果"
- 不出镜真实患者，不出现姓名 / 病历号 / 面部

## 五、交付动作链（谁在哪一步做什么）

| 步骤 | 执行方 | 动作 | 产出 |
|---|---|---|---|
| 1 | 小鲸鱼 | 内容定稿，源文件（.md）入库 `docs/` | 仓库内 .md 源文件 |
| 2 | 小鲸鱼 | 转 Word，按三段式打包 | `<项目名>_交付包_<日期>.zip` |
| 3 | 小鲸鱼 | 打包后 **MEDIA 直发 sandy**（WeCom） | sandy 手机收到 zip |
| 4 | sandy | 转给外部制作方 | — |
| 5 | 制作方 | 拍摄/剪辑/配音，回传成片 | 成片 |
| 6 | sandy / 小鲸鱼 | 对照 `00_交付说明.docx` 的约束验收 | 验收结论 |

**关键点**：
- 第 3 步是**主动推送**，不等 sandy 问。
- 说了"已发"必须真带 MEDIA 路径——只写路径 = 没发（铁律）。
- 源文件 .md 始终留在仓库，**不进交付包**（制作方不需要，且会让他以为要看两个版本）。
