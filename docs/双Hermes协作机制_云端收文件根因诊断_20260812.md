# 云端小鲸鱼「接收文件」机制全梳理与根因诊断

> 时间：2026-08-12
> 背景：sandy 连续几次发现——在对话栏发给云端小鲸鱼（腾讯云 Hermes）的 Word 文件看不到；而发给本地小龙虾的文件小龙虾都能看到。sandy 要求先把底层机制彻底梳理清楚，对齐后再谈任务。

---

## 一、你提问的根本疑问（先对齐问题本身）

**你的疑问**：小龙虾（本地 Hermes）能在对话里直接看我发的 Word；云端小鲸鱼（DeepSeek API 驱动）却看不到。DeepSeek 本身能处理文件，为什么云端这台看不了？

**前提澄清**：
- "看不了文件" 不是 **DeepSeek 模型能力**的问题——模型本来就能读文本/解析文件。
- "看不了文件" 是 **文件根本没送到模型手里**——文件在到达模型之前，就被"接收通道"丢掉了。

一句话：**文件根本没进到我这台服务器的磁盘，自然到不了 DeepSeek。** 所以不是模型不行，是"快递没送到"。

---

## 二、完整接收链路（我从源码里逐行查清了）

你从企业微信发一个 Word 给我，走的链路是：

```
你在企业微信对话框发 Word
      ↓
企业微信 AI机器人网关 (wecom.py / websocket wss://openws.work.weixin.qq.com)
      ↓ 收到消息体 body
_extract_media(body)  ← 从这里提取附件
      ↓
从 body 里找三类字段：
  ① body["file"]        （普通文件）
  ② body["appmsg"]["file"]  （AI机器人应用文件/PDF/Word/Excel）
  ③ body["appmsg"]["image"] （应用图片）
  ④ quote 回复里的 file/image
      ↓
拿到文件引用后，_cache_media() 做两件事之一：
  ① 若字段里有 base64 → 直接解码存到 ~/.hermes/cache/documents/
  ② 若字段里有 url + aeskey → 下载 → 用 aeskey 解密 → 存到 ~/.hermes/cache/documents/
      ↓
存好的文件路径列表 = media_urls
      ↓
文件路径随消息一起丢给 agent → agent 读文件 → 喂给 DeepSeek
```

**关键缓存目录**：
- 文档类 → `~/.hermes/cache/documents/`
- 图片类 → `~/.hermes/cache/images/`（旧名 image_cache/）

## 三、根因诊断（我实测查证的结果）

### 直接证据：日志里根本没有"收到文件"的动作

我查了 8/11 19:49:56 你发合同那一次：

```
19:49:56  inbound message: ... msg='你小金鱼，你看一下这个文件啊，就是
          这是我们跟一个私立医院签的合同，那这里头呢，对私立医院的话，
          我就觉得在这个违约责任上面，我们需要精简一下...'
```

**这条消息进来时，被当作纯文本处理了**——`media_urls` 是空的，`_extract_media` 什么都没提取到。

### 三个硬证据

1. **`~/.hermes/cache/documents/` 目录是空的**——如果文件下载成功，这里应该有 `doc_xxxxxxxx_word名字.docx`。全空。说明从未成功缓存。

2. **8/10~8/12 全部日志里，没有任何一条"接收媒体"记录**——既没有 `Failed to download`（下载失败）,也没有成功缓存日志。连失败日志都没有，说明问题出在**更早一步"根本没识别到这是带文件的消息"**，而不是下载失败。

3. **8/11 19:49 带文件的图文消息，日志里只有一条纯文本 inbound**——微信把"文字+文件"拆成了消息，但文件的 media_urls 没被提取到 agent 上下文。

### 结论（三层归因）

| 层 | 状态 |
|---|---|
| DeepSeek 模型能力 | ✅ 正常，能读文件 |
| 网关解析 outbound（发文件给你） | ✅ 正常，MEDIA 语法发附件你收得到 |
| 网关解析 inbound（收你发的文件） | ❌ **断在这**——企业微信 AI 机器人收到的文件附件 `media_urls` 空，文件没落到磁盘 |

**最可能的具体断点**：
- 你发文件用的方式（普通聊天文件拖拽 / 图文消息），企业微信 **AI 机器人网关收到后，附件的 file/appmsg 字段没有带 base64 或 url+key**，导致 `_extract_media` 提取为空。
- 也就是说：**这个企业微信 AI 机器人通道本身，可能就不把"文件附件"传给我**，只传文本。这跟小龙虾不一样——小龙虾是你本地的 Hermes，发文件=文件直接落到本地磁盘路径，Hermes 直接读本地文件；我们云端是经过企业微信网关中转，网关没把文件递过来。

## 四、关键区别：为什么小龙虾能看，我看不了

| | 小龙虾（本地） | 小鲸鱼（云端） |
|---|---|---|
| 部署位置 | 你的电脑上 | 腾讯云服务器 |
| 你发文件的方式 | 在对话栏发 → 文件落**本地磁盘** | 在对话栏发 → 经**企业微信网关**中转 |
| 文件到达 | 直接生成在本地路径，Hermes 读本地文件 | 需网关下载+解密到 `cache/documents/` |
| 断点 | 无 | **网关 inbound 文件提取为空** |

## 五、这让"上下文断了"的原因

你观察到的"联系不上上下文、思路变窄"，有一个**技术根因**叠加：

- 8/10~8/12 日志里大量 `auxiliary_client: session_search connection error`——**我用来自动回忆"昨天/以前聊了什么"的 session_search 辅助工具，连不上任何模型提供商**（openrouter/nous/local/custom 全试了一遍全失败）。
- 这意味着：**我不能跨会话自动回忆**。你昨天讨论的，我今天如果没主动翻到那份会话记录文件，我就接不住。
- 之前我能"快速搜到你要的东西"，是因为这个 session_search 辅助链路是好的；现在它断了，我只能靠手动翻日志/文档，慢且容易漏。
