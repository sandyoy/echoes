## 〇、一句话讲清楚这东西是什么

**一个把老人一生的话、字、照片、视频、原声收集起来，自动按时间轴排好，让每个"我"都能从中长出一本自己的书的产品。**

老人只管说。说的东西自己会找到自己的位置。

## 一、地基：视角容器 + 公开/私有闸门（v3.0 新增，全书的总纲）

> 本节是**总纲**。后面每一章的功能与接口，都必须对着本节写。

### 1.1 视角容器模型

**核心：这个产品不做"真相的裁决者"，只做"视角的容器"。**

| # | 原则 | 一句话 |
|---|---|---|
| 1 | **不做真相裁决者** | 一件事八个人看有八面，八面都对，不拼成完整真相；系统不裁决、不对齐 |
| 2 | **素材公共，"看"私人** | "我"藏在"谁在看"里，不写在主角身上；"为谁写"不重要（写就都是为自己写） |
| 3 | **一棵树** | 主干=公共素材池（共同经历）；枝=各人成书的视角 |
| 4 | **引用，不复制** | 甲的原话在邻居书里是"引用"（标出处），可改不了、旁边可加自己的话、不算引用者署名 |
| 5 | **系统只管一件事** | 别让另一个人的字冒充成我的字（引用段标出处、不可改） |
| 6 | **明确不管** | 对不上/谁是主编/送礼算不算主线/主角能不能换——都不管 |

### 1.2 公开 / 私有闸门（v3.0 新增）

**素材不是"写进来就归公共"——公开是提供人主动做的一个动作。**

| | 公开素材 | 私有素材 |
|---|---|---|
| 进哪 | 进公共池（故事的角色池） | 只进**提供人自己的私有库** |
| 别人能看/引用/写吗 | 能 | **不能** |
| 被提及的人能看到吗 | **能**（v2.4 铁律在此成立） | **不能**（新定） |
| 能分享吗 | 能 | **不能**（分享出去=已公开，天然排除） |

**三条定论：**
1. **默认私有**；公开要主动点一下。
2. **公开范围 = "这个故事的所有角色"**（故事里的人），不是公开给全世界。
3. **v2.4 铁律改为**：旧"看提到自己的那篇永不需要授权" → **改为"只在公开的篇里成立"**；私有库提到谁，不给谁看。

**价值**：保护"还没想好要不要说"的阶段——先写下来、锁着，想清楚了再公开。

### 1.3 【重点】 全局接口预埋（本条决定第1期就动工的事）

> **这是把"视角 + 公开/私有"落到代码上的关键。第1期虽然只做"能录进来"，但下列字段从现在起必须存在。**

**素材条目（每一条文字/语音/照片/视频/原声）必须带：**

| 字段 | 含义 | 第1期是否用 | 第3期用途 |
|---|---|---|---|
| `provider_id` | 谁放的 | 是 | 引用署名、归属 |
| `visibility` | 公开 / 私有（**默认私有**） | 是 | 决定进不进公共池 |
| `source_type` | 原创 / 引用 | 是 | 区分"我写的"与"引用的" |
| `ref_from_id` | 引用自哪条素材/哪个人 | 是（可空） | 标出处 |
| `ref_author_name` | 出处署名（**可能是称呼/笔名，非账号**） | 是（可空） | 引用段署名 |
| `story_id` | 挂在哪件"事"上 | 是 | v2.4 已有 |
| `time_*` | 时间线索（v2.4 §5） | 是 | 时间轴 |

** 铁律：第1期必须把这张表建对。第1期可以不用第3期那些逻辑，但字段一个都不能少——否则第3期回头撬接口，牵动整条链。**

## 二、数据主体模型

### 2.1 主体 = 故事，不是人（v2.4 保留）

**修正原因**：一个人一生很多故事，每段参与者不同。以人为中心会导致权限越做越绕。

```
故事「1979年那场大水」
   ├─  讲述人：李桂芳（老人）
   ├─  记录者：小李（女儿）
   └─  参与者：老王（被提起的人）
```

**v3.0 补充**：故事的参与者里，**每个人都可以是"一个视角"**——同一件"大水"，李桂芳讲一遍、老王讲一遍，**各自成立、互不覆盖**。

### 2.2 两个"加号"，位置决定权限（v2.4 保留）

| 加号位置 | 作用 | 可见范围 |
|---|---|---|
| **登录旁的加号** | 加**家人**（家庭通讯录） | 看**整本书**（全部故事） |
| **故事里的加号** | 加**这个故事的人** | 只看**这一篇** |

**铁律：权限由"从哪个入口加进来"决定，不设权限勾选框。** 老人不需要理解"权限"。

**v3.0 补充**：这是"可见范围"维度；**"公开/私有"是另一个维度**（见 §1.2）——两者正交，互不替代。

### 2.3 家人加入方式（v2.4 保留）
- 用**手机号**录入；对方已在小程序可直接**选名字**加入；加入后对方账号出现入口。

### 2.4 "有你的故事"入口（v2.4 保留 + v3.0 改）

被加入者登录后，首页出现提示：「**李桂芳的故事里提到了你**」

- 可点进去看（按权限）
- 可**补充自己记得的版本**（*只要能看，就能补充*）
- ** v3.0 改**：这条**只在"公开篇"成立**。**私有素材里提到你 → 不提示、不给看。**

## 三、双界面：标准版 / 大字版（v2.4 保留）

### 3.1 命名
**用"大字版"，不用"老人版"**——按功能命名，不按人。

### 3.2 进入方式
打开小程序 → 默认标准版 → 显眼入口【切换大字版】→ 随时可切回（全局切换）。

### 3.3 两版差别

| | 标准版 | 大字版 |
|---|---|---|
| 字体 | 正常 | **特大** |
| 首页 | 故事列表/成书/全部功能 | **就一个大按钮：按住说话** |
| 功能 | 全部 | 只留核心，其余收起 |
| 加人/设置 | 正常 | 藏在"更多"里 |
| 配色 | 正常 | **高对比度** |
| 反馈 | 常规 | 点按**有声音反馈** |

**核心原则：大字版里不用"设置/权限/分享"这类系统术语。**
- 术语会让老人懵。**功能要给，但话要用老人的话。**
- 【v3.0 修正】原"凡出现'分享'字样即为失败"这半句**只说了"不许用什么词"，没回答"那老人怎么把故事发出去"**——是个洞。v3.0 补齐：**分享功能保留给老人，只是换个说法，见下方 3.3.1。**

### 3.3.1 【定案 · v3.0】 老人怎么把故事分享出去

**两样都能分：**
- **整本书**能分（把成书记录发出去）
- **单件故事**也能分（老人常想炫耀的是"你看我写的这件"）

**两种方式（A + B）：**
- **A. 发给微信朋友**：老人最熟的就是微信转发（发到群 / 发给某个子女）——**按钮不叫"分享"，叫"拿给别人看"**
- **B. 做成一张图**：把这篇故事**生成一张好看的卡片图**（像小年糕那种），老人可直接发出去

**按钮命名铁律**：入口词**不叫"分享"**，叫 **"拿给别人看"**（避开禁词，说的是老人的话）。

**权限前提**：能分出去的，**只能是"公开"的素材/故事**（私有内容不进分享物，与 §8.2 一致：分享出去=已非私有）。

### 3.4 实现方式
**同一套代码，两套样式。** 【待验证】小程序全局字号缩放存 rpx 限制，须实机验证；做不到时可能退化为"核心页面大字版"。

### 3.5 【重点】 v3.0 补充：视角与公开/私有 在界面上的呈现要求
- 老人**不需要理解"视角"**这个概念，但需要一个**看得懂的开关**决定"这段给不给大家看"。
- 设计原则：**默认私有**，界面上给一个**直白的"公开"动作**（如"这段也给家人看"），**不用"权限""可见性"这类词**。
- 具体交互留到原型图阶段定 →【留口·界面】。

## 四、核心流程（用户视角）

老人按住说话 / 打字 / 传照片 / 传视频
        ↓
归入某件"事"（素材挂在同一件事上）
        ↓
**决定这段"公开/私有"**（v3.0 新增一步，默认私有）
        ↓
系统按时间轴自动排序（1980年归1980年，1937年归1937年）
        ↓
老人可手动调整 / 用语音纠正"这事是1937年1月的"
        ↓
点【我要成书】→ 先出电子书（必有）
        ↓
**成书时：自己的素材自动装入 + 公共素材点选装入**（v3.0 新增）
        ↓
电子书可分享、可续看、可续添
        ↓
满意后 → 再选择是否印实体书 → 印刷厂 → 邮寄到家

## 五、时间轴（灵魂功能）

### 5.1 自动归位
- 用户**不按时间顺序说话**是常态；系统需从**语音内容**和**文字内容**中提取时间线索，自动归位。
- **保存即触发**排序调整。

### 5.2 提取算法（三类线索）

| 线索类型 | 例子 | 处理 |
|---|---|---|
| ① 显式年代 | "1937年""六十年代" | 直接识别 |
| ② 历史事件 | "文革""包产到户""闹饥荒" | 映射到年代区间 |
| ③ 人生锚点 | "我八岁那年""嫁过来第二年""老大刚会走" | 用已知年份反推 |

### 5.3 人生锚点表
出生年 → 上学年 → 工作年 → 结婚年 → 生老大 → 生老二 → 退休年
- 一旦采到，后续所有"我八岁那年"类表述可**自动换算**。
- **采访中应有意自然询问**（"您是哪年结的婚呀？"）——不是闲聊，是给时间轴打地基。

### 5.4 保命线：不猜
**无法判定时标"时间待定"，不瞎猜、不归错位。** 归错比不归更糟。

### 5.5 手动调整（v2.4 定型）
**入口在时间轴上**——时间轴每一段后面挂**「改时间」三个字**（主入口）；长按为辅。
- 点段=看这段故事；点「改时间」=改时间。
- 不做小铅笔 （太小点不准）；不另放故事页按钮。

**点了「改时间」之后**：语音第一（自动播放问句，老人只用嘴说）+ 「自己选」大字号年份滚轮兜底 + 模糊时间**原样保留不凑整**。

**原则：语音优先，永远留退路。**
【待验证】老人对"改时间"语音问句的真实反应，须真机找老人试。

## 五之二、时间与故事的关系（v2.4 保留）

### 5之二.1 时间是排序维度，故事是归属维度（两者独立）

| | 干什么 | 谁用 |
|---|---|---|
| **时间** | 决定**排在哪**（排序） | 时间轴 |
| **故事** | 决定**跟谁一组**（归属） | 内容 |

**时间轴是目录，故事是章节。**

### 5之二.2 铁律
- **同一时间点允许多个故事**；一说年份 ≠ 归入某个故事。
- 时间精度分级：**年/季/月/模糊**；**精度不同不影响排序**。

### 5之二.3 一段话含多个时间点
- 能明确切分 → 切成多个故事，各归各位。
- 紧密关联 → **询问老人是否算一件事，不替他决定**。
- 拿不准 → 切开，允许事后合并。

### 5之二.4 归类原则：宁可分错，不可错并
- **分错**（本该一件分两件）→ 可修，小错。
- **错并**（两件事并一件）→ 难修，大错。
- **合并损失 > 分离损失。**

### 5之二.5 系统怎么判断"是不是同一件事"
第1步抽时间 → 第2步抽主体 → 第3步比对已有故事（拿不准→新建；相似度高→提供候选由人确认）。
**后台关联度 = 助手不是判官；禁止全自动合并。**
【待验证】"抽主体判断是否同一件事"语义难度**高于**时间提取，非规则可解，须评估。

## 六、素材篮子（一条事，多种素材）

### 6.0 【定案 · v3.0】 入口布局：两门 + 各自的录法

**首页两个大门（平级）：**

| 门 | 名字 | 进去之后 |
|---|---|---|
| 门1 | **【我自己说】** = 自述 | 走"说话 / 写文字 / 拍照 / 拍视频"四种录法 |
| 门2 | **【让人问我】** = 采访 | 直接进**对话框**（AI问-老人答），**只有语音**（见 §七） |

- **为什么是两门**：老人"想有人问我"或"想自己想到啥说啥"，是**两种姿态**。做成两门，**进门即模式，不用先做选择题**。
- **层级要分清**："自述/采访"是**两种写故事的姿态**（上层）；"说话/写字/拍照/拍视频"是**自述里的录素材方式**（下层）。采访不套下层那四样。

---

**铁律：所有素材挂在"同一件事"上展示。**

| 素材类型 | 来源 | 说明 |
|---|---|---|
| 文字 | 老人自己写 / 语音转文字 | 原声可保留 |
| 语音 | 按住说话 | **保留原生声音**，不只是转文字 |
| 照片/视频 | 老人手机图库 / 子女图库 / 故事里的人图库 | "+"号 → 跳图库 |
| 视频 | 当场录 / 相册传 | 对着手机说话的视频也算 |

### 6.1 【重点】 v3.0 补充：素材的"来路 + 公开/私有"（对应 §1.3 接口预埋）

**每条素材入库时，必须记录：**
- **谁放的**（provider_id）
- **公开还是私有**（visibility，**默认私有**）
- **原创还是引用**（source_type）
- 引用的话，**引自谁**（ref_from_id + ref_author_name，名字可以是称呼）

**第1期要求**：字段建齐。界面上**至少要能让提供人选择公开/私有**（否则第1期录进来的东西没有归属性，第3期补不上）。

### 6.2 上传交互（照微信做）
- 一个"**+**"号 → 直接跳手机图库；选项样式参照微信发消息：上传照片？视频？拍一个？
- v3.0 补充：传照片/视频要**既能现场拍、又能从图库选**；授权被拒需"教您开权限"按钮。

### 6.2.1  v3.0 新增：素材只由"本人"入库，系统不做"替人代放"（sandy 拍板）

**规则：素材只由"最终拥有它的人"自己放进小程序。别人手里的照片，走微信原路转给他，由他本人入库、本人决定公开/私有。**

**通道（示例：女儿手机里有妈的老照片）：**
```
女儿微信直接转给妈
   ↓
妈保存到【手机相册】（不是小程序里的私有库）
   ↓
妈打开小程序 → 点"+" → 从相册选这张
   ↓
妈当场选【公开 / 私有】
   ↓
入库
```

**为什么这样定（写下来，防将来被"优化"掉）：**
- **保住"谁放的 = 谁做决定"**：若女儿能直接替妈放，该条素材 provider_id 就是女儿，**妈的公开/私有决定权被架空**。走微信原路转，照片最终由**妈自己**放进来 → 妈说了算。
- **少一整条通道**：不需要开发"替别人放素材"的功能。女儿与妈之间用微信自己传，**系统不碰这个环节**。
- **与"公开/私有"闸门严丝合缝**：素材入库时，**放的人当场决定公开还是私有**。
- **推论**："子女代放"这条原【留口】**直接取消**（此方案使其不存在）。

【留口·界面】"+"号进来后，选公开/私有的界面怎么给（不出现"权限"字），留原型阶段定。

### 6.2.2  v3.0 新增：语音"两边都要"——留声为主、留字为辅（sandy 拍板）

**背景**：老人语音写的内容，是"直接转录"还是"录音再转录"？——**答案：两条都要，以"录音再转录"为主。**

| 项 | 做法 |
|---|---|
| **主资产** | **原生声音**，一定存（老人的声音本身就是记忆的一部分，感情资产） |
| **文字** | 从声音转出来，**后台存着**，用于：时间轴提取、检索、将来成书 |
| **给老人看什么** | 只给"在录"的动效（波纹/计时），**不显示转出来的错字**（老人口音致ASR错，看到错字会受挫） |
| **错了怎么办** | 第1期**不给老人改文字**；用**声音回放**确认（不用错字确认） |
| **接口要求** | **声音 + 文字两条都存**，接口必须都支持 |

**第1期不做"边录边显示文字"**：显示的必然是错字，给老人看的错字是伤害不是帮助。老人看到的=一个大波纹/计时器，知道在录就行。

### 6.2.3  v3.0 新增：回放按钮（sandy 拍板：给）

- 定位：**给，但不是必须**（多一个按钮多一分复杂，故不做成强制流程，只做一个可点的入口）。

### 6.3 拍板确认
- **谁传**：老人自己 + 子女 + 故事里的人——**凡有这篇故事权限的人都能添**。
  - 【重点】v3.0 收紧：**"添"=在自己名下添；素材只由"本人"入库，不做"替人代放"（§6.2.1）**。
- **视频来源**：当场录 + 相册传。

## 七、采访引导（AI 当主持人 · 含"可打断"硬要求）

> v3.0 大改：本节由 v2.4 老版（只有"AI当记者+可打断"）**升级为完整形态**。
> 依据 = sandy 2026-10-09 口头拍定；后端已就绪：`backend/interview_api.py`（6 接口，自测 37/37），
> 接口定义见 `docs/事卷/接口定义_采访引导v1_20261008.md`。

### 7.1 【定案】 采访 = 独立入口（第二个门，与"自述"平级）

- 采访**不是**"自述里的二选一子模式"。若塞进自述，老人点进去要先做一道选择题（"你自己说？还是让AI问？"）——**多一道选择题 = 麻烦**。
- **独立入口**：老人想"有人问我"就进采访这个门；想"自己想到啥说啥"就进自述那个门。**进门即模式，不给老人加选择题。**
- 首页两门：**【我自己说】= 自述** ｜ **【让人问我】= 采访**。（见 §六入口布局）

### 7.2 形态 = 对话框式一问一答（采访里只有语音）

- 进门即**对话框模式**：AI 问 → 老人答 → AI 问 → 老人答，来回聊。
- **采访里不套"写字/拍照/拍视频"那套**（那是自述的方式）；采访的输入方式**只有语音**。
- **AI 当主持人**：按**人生锚点**（出生 → 工作 → 结婚 → 生娃 → 搬迁）顺序发问，帮记性不好的老人把回忆勾出来。
- **目的**：很多老人记不清，**有人一问一答地提，他就能想起一些事**——这是采访存在的核心理由。

### 7.3 【重点】 打断纪律（硬要求 · 双向）

| 细节 | 要求 |
|---|---|
| **打断要快** | 老人一出声，AI **立即停**，不再往下讲（延迟须真机测，不得凭印象承诺） |
| **被打断就不许再讲** | AI 话没说完被老人打断 → **直接停，不要再一直讲下去** |
| **老人讲时AI不插话** | 老人讲的时候，AI 不许说话；**等老人讲完，才轮到别人说** |
| **打断不丢话题** | AI 记住刚才问的那句，老人说完**先接回再接别的**（`interrupted_question` 回填） |
| **AI 主动让路** | 每问完一句要留等待（`wait_ms`），不连珠炮 |
| **允许跑题** | 老人说别的，AI 顺着走，不硬拉 |

- **一句话铁律：谁在讲谁为主，两边都守。**
- 【待验证】录音/播放切换系统级延迟**能否压到1秒需实机测量**。**第2期验收硬项。**

### 7.4 【定案】 成品里只有老人讲的内容，没有 AI 的问句本身

- **老人讲的才是故事主体。** 采访成品 = **老人说的话**，**不含 AI 的问句本身**。
- AI 的问句只是**"帮老人想起事的工具"，用完即弃**——它是脚手架，不进入作品。
- 但"只留答、不留问"会**连不成故事**（问句是串联的钩子）。故由下一个动作解决 ↓

### 7.5 【定案】 AI 把老人答的内容"理顺成自述体"

- AI 把一问一答的碎片，**整理成一段流畅的"自述体"**（形态=像自述，不是问答记录）。
- 这一步是**成品形态的统一器**：无论老人是自己说（自述）还是被问（采访），**最终呈现都是自述体**。

### 7.6 【定案 · C 方案】 复述确认 + 归属确认 = 合成一次

- **AI 把理顺后的内容，用语音"报"给老人听**（"您刚才说的这件事是这样：1…2…3…4…"把老人说的复述一遍）。
- **顺便一起问归属**（"是上面那件事吗？"）——**一次问完，少折腾老人一次**。
- 老人**觉得可以 → 确定**。（老人用**耳朵验收**，比看字靠谱。）
- **决策口径**（承接 §7.7 安全默认）：任何反应都不算错，含糊/超时 → 默认安全侧，绝不卡住老人。

### 7.7 归类决策（v2.4 保留口径，决策表见接口文档）

**背景**：自述页没有记者在场，老人自己闷头说，说完归到哪去？采访页同理。
**分两步走：**
- **第1期（先能用）——不问，只留小标**：保存完 → 系统按最可能归位 → 不打扰老人；留一行大字小标「这段还在 1980年5月，要挪个位置吗？」。子女端有"待确认归类"提示区。
- **第2期（真机试后评估）——语音问 + 大字按钮兜底**：语音优先；说"嗯/对/好"→默认新建（安全侧）；5秒无反应→浮出两个超大按钮；始终无反应→默认新建。**任何反应都不算错，永远有安全默认。** 频率保护（防烦）。

【待验证】"老人对语音提问的真实反应"**完全无数据**，须真机找人试。**第2期验收项。**

### 7.8 【定案】 采访里浮"+"号（可补照片/视频）

- 采访对话框里**某处浮一个"+"号** → 点进去**能放照片、能放视频**。
- 采访主体是"问-答"语音，但**不封死补图**，留此口子。
- **补充素材一律先进"私有"**；素材**旁边放一个"公开"键**，老人想公开自己点（与 §6.1"默认私有"一致）。

### 7.9 【定案】 编书时再补照片/视频

- 采访环节**只出文字**（老人语音 → AI 理顺成文）；**照片/视频的补充，主要在"编书"环节**（见 §八）。
- 编书时老人可**往故事里自己再加照片、加视频**。
-  **一律先私有**：编书时补进的素材**同样默认私有**，旁边给"公开"键。（"进来自动都是私有"——sandy 原话）

### 7.10 【对接】 后端现状

- **已就绪**：`backend/interview_api.py`，6 接口（start / next / barge_in / ask_classify / classify_answer / pref），自测 **37/37 全过**。

## 八、成书机制

### 8.1 【重点】 成书顺序（铁律）
点【我要成书】→ 先出**电子书**（必有）→ 看电子书 → 满意 → 再决定是否印**实体书** → 选开本/装帧 → 印刷厂 → 邮寄到家
- 电子书=0成本、秒出、能改；实体书=花钱、改不了、后置慎重。

### 8.2 【重点】【重点】 v3.0 新增：成书的"两筐素材"（核心机制）

**点【我要成书】时，书里的素材来自两筐：**

| 筐 | 内容 | 装法 |
|---|---|---|
| **① 自己的素材** | 我放的（无论公开/私有） | **自动**按时间顺序装入 |
| **② 公共素材** | 别人公开的、与我这本书相关的 | **点选**要不要装（不一定全装） |

**为什么要分两筐**：
- 自己的一定要进（是我的书）；公共的**给不给是"我"的权利**——别人写我，我**未必要收**。
- 这就是 v2.4 说的"成书时主角有收录权"的**具体落地**。

**规则：**
- **引用段独立标记**：装进书里的公共素材，凡引用别人的话，**标明出处**（"这段来自张大叔的讲述"）。
- **引用段不可改**（对应 §1.1 原则4）。
- **署名**：这本书署**"我"（发书人）**；引用段列出贡献者/出处。

### 8.3 【重点】 v3.0 新增：这本书的"我"是谁
- **谁点【我要成书】，谁就是这本书的"我"。**
- 甲的书里主角可以是邻居，但书里的"我"始终是甲。
- **系统不需要转换人称**——甲写的用甲的"我"，引用段标明是"张大叔说"，各归各位。

### 8.4 电子书
- 生成后可**分享**、可继续看、可往里再添内容。**成书不是终点，是活文档。**

### 8.5 实体书
- 对接印刷厂（sandy 联系，多家比价）；印刷厂决定页数/开本/装帧；印完邮寄到家。**现在不用决定。**

### 8.6 书的形态（三种都要）
书的形式（翻页）/ 手机端阅读 / 翻相册式。
**设计追求**：线上看到什么样，印出来就什么样 → 省排版。
【待验证】完全免排版的可行性边界，技术侧评估。

## 八之二、分享机制（v2.4 保留 + v3.0 收紧）

### 8之二.1 sandy 原话
> **"一种是有故事，我直接分享故事给你看；一种是没有故事，但我觉得这个很好玩，分享给朋友看。"**

### 8之二.2 两种分享对照

| | ① 有故事 → 分享故事给你看 | ② 没故事 → 觉得好玩，分享给朋友看 |
|---|---|---|
| 手里有什么 | 一篇故事 | 没有故事，只有"这东西好玩" |
| 分享的是什么 | **那一篇故事** | **小程序本身** |
| 收到的人看到什么 | 直接看到这篇故事 | 引导页（"给你家老人也做一本？"） |
| 他接下来做什么 | 加进来，说说他记得的版本 | 自己开一本 |
| 登录时机 | 看完之后、想加进来时 | 想开始时 |
| 典型场景 | 老人把老伙计写进书 → 转给他"你看我把你写进去了" | 子女用着好 → 转同事"你也给你妈做一个" |

**共同点：都是先看，后登录。看不用登录，参与才登录。**

### 8之二.3 【重点】 v3.0 收紧：分享只管公开素材
- **"我分享出去，证明它已经不是私有了"**（sandy 原话）。
- 分享机制**天然只作用于公开素材/公开篇**；私有素材**不进分享通道**。
- 这条**不需另定规则**，它是从"公开"定义里自动长出来的。

### 8之二.3.1 【定案 · v3.0】 老人自己分享的入口（衔接 §3.3.1）
- **老人自己也能分享**（不必等子女代劳）；入口在**大字版也保留**，但**按钮不叫"分享"，叫"拿给别人看"**。
- **能分什么**：整本书 + 单件故事，都能。
- **怎么发**：A 发给微信朋友（微信转发）／ B 做成一张好看的卡片图。
- **前提**：只能分"公开"的内容（与上方 §8之二.3 一致）。

### 8之二.4 分享的技术形式
| 方式 | 门槛 | 说明 |
|---|---|---|
| **转发小程序卡片** | 最低 | 主力方式 |
| **二维码** | 高 | 微信外/面对面/印在实体书封底 |
| 网页链接 | —— | 小程序没有网页链接 |

### 8之二.5 情况①：有故事，分享故事给你看
老人/子女选一篇故事 → 点【分享给朋友】→ 微信转发卡片 → 对方点开直接读（**不用登录**）→ 篇末「这是李桂芳的故事，里面提到了你 [ 我也加进来 ]」→ 点按钮 → 微信一键登录 → **默认加入"这一篇"**。
- **被提一句的人，只看这一篇，不看全本**——**不需要任何授权**（张三写故事时加他进来=已同意他看这篇）。
- **只有一种情况要授权**：他想看**全本**。

### 8之二.6 情况②：没有故事，觉得好玩
子女点【分享给朋友】→ 卡片是产品本身 → 对方点开看到引导页 → 点【开始】→ 登录 → 开自己的故事。

### 8之二.7 情况③：没被分享，自己找上来
张三把老李写进故事（老李还没上过） → 老李从别的渠道自己注册 → 一进去看到「有 1 篇故事提到了你」→ 点进看完 → 可补充自己的版本。

**系统怎么知道"这篇提到了他"**：
| 环节 | 做法 |
|---|---|
| 张三加老李时 | 老李可能还没账号 → 先按**手机号/名字**登记为"待认领" |
| 老李后来注册 | 用**同一手机号**登录 → 自动**认领** |
| 认领成功 | 首页出现「有 N 篇故事提到了你」 |
| 手机号对不上 | 提供**按名字搜索认领**（张三那边可确认） |

- ** v3.0 改**：**"待认领"只认公开篇里提到的人**；私有库里提到的人**不登记、不提醒**（否则=泄密）。

### 8之二.8 登录点与铁律
| 场景 | 登录时机 | 位置 |
|---|---|---|
| ① 收到故事的人 | 看完后、想加进来时 | 故事页底部按钮 |
| ② 被推荐来玩的人 | 想开始时 | 主页"开始"按钮 |

- **通用原则：看不用登录，参与才登录。**
- ** v3.0 改（红线）**：被提及者权限——"看提到自己的那篇**永不需要授权**"，**改为：只在公开篇里成立**；私有篇不给看。
- 分享有效期：暂**不设期限**。
