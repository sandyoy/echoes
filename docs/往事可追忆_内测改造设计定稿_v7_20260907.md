# 「往事可追忆」内测真机问题 → 改造设计定稿

> sandy 2026-09-07 真机实测反馈 + 本人点头确认方向"整体没问题"。
> **本文件是两端统一标准**：小龙虾负责前端改造+出码，小鲸鱼负责配合后端/ASR/对话能力。任何一端改前先回看此稿，避免跑偏成两套。

## 反馈的 5 个核心问题 & 改造方向

### 问题1｜自述"按住说话"没有文字框确认保存（sandy认可此方向）
**现状**：按住说话→松手→静默ASR→自动保存。ASR失败就降级成 `[语音回忆X秒]`，无文字。
**改造**（"一段回忆=语音+文字双份"):
- 按住说话 → 松手 → 弹**可编辑文字框**，实时显示识别结果
- 框下两钮:【改一改再存】【直接保存】
- 改完/不改 → 保存成 type='audio' 的回忆：正文=文字(content)，另存可播放的 audioPath
- ASR 失败时框仍弹出、预填空或短占位，绝不静默丢内容

### 问题2｜AI采访不是"可打断的一问一答"
**现状**：录音转文字→发送→DeepSeek返回，无实时语音对话、不能打断。
**改造**（先做"能自然停断、可打断"这层，非完整豆包级实时流）：
- 用户说话/打字 → AI回答期间，用户可再次直接说话或打字**打断/追问**
- 保证"用户说完停顿 → AI才接"，用停顿检测/手动结束明确过渡
- 采访中每一句结束可即时"另存为回忆"，不再整段一次Save

### 问题3｜采访页录音喇叭卡死（bug，必修）
**现状**：点喇叭进入录音即卡死，无停止钮，退不回打字，只能杀小程序。
**改造**：
- 录音进行中显示专门【停止】按钮（非状态toggle），一点即停并回到可输入态
- 录音状态与 toast/取消上滑的手势逻辑理顺，绝不允许出现"无出口"状态
- 加录音最长时间保护

### 问题4｜时间轴仍全挤"今天"（无真实年份）
**现状**：存 date 恒为 getTodayDate()，想记旧事也只能落今天。
**改造**：
- 保存流程增加"这是哪年的事?"引导——默认今天，但让用户可快速选/填一个大概年份
- 回忆按所选年份归档进时间轴，形成真实编年

### 问题5｜手输"保存"、采访"发送"点了没反应（待真机复现定位）
**现状**：代码逻辑上 submitType 能存、sendMessage 能发，但 sandy 实测"没反应"。
**改造**：
- 小龙虾先**真机复现**，定位是授权/网络/拦截器/回调哪一环，不猜
- 修到"点击必有可见反馈(成功toast 或 错误提示)"，杜绝静默无反应
