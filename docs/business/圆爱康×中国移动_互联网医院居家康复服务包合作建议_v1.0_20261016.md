## 写在前面：这份建议解决什么问题

广东移动正在为省内医院建设互联网医院、智慧医院——**平台建起来了，网络通了，系统上了**。

但一家医院真正看重的，往往不是"我有没有这套系统"，而是——

> **"这套系统上线之后，有没有持续在跑的医疗服务？有没有实实在在的服务收入？患者愿不愿意用？"**

平台的空转，是互联网医院项目最常见的难题。系统交付那天是项目的顶点，之后逐年变成"运维成本"，而不是"收入来源"。

**这份建议要谈的，就是往这个"壳"里装什么东西。**

我们建议：**在互联网医院的架构下，挂载一个"居家康复服务包"模块。**

- 移动提供：互联网医院平台 + 网络 + 运维服务（**原有业务，继续按现有方式向医院收费**）
- 圆爱康提供：居家康复的**设备、系统、专业执行团队**（**整套能力已成熟，可直接装入**）
- 医院提供：**执业医师开具康复方案的医疗主体职责**（院内角色不变，无需新增投入）

装进去之后，移动向医院交付的就不只是一套系统，而是**一个能持续产生服务费流水的业务模块**。

## 一、为什么是现在

### 1.1 政策已经把"居家康复"写进国家文件

过去两年，"医院—社区—居家"三级联动从一句号召，变成了有具体文件、有量化目标的国家部署：

| 文件 | 关键表述 |
|---|---|
| **《医疗康复护理扩容提升工程实施方案》**（国卫规划发〔2026〕24号，国务院批复） | **"探索医疗卫生机构、社区、居家有效联动的康复护理模式"**——"医院—社区—居家"三级联动首次写入国家级实施方案；明确支持基层"配置适合家庭病床服务的便携式设备，拓展社区、居家康复护理等延伸功能" |
| **《关于加快建设分级诊疗体系的若干措施》**（国办发〔2026〕11号） | "上级医院要主动为**恢复期、康复期**等的患者提供**下转服务**"——**下转成为政策硬指标** |
| **《关于加快推进康复医疗工作发展的意见》**（国卫医发〔2021〕19号） | "积极发展社区和居家康复医疗……通过'互联网+'、家庭病床等方式将机构内康复医疗服务**延伸至社区和居家**" |
| **《互联网诊疗管理办法（试行）》**（国卫医发〔2018〕25号）及配套监管细则 | 互联网诊疗的**合法边界**：由持证医疗机构提供、本机构注册医师执行、适用于明确诊断的慢病复诊 |

**一句话总结政策面：**

> 该不该做——**国家明确鼓励**；
> 能不能做——**互联网诊疗有法可依**；
> 谁来做——**医院承接到家、平台提供入口，正是政策指向的方向**。

### 1.2 医院侧的真实诉求正在变化

2026 年以来，公立医院管理者面对的是这样的局面：

- **分级诊疗"控三"** ——三级医院被要求逐步酌减病情稳定慢性病的普通门诊，恢复期患者要**主动下转**
- **下转之后没人接** ——转下去的患者，社区接不住、家庭更没有承接方式，**患者体验断裂、医院口碑受损**
- **互联网医院"建而不用"** ——平台上线后缺乏可持续的业务模块，逐渐沦为成本项

**"居家康复服务包"恰好回答了这三个问题**：它让医院**下转有去处、患者有承接、平台有业务、服务有收入**。

### 1.3 这个窗口期有时限

政策密集落地期，正是各地医院集中规划、集中采购"康复护理扩容"相关项目的窗口。**《扩容提升工程》明确要求"一城一策"，优先在城区常住人口100万以上的城市落地。**

**现在进入，是站在政策窗口的前半段。**

### 1.4 钱从哪来：患者自费

**本服务包是患者自愿选择的自费服务，不走医保、不涉及任何保险支付。**

这一点需要说透，因为它是这个模式**定价空间**的来源：

- **不走医保，就意味着不受医保定价约束**——服务包的价格、内容、周期由市场决定
- **服务的价值由患者直接感知与判断**——患者愿意为"在家把这几个月康复做完、不用反复跑医院"付费
- **对医院而言，这是完全独立于医保体系之外的一块业务**——不占用医保额度、不影响DRG付费、不与院内任何医保项目产生关联

> **一句话：这是一门"让患者愿意自己掏钱买"的生意——它的天花板在于我们能提供多少患者真正认可的价值，而不在于政策给多少钱。**

**这也决定了我们的重点必须放在一件事上：把服务做到患者愿意自费购买的程度。**

## 二、圆爱康与「智慧家康模式」

### 2.1 我们是谁

**广州圆爱康生物科技有限公司**——一家专注**居家康复服务模式设计与运营**的公司。

我们提出并持续实践**「智慧家康模式」：一套把医院各专科的专业治疗能力延伸到患者家中的居家康复服务管理模式。**

**不派人上门施治**——治疗在患者家中由患者按医嘱完成，我们提供设备、系统与专业团队的远程支持。

**已在多家医疗机构、多个专科方向落地**，形成可复制的做法。

### 2.2 模式的五个组成要素

| # | 要素 | 一句话 |
|---|---|---|
| 1 | **医疗级家用设备** | 把院内同款治疗设备放进患者家中 |
| 2 | **院内—居家治疗闭环** | 院内开具 → 居家执行 → 数据回传 → 医师随访调整 |
| 3 | **六师共管** | 医生（院方）＋康复师（院方）＋护士（院方）＋线上客服＋线下督导＋设备工程师（我方），**6 个角色分工协作，不是 6 个人围着患者转** |
| 4 | **医院主导 · 第三方赋能** | 医疗主体是医院，诊疗服务由医院提供；圆爱康作为辅助方，提供设备、系统与运营支持 |
| 5 | **标准化可复制** | 设备形态、闭环流程、角色分工均可复制——一家医院跑通，可平移到另一家；一个专科跑通，可复用到其他专科 |

### 2.3 已覆盖的专科方向

妇产 · 泌尿/盆底 · 心内 · 神内 · 骨科 · 胃肠 · 儿科心理……**医院各专科的离院治疗患者，都是服务对象。**

> **跨科室适用是我们模式的一个特点**：同一套能力，可以服务多个科室的患者。这意味着**一个模块可以打开医院内部多个科室的服务入口**。

## 三、合作形态：互联网医院里的「居家康复服务包」模块

### 3.1 整体架构

```
┌─────────────────────────────────────────────────────────┐
│              医院（医疗主体）                             │
│   执业医师开具方案 · 阶段性复评 · 院内诊疗职责不变          │
└────────────────────┬────────────────────────────────────┘
                     │
      ┌──────────────┴──────────────┐
      │                             │
┌─────▼─────────────┐    ┌──────────▼──────────────────┐
│  互联网医院平台     │    │   居家康复服务包（挂载模块）    │
│  （中国移动提供）   │◄──►│   （圆爱康提供与执行）          │
│  · 平台与网络       │    │   · 居家康复设备              │
│  · 运维服务         │    │   · 服务包运营与执行           │
│  · 患者服务入口     │    │   · 六师共管专业团队           │
└───────────────────┘    └─────────────────────────────┘
                     │
                     ▼
              ┌─────────────┐
              │   患者/家庭   │
              │  在家完成康复 │
              └─────────────┘
```

### 3.2 三方分工

| 角色 | 做什么 | 不做什么 |
|---|---|---|
| **医院** | 医师开具康复方案、阶段性复评、院内诊疗 | 不新增床位、不新增人力投入、不改变既有诊疗流程 |
| **中国移动** | 互联网医院平台、网络与运维服务、患者服务入口（**"通道"角色**） | 不承担医疗服务与专业执行 |
| **圆爱康** | 居家康复设备投放、服务包运营、六师共管专业团队执行 | 不开具医嘱、不介入医疗决策 |

### 3.3 服务流程

| 步骤 | 内容 | 执行方 |
|---|---|---|
| **1 · 医师推荐** | 主治医师评估患者情况，适合者推荐居家康复服务包（属诊疗的一部分，不额外收费） | 医院 |
| **2 · 平台签约** | 患者在**互联网医院平台上**完成服务包签约与支付 | 平台 + 患者 |
| **3 · 居家执行** | 设备寄送入户；六师团队远程一对一指导；按医嘱完成治疗性训练 | 圆爱康 |
| **4 · 阶段复评** | 按周期回院复诊，医师评估进展、调整方案 | 医院 |

**关键：患者全程在互联网医院平台上完成签约与查询——这是移动平台的价值直接体现。**

### 3.4 为什么这个模块适合"挂"在互联网医院上

- **患者入口天然存在**：互联网医院已有患者注册、就诊、随访流程，服务包**挂上去即有人流**
- **平台价值被放大**：从"能挂号问诊"升级为"能承接康复需求"，**平台活跃度提升**
- **不需要医院做重投入**：不占床位、不加编制、不改流程，**决策阻力小**

## 四、商业逻辑：移动在这里赚什么

> **这是本建议最重要的一节。**

### 4.1 两层收入结构

**第一层：互联网医院运维服务费（已有业务，正交叠加）**

移动原本就在为医院提供互联网医院的建设与运维服务。**这一层不因本合作而改变**——合作后，移动交付的内容从"平台"扩展到"平台 + 一个持续运行的业务模块"，**在同一条服务协议下，交付价值提升，收费基础更牢**。

**第二层：居家康复服务包的服务费收入（增量）**

服务包上线后，患者通过平台签约付费。**服务包持续产生流水，逐年累积。**

### 4.2 与"项目制"收入的关键差别

| | 传统项目制 | 服务包模式 |
|---|---|---|
| 收入形态 | 一次性（建设费） | **持续性（按服务周期反复产生）** |
| 收入曲线 | 交付完即见顶 | **随签约量逐月累积** |
| 与医院关系 | 交付即结束 | **长期绑定、持续服务** |
| 对医院的说服点 | "你需要这套系统" | **"这个模块能带来患者留存与服务收入"** |

**移动在互联网医院这条线上遇到的普遍问题是"一次性的建设收入之后没有持续性收入"。**

**服务包模式正好补上这一环——让每一个上线的互联网医院，从"一个项目"变成"一条持续产出的服务线"。**

### 4.3 收入怎么分

**具体分成比例按双方约定执行**，建议在合作框架确认后，结合落地的医院数量、服务包规模与双方投入，逐项商定。

**结构上建议：**

- **第一层（运维服务费）**：维持移动与医院既有的服务协议，**本合作不改变**
- **第二层（服务包流水）**：按约定比例在**移动、医院、圆爱康**三方之间分配
- **结算方式**：月度对账、按实际完成服务的患者例数结算，票据清晰、可追溯

### 4.4 对医院怎么讲"钱"

医院侧的核心顾虑只有一个：**"会不会涉及新增医疗收费项目？会不会被审计？"**

**回答：不会。**

- 医院**不向患者新增收取居家服务包费用**，不涉及新增医疗收费项目、无需物价报批
- 医院获得的收入，来自**第三方支付的技术协作费**，走财务科目「其他收入 — 合作服务收入」
- 院内诊疗费、复诊费**照常按现有流程收取**，与居家服务包无关
- **患者只支付一笔院外费用（服务包），没有重复收费**
- **服务包属患者自费，不涉及医保、不占医保额度**——医院不必担心影响医保指标或DRG付费

> **一句话给医院**：*"您不用改任何收费项目，也不用向患者多收一分钱，更不占医保额度。院内该收的照收，居家这块由我们来运营，您获得的是技术协作费。"*

## 五、给一线的沟通要点

> 以下是我们与医院长期沟通中总结的**可直接使用的表达**，供一线参考。

### 5.1 开场怎么讲

> **"医院建了互联网医院之后，最怕的就是'建了没人用'。我们今天带的这个模块，就是让平台真正用起来的东西——把出院患者的康复需求，接到平台上继续做。"**

### 5.2 医院问"这跟我们自己做的康复有什么区别"

> **"不是替代，是延伸。院内该做的康复您照做，我们做的是患者出院以后那一段——那一段现在其实是断的，患者回家之后没人管。我们把这个断档接上。"**

### 5.3 医院问"我们要投入什么"

> **"不用新增床位、不用新增人员编制、不用改任何流程。医疗部分还是您的医师开方案、您来复评，医疗主体地位不变。设备、系统、执行团队都是我们的。"**

### 5.4 医院问"对我们有什么好处"

三条，按顺序讲：

1. **分级诊疗下转有去处** ——恢复期患者转得下去、接得住，符合政策要求
2. **患者不流失** ——出院后仍在您的服务体系内，复诊还是回您这里
3. **有服务收入** ——走「技术协作费」，不改任何医疗收费项目

### 5.5 医院问"别的医院做了吗"

> **"我们的模式已经在多家医疗机构、多个专科落地。合作意向确定后，我们可以提供具体案例与落地经验供参考。"**

### 5.6 医院问"合规吗"

> **"合规基础很扎实。互联网诊疗本身有《互联网诊疗管理办法》及配套细则；'医院—社区—居家'三级联动的康复护理模式已经写进2026年国家《医疗康复护理扩容提升工程实施方案》。而且**开方和医疗决策始终在您的医师手里**，我们只做设备、系统和运营配合。"**

## 六、合规边界（供移动内部把关）

| 事项 | 界定 |
|---|---|
| **谁开方** | 必须由合作医院的**执业医师**开具与执行。六师共管中其他角色**不参与、不介入医嘱开具环节** |
| **谁诊疗** | 医疗主体是医院，诊疗服务由医院提供；圆爱康作为辅助方，提供设备、系统与运营支持 |
| **适用场景** | 适用于**明确诊断的慢病与康复期**患者，符合互联网诊疗监管要求 |
| **收费性质** | 服务包属**患者自愿选择的自费服务，不涉及医保、不占医保额度**；医院**不新增医疗收费项目**，收到的是第三方支付的**技术协作费**，走「其他收入」科目 |
| **不做的事** | 不做上门施治；不做健康管理类泛服务；不把患者从医院手里接走 |

**这套边界已在圆爱康现有合作医院的协议中落地执行，可直接复用。**

## 七、建议的推进方式

### 7.1 不建议一步到位

**建议先用"单院试点"验证，而不是一次性铺开。**

**理由**：长流水模式的成立，取决于**医院认不认、医师用不用、患者接不接受**——这三件事只有跑一遍才知道结果。**先跑通一家，再复制。**

### 7.2 推进路径

| 阶段 | 内容 | 周期 |
|---|---|---|
| **第一步 · 选点** | 双方共同选定 1 家已有互联网医院的合作医院作为试点 | 1-2 周 |
| **第二步 · 三方对接** | 移动（平台方）+ 圆爱康（执行方）与医院三方沟通，确认落地方式 | 2-4 周 |
| **第三步 · 模块挂载** | 平台侧开通服务包入口；圆爱康完成设备与团队就位 | 2-4 周 |
| **第四步 · 试运行** | 单个科室先跑，检验全流程；月度对账、按例结算 | 1-3 个月 |
| **第五步 · 复制** | 试点跑通后，在同院其他科室、以及省内其他医院复制 | 持续 |

### 7.3 对移动的意义

**这个路径的特点是：起点低、风险小、可验证。**

移动**不需要为这件事单独立项、单独投入**——它是在现有的互联网医院业务上，**叠加一个已经成熟的模块**。

**跑通了，就是一条新的持续性收入线；跑不通，损失也仅限于一次试点的人力沟通成本。**
