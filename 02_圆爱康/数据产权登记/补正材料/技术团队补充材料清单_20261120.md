**为什么要这个**：深圳数据交易所 11-19 发来沟通函，提了 11 条问题，其中 5 条的答案在系统里，需要技术侧导数据或确认一句话。**11-19 函件给了明确期限，逾期登记申请会被终止，这次是一次性补齐。**
**什么时候要**：尽快，本清单发出后按「第一优先」先做前两项（全量机构清单、导出字段清单），这两项卡着其他稿子没法定稿。
**怎么做**：每一项都写了「要什么 / 长什么样 / 从哪来 / 给谁用」。**不需要看表名，按业务含义在系统里定位即可。** Excel 优先，导全量不要截断。
**不要做的**：不要改字段中文含义，不要自己判断哪些字段敏感而删掉——敏感与否由我们对审核方统一表述，你只需要如实导出。

| 列名 | 说明 | 示例 |
|---|---|---|
| 机构编号 | 系统内的机构编码（原样导） | 1405 |
| 机构全称 | 工商/事业单位登记全称，不要简称 | 珠海市妇幼保健院 |
| 所在省 | | 广东省 |
| 所在市 | | 珠海市 |
| 首次接入时间 | 该机构第一笔业务数据的产生时间，精确到年月日 | 2023-05-18 |
| 接入状态 | 在用 / 已停用 / 洽谈中（三选一） | 在用 |
| 数据条数 | 该机构产生的业务数据记录数（**不含日志**） | 128,430 |

**从哪来**
按机构维度统计业务数据的量。如果「数据条数」一次跑不出来，就先交前 6 列，第 7 列我们另说。

**特别注意**
- **必须全量，不许截断。** 上次交上去的是第 55–135 段，审核方正是从截断的片段里看到郑州、昆明的机构，才质疑我们「填广东省、却有省外数据」。这次要全表。

- 如果机构名称有变更（改名、合并），按现行全称导，备注里可以不写。

**给谁用**：答第 2 条（地域范围）。我们要算两件事——①省外机构一共几家；②这些机构的数据条数占全局的比例。占得极低就维持「广东省」，占得高就要改口径。

### 材料 2 · 导出数据集的最终字段清单

**要什么**
上次我们提交给数交所的《数据字典》里一共有 10 张业务表，这次要在这份字典的基础上，逐字段标一行「这个字段会不会进入对外导出/登记的数据集」。

**长什么样**（Excel，一表，列固定这 6 列）

| 列名 | 说明 |
|---|---|
| 业务表中文名 | 用业务含义写，例如「用户治疗方案」「治疗处方明细」「评估报告」「评估原始曲线数据」 |
| 字段英文名 | 系统里的原字段名，原样抄 |
| 字段中文含义 | 沿用数据字典里的说法，一个字不要改 |
| 数据类型 | 原样 |
| 是否进入登记数据集 | 填「是」或「否」 |
| 不进入的原因 | 只在填「否」时写，例如：含姓名、含手机号、含身份关系、含聊天正文、含网络地址、内部运维字段 |

**从哪来**
照《数据字典》的 10 张表逐张过一遍，字段数一共约 200 个，一小时能标完。判断标准很简单：**能直接或间接指向"某个具体的人"的字段 → 否；纯业务过程数据（时间、时长、参数、分值、设备号、疗程进度）→ 是。**

**特别注意**
- 这张表是给审核方看的，会随函提交，**所以列里不要出现内部表名**（用业务表中文名即可）。
- 拿不准的字段不要自己拍，标「待定」并在备注写一句你的疑问，我们一起定。
- 这张表同时是我们答第 4 条（uid 属去标识化个人信息）的核心证据，字段标得越干净，这一条越好过。

**给谁用**：答第 4 条 + 支撑《脱敏与字段隔离技术说明》。

### 材料 4 · 设备侧采集数据的生成方式说明

**要什么**：一段话（200 字以内）+ 一份字段级说明。说清三件事：
1. 康复评估的分值（前静息、快肌、慢肌、耐力、后静息五项得分）是**设备原始信号算出来的**，还是**人工填的**；

**长什么样**：一段话 + 一张两列小表（「数据项 / 生成方式」）即可，不用导数据。

**给谁用**：答第 5 条（我们漏勾了「衍生创造」这一项数据来源）。要证明"这些结论是我们系统按固定规则算出来的、可复现"，就必须先说清算法链路的起点在哪。

### 材料 6 · 2024 年 7 月以前的数据是什么

**要什么**：说明 2022-06 到 2024-06 这段期间的数据，业务上是什么形态。

**要回答的四个问题**（一句话一个）：
1. 这段期间的数据，是同一套居家康复系统产生的，还是早期设备销售/试用产生的？
2. 和 2024-07 以后的数据，**在不在同一套表结构里**？（这决定我们能不能按时间一刀切开）
3. 如果不在同一套结构里，早期数据现在存在哪（独立库 / 归档表 / 已停止写入）？
4. 早期数据里有没有单独的患者同意记录（纸质或电子）？

**为什么要问**：我们要把登记时域起点从 2022-11 退到 2024-07-01，理由是早期数据的知情同意证据链不完整。这段说明写不好，审核方会认为我们在"挑对自己有利的时间段"，这段说明写好了，反而是我们主动收缩范围的诚信表现。

**给谁用**：答第 3 条（历史数据范围）。

### 材料 8 · 系统由我司建设与运维的书面确认

**要什么**：技术负责人签字的确认表，下面 8 条逐条打勾（是/否）。这些是审核方判断"你们是数据权属方，还是只提供技术服务"的唯一依据。

**已核实即可，不必勉强**：第 8-6 条已由我方确认为事实——全量数据调取仅技术团队可执行。技术同事只需在其上签字或回邮件确认，作为留存依据。

| # | 事实 | 是/否 | 备注 |
|---|---|---|---|
| 8-1 | 居家康复与服务协同系统由我司自主开发，合作医疗机构不参与系统建设 | | |
| 8-2 | 合作机构在其自有公众号、网络医院或客户端设置入口，患者经院方标识页进入「智慧家康」系统；进入后的评估、治疗执行、随访等全部服务环节，均在我司系统内完成 | | |
| 8-3 | 业务数据存储于我司自有或租用的境内服务器，我司未向任何合作机构开放数据库直连或后台管理入口 | | |
| 8-4 | 系统账号、机构接入、角色与权限配置均由我司开通、变更与回收 | | |
| 8-5 | 机构账号仅可查看本机构服务患者的业务页面记录，并仅可对**单笔业务单据**进行单次导出（供院内归档） | | 若存在批量导出功能，请注明在哪、谁能用 |
| 8-6 | **全量数据导出、批量下载及多环境数据调取，仅由技术团队在受控环境下按审批流程执行**（已确认事实） | 是 | 请补充：由谁审批、是否留记录 |
| 8-7 | 数据的备份、清洗、结构化加工与质量校验由我司执行 | | |
| 8-8 | 康复效果评估、疗程完成度、治疗依从性等结论字段，由我司设计的算法规则生成 | | |

**为什么单独把 8-5 和 8-6 拆成两条**
医院能单次导出单笔单据，这是事实，我们必须在函里如实写——不写，审核方一核验就变成"隐瞒"。但真正的控制权在**全量出口**：要全量必须找我们技术人员，这才是"数据由我们控制"最硬的证据。两条一起写才完整：先说能看能单次导（承认现状），再说全量在我司手里（证明控制）。

**为什么要问**：审核方质疑"你们到底是数据权属方，还是只提供技术服务"。这 8 条就是"数据由我司系统持续采集累积形成、由我司事实控制"的全部依据，**任何一条打不了勾，都要提前告诉我们，我们改口径**，不要硬勾。特别是 8-6，如果实际上运营或客服也能一键导出全量，那这条要改写法，不能照抄。
