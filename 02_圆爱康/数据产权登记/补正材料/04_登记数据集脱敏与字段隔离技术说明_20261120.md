**申请主体**：广州圆爱康生物科技有限公司
**对应申请**：DJ202609230003
**数据集**：广东省居家康复治疗与服务协同数据集
**编制日期**：2026-11-20
**编制依据**：技术部门 2026-11-20 提交《字段清单》（10 张核心表全字段 + 是否进入登记数据集标注）

---

## 一、说明目的

应深圳数据交易所《数据产权登记事宜沟通函》要求，就本次登记数据集的个人信息属性、脱敏处理方式、字段隔离措施及最终字段清单作出说明。本说明所列字段与技术部门提交的《字段清单》逐项一致，不含推定内容。

## 二、数据集的系统来源

**2.1 系统构成**

本次登记数据集来源于本公司自主开发并运营的居家康复与服务协同系统，系统由以下端口组成：

| 端口 | 使用对象 | 主要功能 |
|---|---|---|
| 医护管理端（PC） | 合作医疗机构的医护人员、康复师 | 患者建档、方案制定与调整、评估报告查看、治疗进度管理 |
| 医生端小程序 | 合作医疗机构的医生 | 开具与调整治疗方案、查看治疗记录与自评报告、远程指导 |
| 患者端 App（智慧家康） | 居家康复患者 | 接收方案、按医嘱执行治疗、自我评估、上传记录、在线咨询 |

**2.2 数据的产生过程**

1. 患者经医疗机构评估后建档，医生在医生端开具治疗方案与疗程；
2. 患者居家使用康复设备，设备与患者端 App 联动执行处方；
3. 设备自动记录治疗参数、治疗时长、电流强度；
4. 记录同步至系统云端，按治疗方案—疗程—处方—执行四层串联，形成患者的全周期康复数据链；
5. 医生在医生端查看执行记录与评估结果，按需调整处方。

**2.3 数据集的构成**

| 构成 | 容量 | 数量 | 内容 |
|---|---|---|---|
| 结构化业务数据 | 1,753.54MB | 1,256,439 行（广东省内核减后） | 治疗执行记录、评估记录、服务协同记录、机构接入记录 |
| 非结构化业务文件 | 139.32MB | 355,401 件 | 波形图文件、评估报告文件 |

**2.4 不纳入登记范围的构成**

| 构成 | 容量 | 说明 |
|---|---|---|
| 系统运行日志 | 10,681.78MB | 系统运行痕迹，非业务内容 |
| 其他数据 | 7,678MB | 历史归档、临时表、缓存等，非业务内容 |

全库合计 20,252.64MB。本次登记范围在省内核减后约 1,859.5MB，约占全库的 9.2%。

## 三、个人信息属性认定

**3.1 认定结论**

本公司认同审核意见：数据集内的 uid 等系统内部编码，因本公司后台保有与真实身份的映射关系，该数据集在性质上属于**去标识化个人信息**，尚未达到不可识别的匿名化程度。

本公司不就此认定提出异议，并以该认定为前提实施相应保护措施。

**3.2 关于 uid 与登记数据集的关系（须如实说明的事实）**

审核意见中「uid 可与真实身份对应」的判断，指向的是本系统的完整数据，而非本次登记的数据集本身。二者需作区分：

| 项目 | 事实状态 |
|---|---|
| 登记数据集是否包含 uid 字段 | **不包含** |
| uid 的实际存放位置 | ch_user_treatment（治疗方案表）、ch_user_report（评估报告表）等，**整表不进入登记数据集** |
| 登记数据集内的标识字段 | 治疗记录 ID（id）、治疗方案 ID（treatment_id）、疗程编码（course_id）、处方编码（recipe_id），均为系统内部业务流水号 |
| 内部关联路径是否客观存在 | **存在**。treatment_id 可在系统内关联至 ch_user_treatment 的 uid，进而关联至账户信息 |
| 本公司定性 | 仍认定为**去标识化个人信息**，按个人信息标准履行保护义务 |
| 对外提供时的处理 | 全部内部编码替换为一次性映射编码，映射表单独保管、不随数据集提供 |

**3.3 与匿名化的区别**

| 项目 | 本次登记数据集的实际状态 |
|---|---|
| 直接标识符 | 全部移除，所在表整表不进入数据集 |
| 内部编码 | 保留业务流水号，用于记录串联 |
| 映射关系 | 存在于本公司身份库，与业务库物理隔离，不对外提供 |
| 反识别可行性 | 仅本公司具备内部映射条件；对外提供时替换为一次性编码且不附映射表 |
| 结论 | 去标识化，非匿名化 |

## 四、字段隔离措施

**4.1 隔离方式：整表隔离，非同表删列**

本系统采用的隔离方式不是「在同一张表内删除敏感列」，而是**整表隔离**——登记数据集由单一业务执行表构成，凡承载身份信息、消息内容、诊断意见、网络地址的表，整张不进入登记范围。

**4.2 分库分表结构**

| 库 | 内容 | 访问权限 |
|---|---|---|
| 身份库 | 患者姓名、性别、出生日期、手机号、身份证件号、住址、紧急联系人 | 仅系统服务账户与获授权的少数管理岗可访问 |
| 业务库 | 治疗执行记录、治疗参数、提交状态、机构接入记录 | 按岗位授权访问 |

两库通过 uid 关联，但**不设跨库联表查询的直通权限**。业务库内不含任何直接标识符，身份库内不含业务明细。

**4.3 登记数据集的取数来源**

登记数据集**仅取自业务库的单一业务执行表**（ch_user_treatmentrecipe），取数过程不联查身份库，不联查评估报告表、消息记录表。

因此，仅凭登记数据集本身，无法定位到任何特定自然人；须同时取得身份库内映射关系，才能完成关联。

**4.4 访问控制**

1. 登录采用密码加多因素认证；
2. 按岗位最小必要原则授权；
3. 批量导出须经数据安全负责人审批；**全量导出、批量下载、多环境调取仅可由技术团队按审批流程执行**；
4. 合作机构账号仅可查看本院患者的记录页面、单笔单据单次导出（供院内归档），无全量导出入口；
5. 全部访问与操作留日志，日志保存不少于六个月。

**4.5 存储与传输**

1. 数据存储于中华人民共和国境内服务器，不向境外传输；
2. 分级数据按对应等级加密存储；
3. 对外传输使用加密通道；
4. 建立本地与云端双重备份。

## 五、对外提供的脱敏规则

**5.1 替换规则**

| 处理对象 | 规则 |
|---|---|
| id / treatment_id / course_id / recipe_id 等内部编码 | 替换为一次性映射编码，映射表单独保管，不随数据集提供 |
| 机构标识（org_id） | 保留机构编码，不提供机构名称与地址 |
| 时间字段 | 保留日期；**不提供精确到秒的时间戳** |
| 波形图 URL（recipe_url） | 对外提供时替换为独立文件索引，不提供可直连系统的地址 |

**5.2 不提供的字段**

姓名、手机号、身份证件号、住址、紧急联系人、消息正文、语音原文、来源 IP 地址、设备指纹、诊断内容与诊断意见原文、诊断医生姓名、原始肌力波形数据，以及任何可与其他数据结合定位特定自然人的字段组合。

**5.3 提供的形态**

对外仅提供去标识化后的结构化数据集（表格形态），附字段说明与样例数据，不提供原始数据库导出文件。

## 六、登记字段清单

### 6.1 登记数据集构成：单一业务执行表

本次登记数据集由 1 张业务执行表构成：**ch_user_treatmentrecipe（用户治疗方案疗程处方表）**，表内 24 个字段全部纳入登记。

| 序号 | 字段名 | 含义 | 数据类型 | 是否含个人信息 |
|---|---|---|---|---|
| 1 | id | 治疗记录 ID | varchar | 否（内部流水号，对外替换） |
| 2 | treatment_id | 治疗方案 ID | varchar | 否（内部流水号，对外替换） |
| 3 | course_id | 疗程编码 | varchar | 否（内部流水号，对外替换） |
| 4 | course_index | 疗程阶段序号 | int | 否 |
| 5 | recipe_index | 处方索引 | int | 否 |
| 6 | recipe_id | 处方编码 | varchar | 否 |
| 7 | recipe_name | 处方名称 | varchar | 否（内容为电刺激模式名称，非患者信息） |
| 8 | recipe_time | 治疗时长（分钟） | int | 否 |
| 9 | time_begin | 治疗开始时间 | datetime | 否（对外精确到日） |
| 10 | time_end | 治疗结束时间 | datetime | 否（对外精确到日） |
| 11 | device_code | 使用设备编号 | varchar | 否 |
| 12 | dian_liu | 电流强度（mA） | 数值 | 否 |
| 13 | recipe_url | 治疗波形图 URL | varchar | 否（对外替换为文件索引） |
| 14 | status | 治疗状态 | 枚举 | 否 |
| 15 | terminate | 是否为手动结束 | 枚举 | 否 |
| 16 | create_by | 创建者 | varchar | 否（员工工号）※ |
| 17 | create_time | 创建时间 | datetime | 否 |
| 18 | update_by | 更新者 | varchar | 否（员工工号）※ |
| 19 | update_time | 更新时间 | datetime | 否 |
| 20–24 | 其余 5 个字段 | 治疗过程辅助记录字段 | 见《数据字典》 | 否 |

> ※ create_by / update_by 两个字段的取值样例为数字工号（如 1405）。若该工号可能对应患者本人，则对外提供时须将这两列剔除；本说明提交前已提请技术部门书面确认取值来源。

**该表的业务含义**：一条记录＝一次治疗执行——**何时、用哪台设备、按哪个处方、治疗多久、电流多大、是否完成**。为纯业务过程记录，不含任何身份属性字段。

### 6.2 不进入登记数据集的 9 张表（整表排除）

| 序号 | 表名 | 表说明 | 排除理由 |
|---|---|---|---|
| 1 | 治疗方案表 | 用户治疗方案 | 含 uid 与治疗名称，可关联身份 |
| 2 | 疗程表 | 用户疗程 | 含 uid |
| 3 | 治疗过程记录表 | 用户治疗过程 | 含 uid、关联评估数据 |
| 4 | 评估报告表 | 渠道用户报告 | 含 uid、诊断内容、诊断意见、诊断医生姓名 |
| 5 | 评估结果表 | 评估结果明细 | 评估结果与患者强关联 |
| 6 | 评估原始数据表 | 原始肌力波形数据 | 原始肌电数据属医疗健康敏感数据 |
| 7 | 消息对话记录表 | 医患消息记录 | 含**消息正文（文本）**、**发送者 IP**、发送者 ID、@用户 ID |
| 8 | 在线会话表 | 消息会话 | 含**会话创建者名称**、成员信息、对话标题 |
| 9 | 设备蓝牙日志表 | 设备连接日志 | 设备与患者绑定关系，可辅助识别 |

> 上述 9 张表中的敏感内容（消息正文、发送者 IP、会话创建者名称、诊断内容、诊断意见、诊断医生姓名、原始波形数据），**均因所在表整表不进入登记范围而不进入数据集**，未作逐列处理。此点如实告知审核方：这些数据仍存在于我司系统内，只是不进入本次登记数据集、不对外提供。

### 6.3 敏感字段落位与隔离结果对照表

| 敏感项 | 系统实际存放位置 | 是否进入登记数据集 |

| 对话标题、会话详情 | ch_online_conversation | **否**（整表排除） |
| 诊断内容、诊断意见 | ch_user_report | **否**（整表排除） |

## 七、数据集的形成主体说明

本次登记数据集并非依托与单一医疗机构的合作形成，而是本公司在广东省内多家医疗机构开展居家康复服务过程中，通过本公司自主建设并统一运营的系统持续采集、加工累积形成。

| 环节 | 承担方 |
|---|---|
| 系统设计与开发 | 本公司 |
| 系统部署与运维 | 本公司 |
| 服务器与存储资源 | 本公司租用并独占管理，位于中国境内 |
| 账号开通与权限配置 | 本公司 |
| 数据采集、清洗、结构化加工 | 本公司 |
| 衍生字段算法规则设计 | 本公司 |
| 数据备份与质量校验 | 本公司 |

与合作医疗机构的服务协议未就上述业务数据的所有权归属作出约定。涉及医疗机构诊疗行为本身形成的记录（病历、诊断、处方、医嘱），由医疗机构依其职责形成并归其管理，不纳入本次登记范围。

## 八、结论

1. 本次登记数据集属去标识化个人信息，本公司按此定性实施保护措施；
2. 身份信息与业务数据物理隔离，登记数据集仅取自业务库的单一业务执行表，不含直接标识符、不含 uid；
3. 敏感数据采用整表隔离而非逐列删除，凡承载身份信息、消息内容、诊断意见、网络地址的表整表不进入登记范围；
4. 对外提供时替换为一次性编码且不附映射表，仅提供结构化数据集；
5. 数据集由本公司自主建设并运营的系统采集加工形成，持有关系基于事实控制，不以任何单一机构的授权为前提。
