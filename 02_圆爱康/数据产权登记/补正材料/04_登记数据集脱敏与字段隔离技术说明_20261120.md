# 登记数据集脱敏与字段隔离技术说明

**申请主体**：广州圆爱康生物科技有限公司
**对应申请**：DJ202609230003
**数据集**：广东省居家康复治疗与服务协同数据集
**编制日期**：2026-11-20

---

## 一、说明目的

应深圳数据交易所《数据产权登记事宜沟通函》要求，就本次登记数据集的个人信息属性、脱敏处理方式与字段隔离措施作出技术说明，并附字段清单。

---

## 二、数据集的系统来源

**2.1 系统构成**

本次登记数据集来源于本公司自主开发并运营的居家康复与服务协同系统，系统由三个端口组成：

| 端口 | 使用对象 | 主要功能 |
|---|---|---|
| 医护管理端（PC） | 合作医疗机构的医护人员、康复师 | 患者建档、方案制定与调整、评估报告查看、治疗进度管理 |
| 医生端小程序 | 合作医疗机构的医生 | 开具与调整治疗方案、查看治疗记录与自评报告、远程指导 |
| 患者端 App | 居家康复患者 | 接收方案、按医嘱执行治疗、自我评估、上传记录、在线咨询 |

**2.2 数据的产生过程**

1. 患者经医疗机构评估后建档，医生在医生端开具治疗方案；
2. 患者居家使用物联网康复设备，设备与患者端 App 联动执行；
3. 设备自动记录治疗参数、治疗时长、肌电数据；
4. 记录实时同步至系统云端，形成患者的全周期康复数据链；
5. 系统按既定算法生成康复效果评估结论、疗程完成度等衍生字段；
6. 医生在医生端查看记录与评估结果，按需调整方案。

**2.3 数据集的构成**

本次登记数据集由两部分构成：

| 构成 | 容量 | 数量 | 内容 |
|---|---|---|---|
| 结构化业务数据 | 1,753.54MB | 1,270,370 行 | 治疗执行记录、评估记录、服务协同记录、机构接入记录等 |
| 非结构化业务文件 | 139.32MB | 355,401 件 | 波形图文件、评估报告文件、设备记录文件等 |

**2.4 不纳入登记范围的构成**

| 构成 | 容量 | 说明 |
|---|---|---|
| 系统运行日志 | 10,681.78MB | 系统运行痕迹，非业务内容 |
| 其他数据 | 7,678MB | 历史归档、临时表、缓存等，非业务内容 |

全库合计 20,252.64MB，本次登记范围 1,892.86MB，占比 9.3%。

## 三、个人信息属性认定

**3.1 认定结论**

本公司认同审核意见：本次登记数据集内的 uid 字段虽为系统内部编码，但本公司后台保有 uid 与真实身份的映射关系，故该数据集在性质上属于**去标识化个人信息**，尚未达到不可识别的匿名化程度。

本公司不就此认定提出异议，并以该认定为前提实施相应的保护措施。

**3.2 与匿名化的区别**

| 项目 | 本次登记数据集的实际状态 |
|---|---|
| 直接标识符 | 已全部移除，不进入数据集 |
| 内部编码 | 保留 uid，用于记录关联 |
| 映射关系 | 存在于本公司身份库，与业务库物理隔离，不对外提供 |
| 反识别可行性 | 仅本公司具备内部映射条件；对外提供时替换为一次性编码且不附映射表 |
| 结论 | 去标识化，非匿名化 |

## 四、字段隔离措施

**4.1 分库分表**

系统在存储层面划分为两类库：

| 库 | 内容 | 访问权限 |
|---|---|---|
| 身份库 | 姓名、性别、出生日期、手机号、身份证件号、住址、紧急联系人 | 仅系统服务账户与获授权的少数管理岗可访问 |
| 业务库 | 治疗执行记录、评估记录、设备记录、服务协同记录 | 按岗位授权访问 |

两库通过 uid 关联，但**不设跨库联表查询的直通权限**。业务库内不含任何直接标识符，身份库内不含业务明细。

**4.2 登记数据集的取数来源**

登记数据集**仅取自业务库**，取数过程不联查身份库。

因此，仅凭登记数据集本身，无法定位到任何特定自然人；须同时取得身份库内映射关系，才能完成关联。

**4.3 访问控制**

1. 登录采用密码加多因素认证；
2. 按岗位最小必要原则授权；
3. 批量导出（单次超过 100 条）须经数据安全负责人审批；
4. 全部访问与操作留日志，日志保存不少于六个月。

**4.4 存储与传输**

1. 数据存储于中华人民共和国境内服务器，不向境外传输；
2. L3 及以上数据加密存储；
3. 对外传输使用加密通道；
4. 建立本地与云端双重备份。

## 五、对外提供的脱敏规则

**5.1 替换规则**

| 处理对象 | 规则 |
|---|---|
| uid | 替换为一次性映射编码，映射表单独保管，不随数据集提供 |
| 机构标识 | 保留机构编码，不提供机构名称与地址 |
| 时间字段 | 保留日期，精确到日；不提供精确到秒的时间戳 |
| 区域字段 | 仅保留至市级 |

**5.2 不提供的字段**

姓名、手机号、身份证件号、住址、紧急联系人、消息正文、语音原文、来源地址、设备指纹，以及任何可与其他数据结合定位特定自然人的字段组合。

**5.3 提供的形态**

对外仅提供去标识化后的结构化数据集（表格形态），附字段说明与样例数据，不提供原始数据库导出文件。

## 七、数据集的形成主体说明

本次登记数据集并非依托与单一医疗机构的合作形成，而是本公司在广东省内多家医疗机构开展居家康复服务过程中，通过本公司自主建设并统一运营的系统持续采集、加工累积形成。

| 环节 | 承担方 |
|---|---|
| 系统设计与开发 | 本公司 |
| 系统部署与运维 | 本公司 |
| 服务器与存储资源 | 本公司租用并独占管理，位于中国境内 |
| 账号开通与权限配置 | 本公司 |
| 数据采集、清洗、结构化加工 | 本公司 |
| 衍生字段算法规则设计 | 本公司 |
| 数据备份与质量校验 | 本公司 |

与合作医疗机构的服务协议未就上述业务数据的所有权归属作出约定。涉及医疗机构诊疗行为本身形成的记录（病历、诊断、处方、医嘱），由医疗机构依其职责形成并归其管理，不纳入本次登记范围。

---

## 八、结论

1. 本次登记数据集属去标识化个人信息，本公司按此定性实施保护措施；
2. 身份信息与业务数据物理隔离，登记数据集取自业务库，不含直接标识符；
3. 对外提供时替换为一次性编码且不附映射表，仅提供结构化数据集；
4. 排除字段清单所列内容一律不进入登记数据集、不对外提供；
5. 数据集由本公司自主建设并运营的系统采集加工形成，持有关系基于事实控制，不以任何单一机构的授权为前提。
